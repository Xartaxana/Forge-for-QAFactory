## Что не так

Класс фабрики: **пары кейсов, которых критик велел слить в один тест, разрезаются нарезкой на окна по кейсам, а у окон legacy нет проверки наличия
`plan_remarks` (C12)** — один механизм закрывает оба пути (FR-9, FR-40; P16; AR-13, AR-19).

- Legacy S5 режется по КЕЙСАМ (`controller._scope_windows` → `split_windows` = `pack_windows` над группами из одного кейса,
  `controller.py:4428-4443`, `:446-449`). Партнёры слияния попадают в два окна и не могут быть слиты ни одним.
- У legacy нет среза, нет дельты и нет C12 (C12 бежит на плановом окне, `s5_precheck` `:4465-4468`).
- Пока узла нет, остаток назван только в брифах (K2-E12 у каждого legacy-брифа с таким остатком).
- Критик: находка «должна быть Lead», в `plans/piles/test-code-quality/` на 2e73966 её нет (`git grep -i "split_windows|case_groups"`
  по `plans/piles/` находит только `cost-dashboard/README.md`; положительный контроль `TQ2-1` находит карточку и пачку 2).

## Что именно менять

Направление выбрано Lead (F7, вариант (a)): **окно режется так, что группа слияния остаётся вместе — один механизм для обоих путей**.

1. `scripts/s5_plan.py`, `case_groups` (и `test_adjacency`): в рёбра смежности добавляются рёбра слияния критика кейсов
   (concern `parametrise into one test: TC-1, TC-2` на обоих кейсах пары).
2. `scripts/controller.py`, `split_windows` и `_scope_windows`: то же для legacy-нарезки — группа слияния не режется между окнами.
   Цена: группа выше капа становится одним окном `over_cap` (`pack_windows`, `:433-435`) и меняется нарезка legacy.
3. C12 для окон legacy: проверка наличия `plan_remarks` (по образцу `s5_plan.remark_rows_missing`, `s5_precheck` C12) — отказ называет
   недостающую строку (FR-1).
4. Тесты: одна строка в `scripts/tests/test_s5_plan_windows.py` и в таблице нарезки контроллера — пара слияния не режется;
   группа выше капа даёт одно окно `over_cap`; пара без токена режется как сегодня; legacy-окно без `plan_remarks` — отказ C12.
   Старые строки нарезки (K7, k9) не меняются.
5. Это новая идея, меняющая нарезку legacy «байт в байт» (так записано в спеке F7): **перед дизайнером — короткий план владельцу и критик
   на план** (PROJECT.md «Как разрабатывается новая идея владельца», шаги 4 и 6). Вариант (b) — слово владельца, принимающее остаток
   для процесса драйвера — остаётся только его, по P31.

Принципы и правила: P16, P31; FR-9, FR-40; AR-13, AR-19, AR-25.
