## Что наблюдалось

1. **S3 понизил уровень по неизмеренной посылке (L-5, L-4).** TS-9/R-13: «a datasource bound to an integration needs an external source,
   not deterministic on the stand» (`test-plan.md:33,384`). Прогон P2 28.10 на том же стенде сделал это API-тестом и прошёл зелёным
   (datasource с `link=https://git.example.invalid/…`, `wait_for_completion=False`). R-10: слово человека Q3 b просило ручной обход
   ДОПОЛНЕНИЕМ, план сделал его заменой API-части, которая у P2 была.
2. **S4 снял ветку и не дал ей дома (L-1, L-3).** Конфликт alias был способом сломать перенос в TC-008; критик кейсов верно отверг его для
   атомарности (alias проверяется до транзакции), кейс заменил его на «нет проекта» с пометкой «collision … covered only if the plan
   asks». Отказ при конфликте alias не проверен нигде (был у Q, P1, P2, M). TC-006 — одна партиция «нет роли», без «участник, но не админ».
3. **S5 тихо выбросил вариант (L-6).** Webhook из TC-002 (`test-cases/integrations/TC-002.md:29`) — `automation-manifest.json:1333`
   «webhook left out, needs an assistant», хотя фикстура `assistant` есть и её использует TC-005; в отчёте ни слова.
4. **Слабые оракулы прошли критика кода (D-7, D-8, L-9).** «Пригодность после переноса» = test-connection «как до»: для git и aws оба
   вызова 400 (лог финального прогона, `POST /v1/settings/test/: 400` до и после, затем `PASSED`) — тест зелёный и при потере кредов.
   Секреты aws и token сравниваются маска с маской. TC-004 Then 1 = `status == 200` без разбора причины; тело несёт ассистента
   исходного проекта — после починки бага покажет ту же красную строку. Повторы: маска — TQ1-12 (`20261024-otkaz-ne-razlichaet-…`);
   пользователь из `.env` с тихим `pytest.skip` вместо фикстуры `non_admin_user` (L-12) — TQ1-11.

## Класс

Между S3 и S5 у решения «этот вариант/ветка/уровень не делаем» нет обязательного носителя, который дойдёт до отчёта: план понижает
уровень по посылке без измерения (FR-41, P19 п. 1), критик кейсов снимает ветку без нового дома, автоматор выбрасывает вариант строкой
причины в манифесте, отчёт этого не читает. Критик кода не спрашивает «различает ли оракул исход», когда обе стороны сравнения равны
до действия.

## Что нужно

1. S3: понижение уровня (API → manual-agent) по причине «среда не даёт» — только с измерением (одна проба, PROJECT п. 6а) или пометкой
   «не измерено», которую видит критик плана; прецедент другого прогона того же проекта — довод против.
2. S4: ветка, снятая с кейса, — строка «переезжает в TC-n / исключена: причина» в форме критика кейсов.
3. S5: вариант кейса, не автоматизированный, — пробел отчёта по имени (Left with you / not proven), не только строка манифеста.
4. Критик кода (rubric dim 2): оракул «как до» обязан показать, что «до» отличимо от отказа (не 4xx/маска); сравнение маскированных
   значений — не доказательство. Корпус TQ1-4 пополнить образцами 12586 (D-7, D-8, L-9).
