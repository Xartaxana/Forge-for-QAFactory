# Стенд-идентичность N1a (t-336) — долги и аналоги

id: B-276 | кучка: `driver-hosts` | от: новое, 03.10 — (а) N1b, остальное после релиза | приоритет: — | кандидат наверх: нет

Что не так / что сделать: **Стенд-идентичность N1a (t-336) — долги и аналоги:** (а) `--command` в `stand_identity.py` парсится `shlex.split(posix=True)` — на Windows съедает обратные слэши; на `os.name == "nt"` — `posix=False` + тест `C:\x\y.exe --flag` (N1b, дорога ответа человека); (б) `guard_pre_tool.py`: сигналы «это роль фабрики» разные (`_is_factory_role` в `config_write_check`, «любой `agent_type` или транскрипт subagents» в остальных) + противоречие докстрингов ~:574 / ~:849 про то, когда приходит `agent_type` — ОДИН предикат (FR-17); (в) `config_write_check` и `stand_record_write_check` не разворачивают тела `bash -c` / `pwsh -Command` (K34 фиксирует остаток); (г) `fresh_evidence` пропускает `RequestError` при отсутствии прецедента (ловит `s6_freshness`); (д) `config-keys.json` :433 устарел («first --mine run only»); (е) чужая проба пишет свои свидетельства под репетицией (FR-45, AE16); (ж) остаток замера: роль драйвера без привязки `story_step` и без `agent_type` от хоста проходит гард как главная сессия — одно событие хука изнутри ведомой роли на свежем прогоне (RUNBOOK §9, утренний чек-лист); (з) критик t-343 F5: гарды слова человека ловят CLI по ИМЕНИ скрипта (`stand_identity.py`, `waiver.py`) — вызов библиотекой (`python -c "import stand_identity…"`, `-m`) проходит оба гарда; класс для всех CLI слова человека, пока «на дисциплине» с честной строкой в докстринге; (и) F7: AE2 держится только при записи — строка `probe discovered` отвечает раньше источников, стенд, ставший hot-reload позже, отвечает устаревшей меткой (N3); (к) F9: текст гейта A из `comparisons` при ответе меткой говорит «0 file(s) compared by content» (FR-10, N3); (л) t-345: двери других гардов (`HUMAN_WORD_MSG` :1260 «return the open point in your digest», `config_write_check`) не проверены на приём `role_digest.parse` так же, как F1 — тест-парсер на каждую дверь гарда; `audit_factory.py:950` читает argv[1] только; `guard_pre_tool.py:1360` своя карта имён скриптов (FR-13); (м) критик t-361 F4: шаг «запустить пробу и разобрать запись» живёт дважды — `execution_request.rehearsal_probe` (бросает на `unknown`/`mismatched`) и `story_run.build_run_probe` (читает сырые поля), близнецы уже расходятся по `cwd`; docstring `rehearsal_probe` называет build check вызывающим — ложно: одна `execution_request.rehearsal_record(spec) -> (record|None, why)` для обоих (малый батч); (н) ответ `stop` на вопрос о стенде держится в журнале с «owner: environment», в отчёт владелец попадает через N2/N3 (Q8); (о) ось 5: `phases/s5.md:8-16` и `s6.md:6-9` описывают stand check, но не build check (вопрос о стенде N1b) — строка близнеца при t-301 N6 / B-261; **(п) после N2 (критик t-393):** `refusal_text` не знает списка слов вызывающего — валидная запись, отказанная только по списку, получает «the probe gave no reason» / валидный NA1 — «requires … no_changed_file» (FR-1; сегодня недостижимо, все вызывающие передают ACCEPTS) → N3/T2; (р) поля `cause` и `do_not_retry` в `env_blocked.json` не зарегистрированы в `handoffs/vocabulary.yaml`; прозаические близнецы для причины `build` — `agents/qa-runner.md:136`, `references/role-commands.json:38`, `design/state-exits.md:41`; (с) проба гейта A принимает `{report_path}` в двух токенах, S5 отказывает (FR-17, `gate_preflight.py:1975`) → N3; (т) слово другой стори на запуске классифицируется как `invalid_request` (FR-46) → с X5-B; (у) S2b при доказанном несовпадении говорит «post-run runtime probe unavailable», `runtime_identity_unread` не доходит до блока прогона и отчёта (F9 критика t-378). [F03]
