# Доверие командам по форме: команда прогона из файла проекта с необычной формой ждёт «да» человека один раз на машину

id: — | кучка: `driver-hosts` | от: обзор testing-factory (docs/RELATED_WORK.md §2), владелец 21.10.2026 | приоритет: П3 | кандидат наверх: нет

Что не так / что сделать: команда прогона тестов, прочитанная из файла проекта, у нас либо проходит как есть, либо упирается
в разрешение инструмента. У Testing Factory доверие решается ПО ФОРМЕ команды: «необычная» команда (не начинается с известного
раннера, цепочки и пайпы, `curl`/`rm`/`ssh` и подобное, путь вне проекта) требует «да» человека один раз на машину; одобрение —
sha256 нормализованной команды в git-ignored файле состояния (`approved-commands.json`). Известные раннеры идут без вопроса.
Что сделать у нас: то же для команд прогона из конфигурации проекта — известная форма проходит, необычная форма один раз
получает вопрос человеку (P13: слово человека проводит через гейт и записывается; FR-50: «спросить» относится к доступу,
который человек МОЖЕТ дать; FR-57: запрет не обходится, но у него есть дверь), одобрение хранится по хэшу нормализованной
команды вне репозитория проекта. Побочный эффект, ради которого это в онбординг/хуки: закрывает и волну permission-запросов на
известных раннерах (RELATED_WORK §2, K3). Для спеки дизайнера (решает Lead): список «известных раннеров» — данные
(`launch-causes.json`, FR-13, AR-1), не регулярка в коде; сомнение в форме = вопрос, не проход (FR-59); у них та же регулярка
скопирована в два места и тест ловит расхождение — у нас клон запрещён (`dup_ratchet`), читатель один (AR-13).

Свидетель: репозиторий `git.example.com/tst/testing-factory` (v0.1.33, `main` cda7f7e): `lib/command-trust.mjs` строки 1–50,
ADR 0073 (содержание — `docs/RELATED_WORK.md` §2 п. 1). Клон в скрэтчпаде сессии Lead, пересобрать по SSH — см. §2.
