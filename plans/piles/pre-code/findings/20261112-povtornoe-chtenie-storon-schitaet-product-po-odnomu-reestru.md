## Что не так

Класс фабрики: «близнецы одной стадии читают один и тот же факт одним путём» (AR-13, AR-19; FR-54) и «запись по умолчанию живёт в одном
месте» (AR-15). Два экземпляра в `Driver` из `ai-packages/qa-factory/scripts/story_run.py`; оба названы критиком кода узла PC2-7
(`docs/tasks/specs/reviews/t-057-critic-on-code.md`: N1 — строки 140 и 156, N6 — строки 119 и 170).

**(а) Близнецы считают неявную сторону по разным входам.** `Driver.s0_sides_sets` (`story_run.py:8539-8564`) берёт слитые записи
`self._sides_entries(environment)` (реестр + слова запуска `--side` / `--reference` + ответы человека; `:8457-8490`) и проверяет
`contract.product_implied(entries)` над НИМИ (`:8563`). `Driver.sides_reread` (`story_run.py:18199-18238`) проверяет
`contract.product_implied(read["sides"])` над одним реестром (`:18225`) и строит записи сам из строк реестра (`:18219-18227`), без слов
запуска и ответов. Пример критика (N1): запуск `--side ui=real` при нечитаемом реестре на S0, повторный запуск после починки реестра:
S0 записал бы `{backend, ui}`, повторное чтение записывает `{backend, product}`. Одна и та же стори получает разный набор сторон от
того, на каком пути она оказалась.

**(б) Запись стороны по умолчанию написана дважды.** `story_run.py:8564`
`{"reality": self.SIDE_REAL, "deliverable": True, "source": "default"}` и `story_run.py:18226-18227`
`{"reality": self.SIDE_REAL, "deliverable": True, "settles_by": "", "reference": None, "source": "default"}`: две записи одного смысла,
различаются набором ключей (второе несёт `settles_by` и `reference` под форму строки реестра). Читатель по-прежнему один —
`contract.product_implied`; записи по умолчанию рядом с ним нет.

## Что именно менять

Направление выбрано (Lead, 12.11.2026).

1. **(а) `story_run.py`, `Driver.sides_reread`.** Записи строятся через `self._sides_entries(pipeline.get("environment"))` — тот же
   слитый разбор, что у S0; неявный `product` определяется `contract.product_implied` над этими слитыми записями, как в
   `s0_sides_sets`. Дальше цикл `sets += self.side_set_args(...)` пишет их тем же `stage_done` вызовом вместе со снятием метки
   `sides_unknown`. Ожидание: для каждого набора входов (реестр читается, слова запуска, ответы человека) повторное чтение записывает
   ровно то, что записал бы S0 при читаемом реестре. Края: реестр всё ещё нечитаем или с битой строкой — как сейчас (`read["problem"]`:
   одна строка отказа, метка остаётся; решение о метке не меняется); `entries` пусты (S13: всё real, без эталона) — ничего не пишется,
   метка снимается; у записи из слов запуска нет `settles_by` — ключ не пишется. ИНВАРИАНТ: нечитаемый реестр никогда не читается как
   real, и метка не снимается без чистого чтения.
2. **(б) одно место для записи по умолчанию.** Рядом с `contract.product_implied` (`ai-packages/qa-factory/scripts/contract.py`) —
   маленький помощник, возвращающий запись стороны `product` по умолчанию (`reality` real, `deliverable` True, `source` default);
   оба места (`s0_sides_sets`, `sides_reread`) берут её оттуда, второй набор ключей не пишется. Ожидание: набор ключей записи един для
   обоих путей, а значения, которые видят `side_set_args` и `stage_done`, не меняются.
3. **Тест.** Строки-варианты в существующей таблице `scripts/tests/test_story_sides.py`, функция `driver_cases` (блок F1 (а)): запуск
   `--side ui=real` + нечитаемый реестр на S0 + повтор после починки — набор сторон повторного чтения равен набору S0 при читаемом
   реестре (контроль: тот же запуск с читаемым реестром сразу); ответ человека `ours`/`another team's` в запуске до починки доходит до
   записи; реестр без нереальной стороны — `product` не пишется; пустой набор — метка снимается без записи сторон. Свидетель узла:
   `python -B ai-packages/qa-factory/scripts/tests/scenario_walk.py --witness-for <пути узла>`.

Исполнитель: designer → builder → critic (узел правит `story_run.py` — горячий файл; список функций в `owns` диспатча:
`Driver.sides_reread`, `Driver.s0_sides_sets`, правило D-0048).
