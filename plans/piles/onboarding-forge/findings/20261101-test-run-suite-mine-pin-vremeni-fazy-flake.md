# `test_run_suite_mine`: пины времени фаз (`build_s >= 0.35` у медленного импорта, `collect_s`/`stand_probe_s >= 0.3` у `sleep(0.35)`) — флейк под нагрузкой и на грубых часах (FR-31)

## Что наблюдалось

`scripts/tests/test_run_suite_mine.py` около :1915-1940: тест AK1/AK3/F6 измеряет настоящее время: `time.sleep(slow)` в подставных `probe_runtime` и `collect_files`, затем проверяет `collect_s >= 0.3`,
`stand_probe_s >= 0.3`, `build_s < 0.3`, а для F6 — поиск-метапуть спит 0.4 с при загрузке `execution_request` и ждёт `build_s >= 0.35`, `total_s >= 0.35` (`r0107-s2b-fix.md`, F6). Такие нижние пределы по wall-clock
краснеют на загруженной или грубо тикающей машине (FR-31, как `test_stand_lease` PC1-7): тест падает от нагрузки, а не от дефекта.

## Что именно менять

1. Подменить часы фаз (`phase_clock`/`time.monotonic` в `run_suite`) ступенчатым счётчиком: «медленная» фаза продвигает его на 0.35, пины сравнивают с этим числом точно (без sleep).
2. Сохранить ключи: фазы — числа с одним знаком, суммируются, `build_s` исключает collect и probe, часы стартуют до импорта `execution_request` (F6) — те же утверждения, но детерминированно.
3. Узкий свидетель: этот файл тестов; прогон 20 раз подряд без падения — в отчёте. Мутация: `+=` → `=` в `_phase` — красит ключ суммирования (как было).
