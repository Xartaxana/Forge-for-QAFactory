# `project_decisions resolve` переписывает `config.json`, даже когда значение не изменилось (CRLF → LF, переформатирование)

id: — | кучка: `onboarding-forge` | от: наблюдение Lead 12.11.2026 (снимок `docs/tasks/compact-snapshots/2026-11-12-2032-narrative.md`, строка «`resolve` переписывает config.json при неизменном значении») | приоритет: П3 | кандидат наверх: нет

## Что наблюдалось

`scripts/project_decisions.py`, `resolve` (:438-505): после `_set_pointer` для каждого указателя строка :488-489 пишет `_atomic(config_path, json.dumps(config, indent=2, ensure_ascii=False) + "\n")` безусловно, как только есть указатели и файл существует.
Если значение по указателю уже равно присваиваемому, файл всё равно перезаписывается: CRLF становится LF, порядок и отступы приводятся к `indent=2` — в диффе проекта шум, в журнале «запись» без изменения смысла. Переменная `before` (:454) уже хранит копию до записи — сравнение есть из чего сделать.
Проверено чтением main: условия сравнения `config == before` нет.

## Что именно менять

1. `scripts/project_decisions.py` `resolve`: писать `config_path` только когда `config != before` (JSON-равенство после `_set_pointer`); иначе файл не трогается. Квитанция (`receipt`), маркеры и закрытие строки идут как сейчас.
2. Восстановление после сбоя (`recovering`, :478): `before` берётся из первой попытки, а текущий файл мог уже содержать запись — сравнивать с тем, что читается сейчас, а не с `receipt["before"]`.
3. Тест: `scripts/tests/test_project_decisions.py` (или тот, что судит `resolve`; назвать в спеке) — строка «значение то же, файл CRLF → байты `config.json` до и после равны, решение закрыто»; строка «значение другое → файл записан»; строка «повтор после сбоя».

Принципы и правила: FR-54; AR-14 (один писатель — не меняется).

Решение владельца нужно: нет.
