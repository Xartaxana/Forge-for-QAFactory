# Скан загрузчика env-файла в `_loaded_env_files` умеет только Python (conftest, pytest-dotenv): остаток оси 34, когда конфиг не называет файла (t-231 F-e (a), t-239)

## Что наблюдалось

Когда конфиг проекта не называет env-файл, только гейт (`gate_preflight._loaded_env_files`, `gate_preflight.py:5090-5112` по спеке t-231; дерево сверить заново) смотрит, что грузит раннер: литералы путей `load_dotenv(` / `dotenv_values(` в conftest, голый подъём по дереву, `env_files =` pytest-dotenv; для остальных языков — только `<tests_root>/.env`. Это одна Python-only дорога там, где остальные читатели (зонд стенда, рекордер, `stand_health`) читают только то, что назвал конфиг (P31, ось 34). Проект на Node или другом раннере, чей загрузчик читает файл с другим именем, получит в диагнозе гейта умолчание `.env`. Пока остаётся остатком оси: в t-239 выбрано (a) — шаг остаётся собственным шагом гейта, потому что вариант (b) (один выбор для всех читателей) отнимает у человека сегодняшнее значение «пустой `env_file` = только переменные процесса (секреты CI, менеджер секретов)» — `references/templates/config.json:47`, `config-keys.json` `environment.note`.
