# Десять мест `isinstance(then, int)`: читатели номера Then или проверки формы? Один скаут разбирает (t-205 F5, HF8-4)

id: — | кучка: `onboarding-forge` | от: спека t-205 §5 F5 (критик согласен; решено «по рекомендации, до слова владельца»), пункт 3 находки HF2-0, 13.11.2026 | приоритет: П3 | кандидат наверх: нет

## Что наблюдалось

Номер Then читается одним читателем `contract.then_number` (строка `"2"` от руки, `True`, `[2]` он обращает в 0 = «нечитаем»). В HF8-4 (P6) исправлено ОДНО место — `ledger.plan_row_state` (`ledger.py:866-868`: рукой присланная `"2"` в открытом Then пропускалась, и зелёный не помечался). Остальные места с `isinstance(…then…, int)` не разобраны: каждое либо ПРОВЕРКА ФОРМЫ (правильно отказывает строке, а не читает), либо ЧИТАТЕЛЬ (должен идти через `then_number`, иначе «`"2"` пропущена» снова в другом месте). По t-205 §5 F5 их десять: `contract.py:338, 393, 1140, 1632, 1650, 1761`, `planning_contract.py:2080`, `question_register.py:1267`, `s5_precheck.py:1735`, `manifest_put.py:1285` (номера строк по дереву на 12.11.2026 — перечень заново; не обязан совпасть).

## Что именно менять

Направление выбрано (спека t-205 §5 F5): сначала ОДИН скаут-диспатч классифицирует места; результат открывает узел (или закрывает находку «все — проверки формы»).
1. Скаут: свежий перечень двумя формами (в дереве на 13.11.2026 первая даёт 11 мест — десять из t-205 и `contract.py:2353`; вторая — `gate_preflight.py:2031`, `ledger.py:120, 867` (867 чинит P6), `question_register.py:1368`, которые первая не видит, потому что `get("then")` закрывает скобку): `grep -nE "isinstance\([^)]*then[^)]*, *int" ai-packages/qa-factory/scripts/*.py` и `grep -nE "\"then\"\)[^)]*, *int\)" ai-packages/qa-factory/scripts/*.py` (без `tests/`; положительный контроль каждой формы — перечисленные строки находятся); таблица «файл:строка — функция — что делает с не-int (отказывает строку / пропускает / приводит) — вердикт ВАЛИДАТОР или ЧИТАТЕЛЬ — причина». Ответ скаута несёт путь поиска (след) и перечень прочтённых функций.
2. Узел после скаута (builder → critic): каждое место с вердиктом ЧИТАТЕЛЬ переводится на `contract.then_number` (одна дорога, AR-13), направление ошибки места — как у P6 (читатель «не читается» = 0 → не засчитывает покрытие/не засчитывает зелёный). Места с вердиктом ВАЛИДАТОР остаются; их список — shrink-only тест-сторож «проверки формы, каждая с причиной» в `scripts/tests/test_contract.py` (keep-файл).
3. Тест на каждое место-читатель: таблица `then` ∈ `1`, `"1"`, `True`, `[1]`, `0`, `-1`, `None`, отсутствует; ожидание — как у `then_number` (читаемо только целое ≥ 1). Мутация: вернуть `isinstance(…, int)` в месте — красит строку `"1"` или `True`.
Нет мест-читателей — находка закрывается строкой «все десять — валидаторы», без кода.
