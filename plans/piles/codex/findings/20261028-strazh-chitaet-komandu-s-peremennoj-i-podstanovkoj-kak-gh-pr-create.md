# Страж читает команду с переменной и подстановкой как `gh pr create`

id: — | кучка: `codex` | от: Lead, замер 28.10.2026 (прогон TP1-12586, стенд testproject1-dev-010, S2) | приоритет: П1 | кандидат наверх: нет

Что не так: страж (`stage_guard._delivery_match`, `adapter_forms._wildcard`, `stage_guard._delivery_in_text`; зона CX1-20) принимает за команду доставки обычную команду записи ответов. Прогон TP1-12586, S2, 28.10.2026 около 00:20: дирижёр записал ответы человека одной bash-командой с функцией оболочки `run(){ python "$P/scripts/question_register.py" ... --answer $1 ${2:+--reading $2} --words-file $W/s2-...-$(echo $1|tr Q q).txt ... --register-hash $3; }`; страж отказал: «STAGE GUARD: TP1-12586: this delivery command (`{ python $P/scripts/question_register.py --task ...`, from references/adapter-forms.json (github)) is blocked — delivery_ready is not yes ... have the human say 'deliver with known gaps' at gate B».

Замер Lead на установленном релизе (`D:/ws2/QAFactory`, `stage_guard._delivery_match(cmd, {})`):

| команда | результат |
|---|---|
| `$a $(f)` | совпало с github |
| `python x.py --n $a --f b-$(f).txt` | совпало |
| `echo $a $(f)` | совпало (даже команда-упоминание) |
| `$a $(f) $(g)` | совпало с gitlab |
| `python x.py --n $a --f b.txt` | None |
| `python x.py --f b-$(f).txt --n $a` | None |
| `gh=gh; $gh pr create` | совпало (задуманный случай, должен остаться отказом) |

Причина (гипотеза для дизайнера): слово `$var` считается «дикой программой» (`_wildcard`), а слово с `$(...)` может стоять за следующие слова формы, поэтому любое `$var` перед словом с подстановкой укладывается в форму доставки.

Два дефекта: (а) ложное срабатывание сопоставителя на любой стадии, команды-упоминания включены; (б) отказ на S2 называет дверь гейта B (`deliver with known gaps`, `check_delivery`), которой здесь нельзя воспользоваться и которая тут ни при чём (FR-1, FR-2, P15), а показанная форма `{ python $P/...` не объясняет роли, почему отказ. Обход дирижёра: раздельные простые команды.

Что сделать: сопоставитель не принимает `$var` + слово с подстановкой за форму доставки без признаков самой формы (слова `pr create` / `mr create` и т. п. после раскрытия или после дикой программы); `gh=gh; $gh pr create` остаётся отказом (CX1-20 «ошибается в сторону отказа»). Ключи: семь строк таблицы выше, каждая с ожидаемым исходом. Текст отказа на стадии, где гейт B недостижим, не называет его дверь; называет, какое слово команды сочли доставкой и как записать команду без него.

Край, который спека обязана назвать: направление допустимой ошибки — лишний отказ на реальной доставке допустим меньше, чем пропуск `$gh pr create`; поэтому правка сужает совпадение, а не отключает `_wildcard`.
