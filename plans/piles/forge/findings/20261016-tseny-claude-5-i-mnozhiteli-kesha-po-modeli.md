Три следствия для `usage_report.load_prices` (FR-25/FR-41 — одну неверную цифру как точную не показывают, P18):

1. **Множитель чтения кэша — по модели**, не один на файл: у файла `cache_read_multiplier: 0.1`, а у Fable 5.1 он 0.025, у
   Opus/Sonnet 5.5 — 0.05 (остальные 0.1). С одним общим множителем чтения кэша Fable 5.1 считались бы в 4 раза, а 5.5 — в 2
   раза дороже истинного; у сессии Lead чтение кэша — основная масса входных токенов. Строка модели получает необязательные
   `cache_read_multiplier`/`cache_write_multiplier`, перекрывающие общие; читатель — один `load_prices` (кортеж модели растёт
   на два множителя или становится записью), потребители `cost`/`unpriced_turns`/`savings_report` берут множитель модели.
2. **Запись кэша: 5 минут (1.25×) или 1 час (2×).** Сессии Claude Code этой фабрики ходят с часовым TTL кэша (строка харнесса
   «1-hour Anthropic prompt-cache TTL»); сначала измерить по транскриптам, несут ли записи `usage` разбивку
   `cache_creation.ephemeral_5m_input_tokens`/`ephemeral_1h_input_tokens` (пункт 6 гигиены — одна проба до машинерии): есть
   разбивка — цена по ней; нет — множитель записи остаётся 1.25 с пометкой «оценка: записи кэша считаны как 5-минутные» в
   отчёте и строкой долга здесь.
3. **Haiku 5.5 — два тарифа по длине промпта.** Фабрика Haiku не использует (P7, FR-52); строка получает тариф ≤ 100K и
   `note` о пороге; второй тариф в код не переносится, пока в базе использования нет ни одного хода Haiku 5.5 (измерить
   `unpriced_turns`/`usage.db` в задаче; появится — отдельная находка).

Пин `test_usage_report.CLAUDE_5_X_ROWS` («четыре строки пустые, владелец заполняет») переворачивается: четыре строки заполнены
значениями со страницы цен, и по каждой — контрольное значение стоимости одного хода, посчитанное руками из таблицы выше
(критик по правилу 3 начинает с эмпирики: деньги).
