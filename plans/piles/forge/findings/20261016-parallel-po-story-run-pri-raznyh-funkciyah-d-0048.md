## Что

Очередь по `story_run.py` (11 834 строки, 456 функций; швы вынесены, узла на разбиение нет) сериализовала семь узлов
conductor/2–3, чьи hunk'и не пересекаются. D-0048 снимает ФАЙЛОВЫЙ замок: два узла «в работе» пишут один горячий файл без
строки `очередь:`, если строка `owns:` каждого диспатча называет для этого файла свои функции/регионы и множества не
пересекаются; поздний узел сливает `main` в своё дерево, конфликт решает его билдер (пины ОБЕИХ сторон зелёные — свидетель),
критик у позднего узла один — после слияния; зависимости по замыслу (спека поверх чужого кода) остаются
последовательными.

Что меняется в коде и текстах:

1. **PROJECT.md «Командная работа» п. 3**: фраза «только с строкой `очередь: A → B` в обеих» получает «или с непересекающимися
   списками функций в `owns` обоих диспатчей (D-0048)»; п. 9 без изменений.
2. **`piles.py check` (б)** — сегодня две пачки «в работе» с общим горячим файлом без строки `очередь:` = красный. Новая
   форма: строка пачки (ячейка «Файлы» узла или строка «Хода») несёт `story_run.py (f1, f2, …)`; (б) зелёный, когда у ОБЕИХ
   пачек список есть и множества не пересекаются; пересечение — красный, называющий общие имена; список только у одной —
   красный как сегодня (замок файловый). Имена проверяются на существование (`def <имя>` в файле на `main`, и как метод
   `Driver.<имя>`) — опечатка = красный с именем (FR-59, не молчаливый пропуск). Пины: обе формы, пересечение, опечатка,
   старая форма с `очередь:` без изменений.
3. **`dispatch_gate.py`** owns-overlap WARN уже печатает пути; строка `owns:` с `(f1, f2)` после пути не должна ломать проверку
