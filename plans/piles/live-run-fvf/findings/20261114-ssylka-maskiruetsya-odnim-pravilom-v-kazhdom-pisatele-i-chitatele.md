## Что не так

Класс фабрики: **правило «что в ссылке — секрет» одно (`config_contract.mask_secret_ref`: пары `SECRET_QUERY_RE` и пароль в userinfo), но три места его не применяют или применяют своё (AR-15, AR-13, P31, FR-41)**.
Исправление A-5 привело всех трёх писателей строк ссылок (`_write_s0_files`, `write_paste_references`, `_merge_reference_rows`) к одному помощнику; остались три соседа:

1. `ai-packages/qa-factory/scripts/source_inventory.py::_settle_references` перезаписывает у уже сохранённых строк только статус и НЕ маскирует: старая сырая строка (записанная до A-5) остаётся сырой в `ticket-references.json`, пока не пройдёт слив `_merge_reference_rows`.
2. `ai-packages/qa-factory/scripts/ticket_adapter.py` (`_record_source`, около `:2208`) проверяет учётные данные СВОИМ правилом (`SECRET_QUERY_RE.search(ref) or urlsplit(ref).password`) рядом с помощником: второе правило.
3. Процентно-кодированная пара `token%3Dabc` не маскируется ни помощником, ни `SECRET_QUERY_RE` (исправление называет её известным пределом).

## Что именно менять

Выбранное направление: правило одно, живёт в `config_contract.py`, и каждый писатель/читатель зовёт его; все три пункта — одним узлом, одним коммитом (AR-15).

1. `_settle_references`: перед записью маскирует хранимые строки через `source_inventory.mask_reference_rows` (тем же, что слив) и ищет обновление статуса по замаскированной ссылке (`mask_secret_ref(item["canonical_ref"])`), чтобы сдвиг статуса не терялся; строки, ставшие
   равными после маскировки, соединяются как в `_merge_reference_rows` (источники сливаются, статус первой строки). Файл переписывается, если изменился статус ИЛИ маска. Граница: файла нет — ничего (как сегодня); ссылки без секрета — файл не трогается.
   Тест: строка в `ai-packages/qa-factory/scripts/tests/test_local_keys.py` (keep, `table`): старая сырая строка `https://w.example/p?token=abc123` + settle → в файле нет `abc123`, статус сдвинут.
2. `_record_source`: проверка учётных данных зовёт ОДИН предикат `config_contract.ref_has_secret(ref)` — `mask_secret_ref(ref) != ref` (ссылка, которую помощник изменил, содержит секрет); собственная проверка `urlsplit(ref).password` уходит. Край: `user:@host` (пустой пароль)
   помощник маскирует, предикат отказывает — ошибка в сторону отказа (допустимая); текст отказа не меняется ни на байт. Тест: существующие строки отказа по учётным данным у `record-source` проходят без правки (билдер называет их файл в отчёте); добавлена строка `https://u:@h/x` → отказ в том же файле.
3. Процентное кодирование: в `config_contract.py` `SECRET_QUERY_RE` принимает `%3D`/`%3d` вместо `=` (НЕзахватывающая группа, номера групп прежние, чтобы `route_has_secret` и проверка локатора на `:1004` читали то же); маска пишет `name=<hidden>`. Идемпотентность и
   «не URL — без изменений» сохраняются. Тест: строка `token%3Dabc123` и `Token%3dabc123` маскируются; `monkey%3D1` маскируется (допустимая ошибка в сторону сокрытия); `a%3Db` без имени секрета — без изменений.
4. Свидетель: `scenario_walk.py --witness-for scripts/source_inventory.py scripts/ticket_adapter.py scripts/config_contract.py` (узкий запуск каждого быстрого файла).
