# `role_load.settings` не проверяет типы `allowances.brief` и `brief_charter_head`: сырой `ValueError`

id: — | кучка: `live-run-fvf` | от: критик кода темы FV1-4 (Q7, замечание), `docs/tasks/specs/reviews/20261113-fv14-topic-code-critic.md`; узел-источник FV1-4 | приоритет: П3 | кандидат наверх: нет

## Что не так

Класс фабрики (FR-1, AR-9): **отказ без имени, что не так и чего ожидали — сырое исключение вместо отказа по форме**. Испорченное
значение `allowances.brief` или `allowances.brief_charter_head` в `references/role-load.json` приводит к голому `ValueError` в
`_brief_allowance` (`role_load.py`). Файл принадлежит пакету, поэтому приоритет низкий (критик: nit).

## Что менять

1. `scripts/role_load.py`, `settings` (читатель `allowances`): проверка типа обоих ключей (целое неотрицательное); отказ называет ключ,
   файл, полученное значение и ожидаемое (FR-1) вместо `ValueError` из `_brief_allowance`. Тест: параметризованные строки —
   строка, `None`, отрицательное, дробное, список для каждого из двух ключей → отказ с именем ключа; целое — как сегодня.
2. Соседние ключи `allowances` с той же неопределённостью — нужна доразведка: вердикт называет только два ключа; остальные
   читает перебором исполнитель узла и пишет вердикт на каждый (применено / не относится).

Принципы и правила: FR-1, FR-14; AR-9, AR-18.

Решение владельца нужно: нет.
