# Прочитаться «селекторы проверены» могут только формы `pytest` и `playwright-test`: jest, vitest, dotnet-test навсегда `no_selection_form`

id: — | кучка: `live-run-fvf` | от: критик кода темы FV1-18 (очередь QUEUE, ключ «по языкам»), `docs/tasks/specs/reviews/20261113-fv118-topic-code-critic.md`; кучка выбрана по узлу-источнику FV1-18 (пачки `execution-probes` закрыты: ни одна пачка не несёт узлов про строки выбора в формах запуска) | приоритет: П2 | кандидат наверх: нет

## Что не так

Класс фабрики (P2, AR-1): **закрытое разнообразие, у которого в данных нет строк для большинства членов**. После FV1-18 контракт
селекторов отвечает «проверено» только для двух раннеров: `pytest` (по id узла, ключ `selection_by_node_id`) и `playwright-test`
(строка выбора). Все остальные формы таблицы запуска — jest, vitest, dotnet-test и прочие — навсегда `no_selection_form`: на
каждом прогоне проекта на них печатается заметка SELECTORS «выбор раннера не проверен» (критик: безвредна, только когда её
дверь честная — FIX-3 той же темы).

## Что менять

Данные, не код (AR-1):

1. `references/launch-causes.json` (строки запуска) и таблица форм запуска: строки выбора для jest, vitest, dotnet-test (и прочих форм таблицы)
   — как у `playwright-test`. Сами формы выбора по раннерам (флаги `-t`, `--filter` и т. п.) — нужна доразведка: вердикт названия
   флагов не даёт, их выбирает дизайнер по документации раннеров (P5: все способы получить данные).
2. Тест: параметризованная строка на каждую форму — `selector_contract` на команде с проверенной записью отвечает `verified`, а не `no_selection_form`;
   форма без строки выбора по-прежнему `no_selection_form` с названием формы.

Принципы и правила: P2, P13; FR-13, FR-42; AR-1, AR-3.

Решение владельца нужно: нет.
