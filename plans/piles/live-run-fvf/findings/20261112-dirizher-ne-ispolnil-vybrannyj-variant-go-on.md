# Дирижёр не исполнил выбранный человеком вариант `go on` — прочёл прежние слова и спросил то же в третий раз

id: — | кучка: `live-run-fvf` | от: живой прогон LR2-1 (плечо `factory`, релиз 0.11.0), 12.11.2026 | приоритет: П1 | кандидат наверх: да

## Что не так

На вопрос дирижёра S5 с вариантами `(a) go on` / `(b) retry` / `(c) stop` владелец ответила одним словом из предложенных:
файл ответа `answers/s5-empty-scope-go-on.md` = `go on`. Драйвер не принял вариант кодом, а отдал его дирижёру («answer for
conductor (S5): go on»). Дирижёр: «Recorded no waiver, because the person's words ask for automation and not for an empty S5» —
то есть судил по прошлому ответу (замечание с просьбой автоматизировать), а не по свежему, записал `go on` замечанием
(`waiver.py --remark`), хода не сделал и задал тот же вопрос с теми же тремя вариантами в третий раз. Плечо встало на S5 третий
раз — по потолку RUN-INSTRUCTIONS §5 остановлено без отчёта.

Класс: выбор человека из закрытых вариантов, которые предложила сама фабрика, не исполняется (P13, P22: «исполняет выбранное
имеющимися командами»; FR-9: у решения человека есть исполнитель; FR-7: отвеченный вопрос не задаётся тем же текстом). Два
дефекта: (1) вариант, названный в вопросе в бэктиках, код не читает как жетон — значит, предложенная дверь не та, что
принимает код (FR-2, FR-37); (2) дирижёр берёт за слово человека прежний ответ, а не последний.

Свидетель: `runs/factory-12.log` (строки «conductor: ask_person …»); `notebook.md`, «Ход прогона», 19:05–19:07.

## Что сделать (предложение оператора)

Варианты дирижёра, предложенные человеку, — закрытые жетоны формы `human-questions.md`, их читает код и исполняет без второго
круга; дирижёр получает только свободный текст, и всегда последний ответ, с прежними — как историю. Тест: вопрос дирижёра с
`go on` + ответ `go on` → стадия проходит записанным отказом, без нового вопроса; ответ, противоречащий прошлому замечанию, —
исполняется последний.

Принципы и правила: P13, P22; FR-2, FR-7, FR-9, FR-37, FR-48; AR-17, AR-24, AR-25.

Решение владельца нужно: нет.
