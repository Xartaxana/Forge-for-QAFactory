## Что не так

Класс фабрики: **один вопрос «задуман ли R-n так» идёт двумя дорогами к человеку (P31, FR-7, P22)**. Строка реестра находок `requirement_silent` доходит до человека на гейте B
через `report_facts.exploratory_gate_parts` и присоединяется к строке реестра вопросов, только если её `refs` несут id Q (`report_facts.py`, около `:3967`). Но
`place_answers._line_for` кладёт в `refs` id требований и кейс, а id вопроса-претензии этого R (`contract.claim_questions(text)[R]`) — никогда. Итог: новая строка
`requirement_silent` спрашивает человека о R-8 или R-11 ВТОРОЙ раз, хотя Q5, Q8, Q9, Q17 уже спросили его через реестр вопросов (измерено критиком на истории LOCAL-1).

## Что именно менять

Выбранное направление (Lead, §11 спеки): ОДНА дорога — строка `requirement_silent` несёт id вопроса-претензии своего R.

1. `ai-packages/qa-factory/scripts/place_answers.py` (`_line_for`): для строки `requirement_silent` добавить в `refs` id вопроса-претензии каждого R из `info["expectation_hint"]`,
   прочитанный через `contract.claim_questions` (единственный читатель связи R → Q, AR-13); R без вопроса-претензии не добавляет ничего (пустой исход назван, AR-23).
   Тест: строка таблицы в `ai-packages/qa-factory/scripts/tests/test_place_of_draft_observation.py` (keep, `table`; `test_place_answers.py` в карантине — не трогать): R с вопросом-претензией — `refs`
   содержит его id; R без вопроса — `refs` как сегодня.
2. `ai-packages/qa-factory/scripts/report_facts.py` (`exploratory_gate_parts`): строка с id Q в `refs` присоединяется к строке реестра вопросов — один вопрос человеку, не два (FR-7);
   новый текст вопроса не создаётся. Тест: строка в файле, который судит `report_facts.py` (`test_report_facts.py`, медленный — «судит канон пачки»), и сценарный вариант на
   истории `local-1-arm-b`, если дизайнер находит такой вариант без нового файла.
3. Установить (не предполагать) и записать в отчёте узла: идёт ли вопрос дороги находок через `human-questions.md` (AR-16); не прочитано, критик назвал это частью узла. Если нет — отдельная
   строка в эту пачку, не правка в этом узле.
4. TEMPORAL (по умолчанию, дизайнер подтверждает в спеке узла): строки `requirement_silent`, уже записанные в реестр без id Q, не переписываются (реестр только дополняется, AR-14) и читаются по прежнему
   пути; новые строки несут id Q. Оба мира называются в спеке узла.
