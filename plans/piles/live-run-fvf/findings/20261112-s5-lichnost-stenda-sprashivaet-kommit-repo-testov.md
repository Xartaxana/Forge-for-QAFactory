## Что не так

Вопрос `kind: stand_identity` на S5: «For the playwright-tests tests this story is the code of `test-automation-framework` at
commit d33d6194e0ad. Whether that build is there is your call… answer `deployed` if that commit is what `local` runs now».
`d33d619` — HEAD репозитория автотестов (`git log -1` копии плеча: «Merge pull request #4 … CI_CD»), а стенд `local` запускает
приложение MyBooks; стори LOCAL-1 — «текущий код» (ответ на S0, `answers/no-change-current-code.md`), изменения в репозитории
нет. Вопрос просит человека подтвердить бессмыслицу; честного варианта «стори проверяет текущий код стенда, сборка не
важна» нет. Оператор ответил `deployed` (мои: тот же текущий код, на котором шло плечо `free`).

Класс: идентичность сборки стенда берётся из репозитория, где лежат тесты, а не из репозитория приложения (поле одной роли
читается не тем читателем, AR-22); ответ человека «текущий код» на S0 не доходит до S5 (FR-8, AR-24).

Свидетель: `runs/factory-15.log`; `notebook.md`, «Ход прогона», 20:16.

## Что сделать (предложение оператора)

Вопрос о сборке задаётся только когда у стори есть изменение (MR/ветка/коммит) в репозитории ПРИЛОЖЕНИЯ; при записанном на S0
«current code» S5 его не задаёт и пишет строку «проверен текущий код стенда». Тест: стори с `current code` → S5 без вопроса
`stand_identity`.

Принципы и правила: P9; FR-8, FR-10; AR-22, AR-24.
