## Что не так

Класс фабрики: **поле роли оправдано как «его заполняет код», но его не заполняет никакой код** — запрещённое направление
(спека P1-a §4.1: пустое поле роли прощается, только если код действительно его заполняет). Метка стоит на ИМЕНИ листа:
`BY_LEAF` помечает лист `requirements` заполняемым кодом (`handoff_check.py:2734`, `_code_fills`) для трёх полей —
`scope[].requirements` формы S3, `inputs_read[].requirements` формы S3 и `filed[].requirements` формы S8, — а
`_requirements_of` (`handoff_check.py:414-427`) отвечает только для строки КЕЙСА (читает шапку кейса). У плана нет кейса, у строк `filed`
нет `case`/`id` (они несут `cases`), поэтому деривер не может ответить никогда; пустое поле молча прощается.

## Что менять

Направление выбрано (Lead пачки, 13.11.2026): **метка «заполняет код» ключуется полным путём поля, а не именем листа.**

1. `scripts/handoff_check.py`: `BY_LEAF` / `_code_fills` (`:564-609`, `:2725-2734`) — метка по пути (`s3…:scope[].requirements`, …);
   для `requirements` оставить метку только за путём, где `_requirements_of` отвечает (строка кейса). Тест: параметризованная строка на каждое из трёх
   полей — пустое поле остаётся пробелом (`kind == "blank"`), а не прощается; строка кейса — по-прежнему заполняется кодом.
2. Класс: другие листья `BY_LEAF` с тем же свойством (метка шире, чем ответ деривера) — перечислить перебором в отчёте узла
   с вердиктом на каждый (применено / не относится / очередь). Тест: для каждой метки есть путь, на котором деривер отвечает не-None.
3. `form-rounds.json`: три строки `derive ...requirements` (`s3` ×2, `s8`) перепривязаны с FV1-14 к этому узлу (критик: «не тот узел»). Тест: строки зеленеют после п. 1.
