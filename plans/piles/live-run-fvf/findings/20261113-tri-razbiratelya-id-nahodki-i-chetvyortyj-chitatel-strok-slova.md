Факт 1 — разбор тега находки из id (`<тег>:<...>`):

- `scripts/waiver.py:791-793` — докстринг говорил «The ONE place the id is taken apart» (в фикс-раунде докстринг исправлен, разборщик остался);

`sys.modules["waiver"] = None`, и `_passable` → `_finding_tag` обязан работать без импорта `waiver` (иначе `ModuleNotFoundError`). Поэтому единственный
выживший нужен в модуле, который импортируется без `waiver`.

Факт 2 — строки слова человека (`word_passes`): `Controller._record_s5_word_passes` (`controller.py`) читает строки сам, мимо индекса и его мемо
(`s5_precheck.live_word_index`, `Controller._s5_word_memo`); индекс строит `waiver.word_passed_index` из тех же строк. Четвёртый читатель одних и тех же
строк; запись нужна СТРОКАМИ, а не индексом, и бежит только на принятом завершении.

1. Один разборщик тега: функция в модуле, импортируемом без `waiver` (кандидат из отчёта фикса — `scripts/contract.py`; выбор модуля — по предложению
   исполнителя фикса, Lead подтвердит). Три сайта (`waiver` разборщик на `:791-793`, `s5_precheck._finding_tag`, `exit_gate._finding_tag_of`)
   становятся вызовами; докстринг называет единственного выжившего. Тест (таблица, id строки = входной id): `exact`, `tag:one`,

   завершении живой читатель запускается один раз (строка F3 «count 2» в `test_controller_state.py` становится «count 1»); слово,
   записанное между двумя завершениями, видно второму (мемо живёт один вызов).
3. Рядом отмечено (не в этом узле): имя `word_passed` теперь на трёх носителях — решение Lead по F7 отчёта фикса.
