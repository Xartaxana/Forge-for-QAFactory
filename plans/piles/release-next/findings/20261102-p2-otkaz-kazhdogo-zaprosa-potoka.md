## Класс

Возмущение «отказ запроса» выбирается по тому, что назвал источник кейса, а не по запросам, которые делает страница потока (FR-18: исполнение одной проверки не есть покрытие класса; FR-17: один механизм там, где проблема встречается — и в `qa-explore`, и в S3/S4; AR-15, AR-26). Не правило MyBooks.

## Что именно менять

Направление выбрано (Lead, 02.11.2026): ОДИН механизм для `qa-explore` и для S3/S4. Узел RN1-6; зависит от XT2-2 (форма `requests[]`).

1. **Один источник запросов.** `requests[]` карты функции (форма из XT2-2 п. (а): `references/feature-map-form.json`, `scripts/feature_map.py`) читает и стратег S3: бриф S3 (`scripts/brief_pack.py`) несёт список запросов страниц потока. Пусто — «не измерено», не «нет» (FR-41). Тест: карта с тремя запросами → бриф S3 называет все три.
2. **Строка плана на каждый запрос.** Для каждого запроса потока стратег (`agents/qa-test-strategist.md`, правило) пишет строку плана «запрос × отказ (500, таймаут)» с оракулом «страница жива, человек узнал об ошибке, данные не потеряны молча»; ось и оракул — данные (`references/perturbations.json`, как в XT2-2 (б), FR-13, AR-1), не список в коде. Запрос без строки — находка выхода S3 (детектор: `scripts/planning_contract.py`), с дверью «строка уже покрыта кейсом <id>». Тест: поток из трёх запросов → три строки плана; удалена одна строка → находка называет запрос.
3. **Кейс получает шаг из набора.** Дизайнер S4 (`agents/qa-case-designer.md`) выражает отказ шагом `fail_request` (EP1-30), ему отдан список запросов строки; критик кейсов проверяет, что отказ каждого запроса назван в Then. Тест: кейс на отказ без названного запроса — находка критика.
4. **Стоимость под контролем.** Число строк «запрос × отказ» идёт под потолок пачки/размера (SC5-6); перебор без строки «почему не слить» — по правилам TQ1-27, не молчаливое урезание. Тест: потолок задан числом, превышение называет запросы, не вошедшие в план.
