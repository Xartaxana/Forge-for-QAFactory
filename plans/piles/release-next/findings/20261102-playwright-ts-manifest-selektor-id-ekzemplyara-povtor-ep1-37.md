## Причина

Тот же класс, что у EP1-37 (0.10.8, «Playwright TS не читается манифестом, селектором и детектором»): язык теста не читается кодом манифеста, селектора и квитанций; тождество экземпляра Playwright не нормализовано одним читателем. Вынужденный отказ записан как слово человека («accepted by you»). Проба TS — отдельная часть: RN1-8.

## Класс

Вторая сторона языка теста, не читаемая кодом (FR-13, FR-17, FR-18, AR-13: факт с читателем читается только через него). Регрессия/не починено: EP1-37 (`execution-probes/findings/20261031-playwright-ts-ne-chitaetsya-manifestom-selektorom-i-detektorom.md`, «принято, слито 0.10.8»). Фабричный класс, не правило MyBooks.

## Что именно менять

Направление выбрано (Lead, 02.11.2026): шаг 1 — сверить, что из EP1-37 не доехало; шаг 2 — починка тремя точками.

1. **Построение манифеста из тестов TS.** `scripts/manifest_from_tests.py`: заголовок `test(…)` читается и для заголовков, собранных в цикле/шаблоне (`${…}`, `forEach`); без разворачивания — строка «не развёрнуто: N экземпляров» с дверью, а не падение. Тест: фикстура со спецификацией на 11 вариантов в цикле → 11 строк (или честный отказ с именем).
2. **Селектор: несколько тестов.** `scripts/run_suite.py` (сборка селектора запуска Playwright; поиск по `--grep`): несколько имён собираются одним регулярным выражением `--grep "a|b|c"`, а не «последний побеждает»; результат содержит число запущенных против запрошенных, расхождение — отказ. Тест: 11 запрошенных → 11 исполнено; 1 из 11 → отказ.
3. **Один читатель id экземпляра.** `scripts/manifest_put.py` (`_instance`, `:184`; `_identity`, `:188`) и читатели отчёта раннера: id нормализуется одной функцией (префикс `file.spec.@tag` отбрасывается, регистр/разделители приведены); `INSTANCE_MANIFEST_JOIN_FAILED` не порождает «фантомов» в счёте. Тест: манифест с префиксом против отчёта без префикса → один экземпляр, счёт 34 = 34.
4. **Квитанции ревью для TS.** `scripts/window_record.py` / `scripts/story_run.py` (приёмка окна, выдача квитанции): для окна с TS-тестами квитанция выдаётся тем же способом, что для pytest (по записанной проверке критика кода), вопрос человеку «принять без квитанций» не строится (RN1-9). Тест: окно TS с рецензией критика → квитанция есть.
