## Причина

Дедуп черновика бага не смотрит баги среди источников стори (тикеты типа Bug), только `bugs/`; аналитик S7 дробит баг по классу входа/требованию, а не по месту дефекта; дедупа черновиков по `defect_location` нет.

## Класс

Черновик бага сверяется со всем, что фабрика уже прочла об этом дефекте (открытые баги источников), и режется по причине, а не по требованию (AR-14, FR-16, FR-3). Фабричный класс.

## Что именно менять

Направление выбрано (Lead, 02.11.2026).

1. **Дедуп с открытыми багами источников.** `scripts/bug_records.py` (сборка черновика; рядом `pair_drafts`, `:352`) читает открытые баги из `sources/*/ticket.json` (type Bug, статус не закрыт) и сверяет по `defect_location` и по ключам требований; совпадение — поле черновика `duplicate_of: XPANBFLFA-140` и строка «дополнить существующий баг» в пакете гейта B (`scripts/gate_brief.py` `bug_drafts`, `:3763`). Тест: фикстура с открытым Bug-тикетом на то же место → `duplicate_of`.
2. **Склейка по причине.** `agents/qa-failure-analyst.md` и `scripts/bug_records.py`: черновики одного `defect_location` (файл:строка) собираются в один с перечнем требований/экземпляров; склеивает фабрика, не человек. Тест: три красных одной строки → один черновик с R-8, R-9, R-10.
3. **Гейт B.** Вопрос «какие из N багов заводим» не задаётся по черновикам одной причины. Тест на пакете гейта B.
