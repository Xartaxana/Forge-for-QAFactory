## Причина

Ожидание в AskUserQuestion не считается ожиданием; «переделка» = порядковый номер диспатча роли, а не повтор scope; диспатчи считаются по сессии агента, а не по handoff. Читатель: `scripts/retro_numbers.py` (`dispatches`, `:219`; `stage_times`, `:1047`; `journal_counts`, `:1028`), метрики — `references/metrics/catalogue.json` (C04 «Human wait»), `references/metrics/cost.md`.

## Класс

Две записи одной величины расходятся, и отчёт печатает неверную как точную (FR-25, FR-26, FR-41, P18; AR-13, AR-22). Фабричный класс.

## Что именно менять

Направление выбрано (Lead, 02.11.2026).

1. **Ожидание из событий вопроса.** `scripts/retro_numbers.py`: «Human wait» = сумма интервалов «вопрос задан → ответ получен» по журналу драйвера/событиям (`E:*` вопроса и слова человека), а не поле halts. Тест: фикстура с вопросом 05:20:48 → ответ 09:10:04 даёт 3 ч 49 мин 16 с.
2. **Машинное время.** Стена стадии минус ожидание внутри стадии; для S6 — ≈ 30 мин. Тест на той же фикстуре.
3. **Круг доработки = повтор scope.** `dispatches` считает «repair round» только для диспатча роли, чей scope (окно/кейсы) уже встречался; новое окно — не починка. Тест: 14 диспатчей с 10 повторами scope → 10 rounds.
4. **Диспатчи по handoff.** Число диспатчей роли — по файлам handoff/событиям `dispatch`, не по id сессии агента; сессии, использованные дважды, разводятся. Тест: два handoff в одной сессии → 2.
5. **Противоречие «no recorded usage».** Если для роли есть строка стоимости, фраза «no recorded usage» не печатается; если нет — цена роли «не оценена» (диапазон, FR-41). Тест на фикстуре с automator.
