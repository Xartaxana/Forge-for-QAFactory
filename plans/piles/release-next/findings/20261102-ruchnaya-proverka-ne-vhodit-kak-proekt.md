## Причина (проверено по коду 02.11.2026)

1. **Шаги пишутся заранее, исполняются вслепую.** Агент `qa-runner` пишет файл шагов, `scripts/manual_capture.py` исполняет его целиком и
   записывает улики. Агент не видит, что получается по ходу, и не может подстроиться; шаг, не подошедший к странице, — падение проверки, а не
   наблюдение. Отчёт кейса — по Then; сомнительное на шагах до Then не собирается как наблюдение для аналитика.
2. **Рецепт входа — форма Test Project 1.** `manual_capture.py` `http_login_source` (:2973): ключ проекта `manual_capture.login.http` (путь +
   `token_field`: один POST → токен), `environment.access` вида `local_login`, умолчание фабрики. Вход «CSRF → форма → кука» не выражается.
3. **`harness_command` закрыт по замыслу** EP1-31 (0.10.8, `execution-probes/findings/20261031-recept-vhoda-ruchnoj-proverki-testproject1-a-onboarding-vyuchil-svoj.md`
   п. 1 (г), п. 2): отказ до запроса и вопрос на онбординге, которого на MyBooks не было.
4. **Отказ приписан человеку и не разобран** (`owner: user`; FR-3, FR-19; P22 — узел RN1-9).

## Что именно менять

Направление — слово владельца 02.11.2026 (P26). Узел многошаговый: спеку пишет designer по этому разделу, критик на план (меняется смысл улики
ручной проверки — PROJECT.md «Как принимается» п. 6).

1. **Пошаговый режим инструмента.** `scripts/manual_capture.py` получает режим «один шаг за вызов» над живой сессией браузера/HTTP прогона:
   агент вызывает шаг (открыть, нажать, ввести, запрос, войти как <актёр>), код исполняет его, пишет улики шага (снимок, видимый текст,
   запросы и ответы — HAR, трассировка Playwright) под id улики и возвращает агенту короткий результат (что на экране/в ответе, id улики).
   Сессия живёт между вызовами. Тест: два шага подряд в одной сессии, у каждого свой id улики и файлы.
2. **Вход доказан пробой стенда, а не обнаруживается в S6.** Слово владельца 02.11.2026: «такого отказа быть не должно. Если фабрика не может
   войти, это обнаружится на пробах стенда намного раньше». Поэтому: (а) проба стенда (онбординг `stand_access`, проба гейта A
   `gate_preflight`) проверяет вход ТЕМ ЖЕ способом, каким ручная проверка будет входить, и для КАЖДОГО учётного типа, который нужен актёрам
   кейсов плана (`stand_account`: `user`, `admin`, …), и записывает способ, который сработал; (б) ручная проверка берёт вход только из
   записанного пробой способа — агент входит через страницу входа шагами п. 1 или код берёт готовую сессию из команды входа проекта
   (`access.kind: harness_command` → Playwright `storageState`; как её сохранить — строка данных раннера в `references/`, AR-1); рецепт «один
   POST → токен» — один из способов, не единственный; (в) у ручной проверки нет своего отказа «не умеем войти»: вход, не доказанный пробой,
   до S6 не доходит — его разбирает проба (P22, RN1-9), а вход, переставший работать в прогоне, — событие стенда (стенд упал / учётка
   отозвана), которое идёт тем же путём, что и любой упавший стенд (`stand_health`), а не отказом инструмента. Сессия на каждого актёра кейса
   (PC-1 покупатель, PC-3 админ). Тесты: проба стенда на фикстуре с актёрами `user` и `admin` проверяет оба входа и пишет способ; ручная
   проверка без записанного пробой способа — ошибка вызова (дефект фабрики), а не `env_blocked` с владельцем; фикстура `harness_command` с
   командой, пишущей `storageState` → шаг `http` идёт с кукой; фикстура NextAuth (csrf → callback/credentials → кука) проходится шагами.
3. **Вывод агента — только по записанной улике.** Каждый «факт» в результате (`actual`, `then_quotes`, наблюдение) ссылается на id улики; код
   сверяет, что цитата есть в записанном ответе/тексте страницы этого шага. Нет ссылки или цитата не найдена — отказ с названием поля (FR-1,
   FR-18). Тест: цитата из улики — принято; выдуманная цитата — отказ.
4. **Наблюдения по ходу — наравне с Then.** Агент пишет каждое сомнительное место на любом шаге: шаг не выполнился, элемента нет, поведение
   странное или расходится с кейсом/требованием (пример владельца: ввод «1», затем «2» отправляет «1» сразу — двузначное количество не заказать,
   хотя запросом 12 проходит). Поле результата `observations[]`: шаг, что ожидалось, что видно, id улики. Падение шага до первого Then — не
   «кейс не исполнен», а наблюдение с уликой. `agents/qa-runner.md` — правило; форма результата — в данных/схеме ручной проверки.
5. **Наблюдения доходят до аналитика.** S7 (`agents/qa-failure-analyst.md`, триаж) получает `observations[]` целиком в передаче (FR-49, AR-21)
   и выносит по каждому «баг / не баг / вопрос человеку» так же, как по красному Then. Тест: наблюдение без Then доходит до триажа и до отчёта.
6. **Живое доказательство (FR-33):** TC_022 и TC_023 LOCAL-1 исполнены на MyBooks `a25b080`: вход пройден, улики шагов записаны, наблюдения
   (если есть) дошли до S7.
