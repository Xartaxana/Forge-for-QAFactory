# «OH6-1 turned a traceback into a silent skip for non-str/NUL session ids»: `cost_capture` молча выходит там, где раньше падал с видимым traceback

id: — | кучка: `onboarding-hooks` | от: спека t-282 F-8, критик на план t-286 (пункт 5, FR-4), 13.11.2026 | приоритет: П3 | кандидат наверх: нет

## Что наблюдалось

Класс (FR-4, P18): проверка, которая останавливает молча, — молчаливый пропуск информированного отказа. Слова критика t-286, которые находка обязана нести: «OH6-1 turned a traceback into a silent skip for non-str/NUL session ids».

`cost_capture._capture` (около :1907) выходит `sys.exit(0)`, а `cost_capture.main` (около :3800) делает `return`, когда id сессии — не одна компонента пути. Направление «тихий выход» уже было для `/ \ : . ..`, и бриф OH6-1 велит сохранять направления. Но OH6-1 расширяет молчащий класс: id сессии не-строка (`str`) или с NUL раньше оставлял видимый traceback (`TypeError` или падение записи — информированный отказ, FR-4), а после узла не оставляет ничего (спека t-282 §4, колонка «7/8», строки «NUL» и «non-str»). Настоящие id хоста — строки UUID, риск на практике низок; не блокирует.

## Что именно менять

Направление выбрано спекой t-282 (F-8 (a), решение координатора 13.11.2026, «по рекомендации, до слова владельца»): OH6-1 направление сохраняет, расширение молчащего класса записано этой находкой. Вопрос Lead пачки (спека F-8 (b)): добавить ли строку в stderr при отказе id сессии (`sys.exit(0)` и `return` сохраняются, добавляется одна строка «session id refused: <причина>»; хук по-прежнему не падает и не блокирует). Ожидаемое поведение: отказанный id оставляет видимый след (stderr или запись `note_denial`), код выхода и поток хука не меняются.

## Тест

Одна таблица в тесте `cost_capture` × id `5` (int), `["a"]` (list), `a\0b`, `..`, `a/b`, хороший id: хороший id пишет запись; остальные — выход без записи и (после решения Lead) строка в stderr; id параметра называет «вызывающий-id». Положительный контроль: хороший id пишет запись.
