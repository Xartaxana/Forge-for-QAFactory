# Запускатель `hooks/run-py.cmd` добавляет к каждому вызову около 1,15 с на Windows: медиана 1821 мс…

id: B-360 | кучка: `onboarding-hooks` | от: координатор, замер W7 | приоритет: — | кандидат наверх: нет

перенос: speed-cost/batch-1 (узел SC1-5; слово владельца 26.10.2026)

Что не так / что сделать: Запускатель `hooks/run-py.cmd` добавляет к каждому вызову около 1,15 с на Windows: медиана 1821 мс против 667 мс у прямого `python -B` (7 прогонов `waiver.py --help`, 03.10.2026, эта машина). Миграция задержку не внесла: запускатель до волны 3 (`2bfba57`) — 1886 мс. Откуда: два-три поиска `where py / python / python3` на каждый вызов (вместе с запуском cmd — 1216 мс) и выбор `py -3`, который сам медленнее `python` (1110 мс против 667). Через запускатель идёт каждый хук, так что цена платится на каждом вызове инструмента ролью (FR-55). Проверить: выбирать интерпретатор без `where` (сначала `python`, запасной путь — по ошибке запуска) и замерить заново; не чинить без замера на живом прогоне, сколько вызовов хуков приходится на стадию. [F16]

Свидетель: Замер координатора 03.10.2026 (узел W7 миграции legacy-2406, часть «задержка запускателя»); числа — вывод `Measure-Command`, семь прогонов на вариант.

Принципы и правила: FR-55, FR-51

Решение владельца нужно: нет (фраза не найдена)
