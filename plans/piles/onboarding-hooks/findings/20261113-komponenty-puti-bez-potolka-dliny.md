# Компоненты записываемого пути без потолка длины: ключ, основа имени или id сессии растят путь сверх предела корня (скаут t-216, спека t-203 §6 Q-1)

id: — | кучка: `onboarding-hooks` | от: скаут t-216 (результат — в спеке t-203, факт 10 и §6 Q-1), 13.11.2026 | приоритет: П3 | кандидат наверх: да (новая ось карты, см. ниже)

## Что наблюдалось

Поддерживаемый корень проекта на Windows — 119 знаков при пределе пути 259 (`native_context.py:10-13`, `PACKET_ROOT_LIMIT = 119`; на ветке `wip/oh3-36` рядом `SUPPORTED_ROOT = 119`, `PATH_LIMITS`). Число выведено для писателей с ОГРАНИЧЕННЫМ суффиксом (пакет нативного контекста, привязка `host_dispatch`: корень + 140). Скаут t-216 нашёл писателей, у которых часть пути — ключ тикета, основа имени файла или id сессии — не ограничена ничем: путь растёт с длиной компоненты, и запись молча не удаётся (или удаётся только на длинных путях). Точный список мест скаутом названным не пересчитан: узел начинается с него.

## Что именно менять

Направление выбрано координатором (13.11.2026, «по рекомендации, до слова владельца»): ОДНА константа предела длины компоненты рядом с `PACKET_ROOT_LIMIT` (`native_context.py`, либо на ветке `wip/oh3-36` рядом с `SUPPORTED_ROOT`), и проверка ТАМ, ГДЕ компонента формируется (а не у каждого писателя своя). Исполнитель узла — `scout → builder`: первый шаг — скаут перечисляет места, где компонента пути из ключа, основы имени или id сессии входит в записываемый путь (поиск по `scripts/*.py`: места, где `/ key`, `/ stem`, `/ session` строят путь под `qa-factory/`; вывод — таблица «место — что за компонента — есть ли потолок — чем ограничен»; положительный контроль — известные места нативного пакета, где потолок есть). Второй шаг — билдер по таблице:
1. Константа `COMPONENT_LIMIT` (значение выводит билдер из формулы: 259 − 119 − самый длинный фиксированный суффикс пути в таблице; формула в комментарии рядом, как у `PACKET_ROOT_LIMIT`; число не сочиняется — считается).
2. В каждом месте таблицы компонента длиннее `COMPONENT_LIMIT` — отказ там, где компонента формируется, с текстом «что не так — чего ждали — как исправить» (FR-1): называет компоненту, её длину и предел; направление ошибки места сохраняется (хук — тихий выход, CLI — отказ).
3. Тест: параметризованная таблица по местам скаута — компонента длины `COMPONENT_LIMIT`, `COMPONENT_LIMIT + 1`, пустая, с не-ASCII (по два знака на символ не считаем: предел в символах); ожидание — путь целиком в пределах 259, либо отказ с названием компоненты. Файл — `test_resolver.py` или тест модуля места (keep-файл, нового нет).

Родственное, но отдельное: сдвиг самого корня при укорачивании временного суффикса `event_store._publish` — F-2 (`findings/20261113-oh5-11-ostatki-f2-publish-temp-f6-native-valueerror.md`); этот узел после F-2 пересчитывает константу.
