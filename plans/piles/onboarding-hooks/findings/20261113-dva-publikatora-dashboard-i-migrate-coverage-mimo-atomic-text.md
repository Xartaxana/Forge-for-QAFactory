# Два писателя пакета публикуют через собственное 32-hex временное имя, не через `event_store.atomic_text`

id: — | кучка: `onboarding-hooks` | от: спека t-263 (§B, F-C), 13.11.2026 | приоритет: П3 | кандидат наверх: нет

## Что наблюдалось

«Записать во временный файл и заменить» в пакете делает `event_store._publish` (через `atomic_text`, `event_store.py:151`). Два
писателя делают то же своим кодом:
- `factory_dashboard.py:4170` — `temporary = out.with_name(out.name + "." + uuid.uuid4().hex + ".tmp")`;
- `migrate_coverage.py:25` — `temporary = path.with_name(path.name + "." + uuid.uuid4().hex + ".tmp")`.

Это вторая и третья дорога для одного действия (P31, AR-15). OH6-3 укорачивает суффикс `_publish` до 8 hex; эти два писателя
остаются на 32, и правило N8a `driver-golden-rules.json` нормализует их только альтернативой `{8}|{32}` (спека t-263, F-B).

## Что именно менять

Направление выбрано (спека t-263, F-C (a), «по рекомендации, до слова владельца»): оба вызывают `event_store.atomic_text`.
1. `factory_dashboard.py` (около :4170): публикация файла идёт через `event_store.atomic_text(out, text)`; собственное имя через
   `uuid` и замена убираются; если `uuid` больше нигде не нужен в модуле — импорт тоже.
2. `migrate_coverage.py` (около :25): то же для `path`.
3. Исход при сбое записи тот же, что сегодня у каждого (исключение не глотается, временный файл не остаётся).

Тест: у каждого писателя запись в доступную папку даёт тот же файл, что раньше; временного `.tmp` рядом нет. Порядок: после OH6-3
(тогда альтернативу N8a можно сузить до `{8}`). `factory_dashboard.py` — зона `cost-dashboard`: правка одной строки.
