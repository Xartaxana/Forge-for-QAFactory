# Гард доставки читает тело heredoc и кавычечный аргумент как команду: текст ответов с «gh pr create» отказан

id: — | кучка: `onboarding-hooks` | от: прогон TP1-12586 на 0.10.5, `testproject1-dev-010`, 29.10.2026 (сообщение дирижёра, передано владельцем) | приоритет: П2 | кандидат наверх: нет

## Что наблюдалось

Дирижёр: «Один раз guard заблокировал мою команду с текстом ответов в heredoc, сославшись на delivery-команду. Это похоже на ложное
срабатывание: повторная запись через файлы и отдельные вызовы прошла без проблем». Точная команда не сохранена; форма воспроизведена
на пакете 0.10.5 (`stage_guard._delivery_match`, пустой конфиг проекта):

| Команда | Вердикт |
|---|---|
| `cat > answers.txt <<'EOF'` / `ok, gh pr create later` / `EOF` | `gh pr create` (github) — отказ |
| `python story_run.py answer --words-file - <<'EOF'` / `yes, then glab mr create the fix` / `EOF` | `glab mr create` (gitlab) — отказ |
| `python story_run.py answer --text "yes; glab mr create"` | `glab mr create` — отказ |
| `cat > answers.txt <<'EOF'` / `please git push the branch` / `EOF` | пропуск |

Оба диалекта (bash и PowerShell) находят форму в теле heredoc.

## Класс

Один вопрос — «какой текст команды исполняется, а какой только хранится» — решён в двух местах по-разному (AR-13, AR-15):
`guard_pre_tool._split_off_bodies` выносит тело heredoc с кавычечным разделителем и here-string в текст (инцидент 2026-09-23 с
`waiver.py` в теле heredoc, комментарий у `guard_pre_tool.py:124`), а `stage_guard._delivery_match` читает сырую команду: тело heredoc
идёт в обход как строки shell, а кавычечные аргументы любой не-mention команды читаются как команды ещё раз (докстринг
`_delivery_in_text`: «the gate errs toward refusing»). Ответ человека, бриф или комментарий, где упомянута команда доставки, становится
доставкой. Отказ имеет дверь (через файл и отдельный вызов), но роль тратит ход и не знает, почему (FR-4, P15).

Сосед — OH3-22 (N-4, прогон 14857: `for … in`, `def log(` ловятся как доставка): тот же читатель, та же ошибка направления. Другие
правила `stage_guard` (коммит тестов при дырах манифеста, правила ранера R1–R4) читают тот же сырой текст — проверить на теле heredoc.

## Направление

Тело heredoc с кавычечным разделителем (или без подстановок), если приёмник не интерпретатор, и here-string — текст для ВСЕХ правил
`stage_guard`, через один общий разбор с `guard_pre_tool` (один выживший, AR-15); кавычечный аргумент не-shell команды (`python x.py
--text "…"`) — текст, кроме `-c`/`eval`/shell-приёмников. Тесты: четыре строки таблицы выше (три — пропуск, `bash -c "gh pr create"` и
`python - <<'EOF'` с вызовом — по-прежнему отказ). Узел OH3-22 расширен этой находкой (один писатель `stage_guard.py`).

Принципы и правила: P15, FR-4, FR-12, FR-57, AR-9, AR-13, AR-15.

Решение владельца нужно: нет.
