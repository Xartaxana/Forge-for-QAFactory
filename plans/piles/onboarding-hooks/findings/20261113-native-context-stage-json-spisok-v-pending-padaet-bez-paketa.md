# `native_context.stage`: pending-файл со списком JSON бросает `AttributeError`, запуск идёт без пакета

id: — | кучка: `onboarding-hooks` | от: спека t-263 (§N, N-1), 13.11.2026 | приоритет: П3 | кандидат наверх: нет

## Что наблюдалось

`native_context.py:164`: `if path.is_file() and json.loads(path.read_text(encoding='utf-8')).get('status') == 'pending':`. Если pending-файл
содержит JSON-список (число, строку), `.get` бросает `AttributeError`; он не пойман в `stage` и уходит в обработчик «fail-open»
`inject_context.main`: нативный запуск идёт дальше БЕЗ пакета, остаётся только сигнал (класс AR-28: неизвестное стало проходом).
Рядом `native_context.py:69` читает JSON тем же способом (`data = json.loads(...)`), `:179` зовёт `data.get('status')`.

## Что именно менять

Направление выбрано: не-словарь — нечитаемый пакет, идёт существующая дорога отказа для нечитаемого пакета.
1. `native_context.stage` (:164): после `json.loads` проверка `isinstance(data, dict)`; иначе то же, что для повреждённого JSON, —
   отказ с названием файла и дверью, а не `AttributeError`.
2. Соседние чтения `:69`, `:179` — перечислить в узле и привести к той же проверке или записать «не применимо — почему».
3. Тест: таблица содержимого pending-файла — `[]`, `[1]`, `1`, `"x"`, `null`, `{}`, `{"status":"pending"}`; каждое не-словарное даёт
   отказ с именем файла, не исключение; `{}` и `{"status":"pending"}` ведут себя как прежде.
