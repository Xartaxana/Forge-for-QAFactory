# Два исключения пункта (f) не взяты: учётка по умолчанию спрашивается из-за открытой карточки роли

id: — | кучка: `project-knowledge` | от: остаток R-2 (iii) спеки `docs/tasks/specs/t-2142-project-knowledge-phase0.md` §6 (правка 3, N3 повторной проверки) | приоритет: П2 | кандидат наверх: нет

Решение владельца нужно: да — взвесить цену; по умолчанию остаётся как сейчас (ошибка в сторону вопроса).

## Что наблюдалось

Класс фабрики: гейт «нужна ли учётка по умолчанию» перечисляет причины, по которым она нужна; чем больше причин считается «нужна», тем
чаще человек отвечает на вопрос, который стори не держит. Повторная проверка предложила два исключения пункта (f) (когда по умолчанию
учётка НЕ нужна): (1) роль уже вынесена карточкой на этом гейте, и ни один ответ карточки не заставляет бегуна создавать учётку;
(2) роль, все кейсы которой отброшены `level_applied` / `decisions`. По направлению Lead («ошибка в сторону вопроса для любой другой
неизвестности») оба НЕ взяты. Цена: учётка по умолчанию спрашивается в стори, единственная причина которой — открытая карточка роли.

## Что именно менять

Сейчас — ничего: узел PK0-4 держит пункт (f) без двух исключений (таблица краёв спеки: «роль с карточкой и вход по умолчанию — пункт (f)
всё ещё считает её»). Если владелец решит взять: файл — `ai-packages/qa-factory/scripts/gate_preflight.py`, функция пункта (f) в
`check_s5_credentials` (имя уточняет спека узла). Ожидаемое поведение: (1) роль с открытой карточкой на этом гейте не считается причиной
для входа по умолчанию, пока ответ карточки не потребует учётки; (2) роль, кейсы которой отброшены, не считается причиной; неизвестное
состояние кейса — по-прежнему причина (AR-28). Тест на каждое исключение и контроль «неизвестное — спрашивается».
Рекомендация: не брать до живого прогона, показавшего, что лишний вопрос случается; тогда — узел с этим текстом.
