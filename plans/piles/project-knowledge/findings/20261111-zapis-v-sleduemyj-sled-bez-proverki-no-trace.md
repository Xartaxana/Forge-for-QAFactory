# Записывающие команды семейства записей не проверяют `no_trace`: опыт оставляет след в проекте

id: — | кучка: `project-knowledge` | от: критик t-2349 на PK0-1 (Q1), спека t-2142 F-22 | приоритет: П2 | кандидат наверх: нет

Решение владельца нужно: нет.

## Что наблюдалось

Класс фабрики: «переносимая запись, записанная историей, которая по правилу P8 / FR-53 не оставляет следов». У реестра ответов
(`project_knowledge.py`) проверка `no_trace` теперь есть на всех трёх записывающих командах (`account`, `role`, `revoke`; через
`_refuse_no_trace`). У остальных членов семейства её нет: `environment_record.py record|revoke`, и, по спеке t-2142 F-22, ни один
писатель записей её не проверяет (`project_decisions`, `product_gaps`, `waiver`). Эксперимент сравнения версий (`no_trace: true`) может
оставить переносимую запись в проекте. Ось в `docs/SIBLING_MAP.md` этот класс не несёт (поиск по `no_trace` и `environment_record` —
только текст осей 29/30, не про это).

## Что именно менять

Сначала разведка (scout): перечислить все писатели переносимых записей (`records/*.json`, решения, пробелы, расписки) и для каждого —
проверяет ли он `no_trace` и через какую функцию; единственный читатель признака — `external_writes.closed_by_run`. Затем один общий
помощник отказа (не копия `_refuse_no_trace` в каждом писателе, AR-15) и строка оси в `docs/SIBLING_MAP.md`. Тест на каждый писатель:
`no_trace` — отказ с выходом 2 и файл не изменён; не `no_trace` — запись проходит.

Принципы и правила: P8, FR-53, FR-54, AR-14, AR-15.
