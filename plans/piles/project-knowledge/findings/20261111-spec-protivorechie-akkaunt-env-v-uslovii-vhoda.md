# Спека противоречит себе: кейс только с `env`-аккаунтом — нужен ли вход по умолчанию

id: — | кучка: `project-knowledge` | от: критик t-2361 (L1) по узлу PK0-5, коммит 0d621b69a | приоритет: П3 | кандидат наверх: нет

Решение владельца нужно: нет — решает Lead пачки при правке спеки.

## Что наблюдалось

Спека `docs/tasks/specs/t-2142-project-knowledge-phase0.md` §3 (7), условие (c): вход по умолчанию нужен, если кейс «не объявляет аккаунт
в предусловиях». Её же итог (строка ~718): НЕ нужен, когда каждый исполняемый кейс объявляет не-дефолтную РОЛЬ с известным аккаунтом. Кейс,
который входит только по аккаунту `env:...`, подпадает под оба чтения по-разному. Код (`gate_preflight.default_login_needed`) следует итогу и
спрашивает (аккаунт `env` не считается названным); докстрока приведена к коду.

## Что именно менять

Класс: правило «когда спрашивать вход по умолчанию» описано двумя формулировками одной спеки. Выбрать одну: либо аккаунт `env` считается
названным (правка спеки + одна строка в `gate_preflight.default_login_needed`, фильтр `named`, и тест `env`-кейса), либо условие (c) в спеке
переписывается на «нет предусловия `kind: account` с ролью `stand_account`». Направление по умолчанию — второе (сторона вопроса, В8).
Тест: кейс с одним `env`-аккаунтом — ожидание названо в тесте.
