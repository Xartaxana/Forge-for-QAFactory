# Неудовлетворённая учётка по умолчанию всё ещё доходит до трёх карточек

## Что наблюдалось

Класс фабрики: одно и то же недостающее знание (учётка стенда) спрашивается человеком несколькими карточками, когда у знания несколько
путей к человеку. Инвариант узла PK0-4 «одна карточка на одну неудовлетворённую учётку» держится для ролей продукта; учётка `default`
(вход без роли) остаётся вне него. Известный случай F-13 спеки: гейт A, `check_actor_sign_in`, при `_stand_account == unmet` через
`_probe_actor` добавляет ЕЩЁ одну карточку про ту же недостающую учётку. Три пути, по которым `default` может дойти до человека
повторно: (1) `_probe_actor`; (2) ключи входа в `check_s5_credentials` (`ai-packages/qa-factory/scripts/gate_preflight.py`);
(3) пункт `default` в предусловиях отдельного кейса.

## Что именно менять

Файл: `ai-packages/qa-factory/scripts/gate_preflight.py`. Выбрано направление: неудовлетворённая `default` проходит через ту же функцию
«решено один раз» (одна строка, не ноль — AR-28, не две — FR-10), что и роли после PK0-4; два других пути читают её решение, а не
спрашивают сами. Ожидаемое поведение: при `unmet` для `default` в пакете гейта ровно одна карточка про эту учётку, независимо от числа
кейсов с пунктом `default`; решённая (`known` / `not_needed`) не спрашивается ни одним из трёх путей. Тест на каждый путь: стори с
неудовлетворённой `default` и (а) `_probe_actor`, (б) ключами входа, (в) двумя кейсами с пунктом `default` — число карточек про учётку
равно одному; контроль: после ответа — нуль. Рекомендация: делать сразу после PK0-4 следующей текстовой правкой гейта A.

Принципы и правила: AR-15, AR-25, AR-28, FR-7, FR-10, FR-17, P22.
