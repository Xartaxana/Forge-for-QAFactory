## Что наблюдалось

- Б-4: `POST /api/cart/merge` отвечает 500 при входе — вход проходит с сообщением «Successfully logged in!», гостевая корзина молча
  пропадает. Код: `MyBooks/src/components/pages/LoginPage.tsx:36-39` — `await fetch('/api/cart/merge', { method: 'POST' })`, затем
  `catch (mergeError) { console.error(...) }`; человеку ничего не показывается (свод `experiments/mybooks/cart-1-run-problems.md`, п. 1, Б-4;
  разведка `docs/tasks/specs/reports/t-1634-mybooks-cart-bug-hypotheses.md`, H1 «Сопутствующее»).

  не проверяется; сбой `GET /api/books/{id}` → 500 валит всю страницу («Something went wrong»).
- Слияние не выведено требованием вовсе: Jira не читалась (`not_fetched`, OH3-39), а S1/S2 `catch`, глотающий ошибку, требованием не
  делают. В реестре CART-1 есть R-8 (слияние при входе: больший остаток, лимит) и R-9 (регистрация и слияние), но требования «сбой слияния виден
  человеку» нет (свидетель: `work/requirements-register.md:20-21` копии проекта, строки R-8 и R-9; поиск по файлу слова `merge` — только строки 13, 19-21).
  Эталон `experiments/mybooks/add-to-cart-cases.md` держит это вопросом Q3.
- Б-4 фабрика могла получить даже при этом: правило владельца Q1 гейта A «код не даёт сделать задуманное — баг» применимо, но строки,
  к которой его применить, не было.

## Класс

«Сбой зависимости на пути пользователя не виден человеку» — класс фабрики, не правило MyBooks. Такие места ищет и классифицирует роль
на любом проекте и языке: обработчик ловит ошибку (или не проверяет статус ответа) и не сообщает пользователю; результат — тихая потеря
данных или молчаливый «успех». Признаки — данные-шаблоны (AR-1, FR-13), не список файлов и не фраз проекта; вердикт, считать ли
место дефектом, — за ролью (FR-12, AR-2); код только называет совпадение шаблона.

## Что именно менять

Направление выбрано (Lead пачки, по рекомендации, до слова владельца).

1. Шаблоны класса — данные: новый файл `references/user-path-failure-patterns.json` (список записей `{id, language_hint, shape, why}`; две
   записи на старт: `swallowed_catch` — `catch`/`except`, чей блок только пишет в лог (`console.error`, `logger.*`, `print`) и не
   показывает ошибку человеку и не перебрасывает; `unchecked_response` — результат `fetch`/`requests`/`axios` читается (`.json()`) без проверки
   `ok`/статуса). Формат и чтение — по образцу соседних `references/*.json`; язык кода не вшит (FR-13, AR-1); для языка без шаблона —
   «не измерено: нет шаблона для <язык>» (FR-41), не «мест нет».
2. Чтение. Скрипт поиска совпадений на входе S1/S2 — функция в `scripts/` рядом с читателем диффа (дизайнер называет файл; не второй
   читатель диффа: брать ханки из `diff_pass` / `repo_map` там, где они есть, иначе файлы области кода тикета). Результат — список
   `[{pattern, file, line, handler}]` в пакет контекста S2 (`brief_pack.py`, раздел по образцу `blast_radius_line`). Предел: не больше 20
   совпадений на бриф, остальное — строка «ещё N, список в <файл>» (край: усечение называется, не молчит).
3. Роль. `agents/qa-requirements-tester.md` и `skills/qa-story/phases/s2.md`: совпадение шаблона, лежащее на пути пользователя (обработчик
   действия, вход, загрузка страницы), роль превращает в строку-кандидат реестра `derived`, `derived_from: bug:candidate-defect`,
   `observable: current-code:<файл>:<строка>`, суть — «сбой <зависимости> на пути <действия> не виден человеку» (ожидание не пишется
   из кода: оно `unconfirmed`, G2-12). Совпадение вне пути пользователя (служебный фон, логгер) роль отбрасывает с записью причины в `open`
   (FR-47: решает роль, код называет). Дальше кандидат идёт обычной дорогой G2-15 (бриф → строка плана → тест).
4. Теста нет без фикстуры: фикстуры кода в `scripts/tests/fixtures/` (положительная и отрицательная).
5. Тесты: новый `scripts/tests/test_user_path_failure_patterns.py`: (а) фикстура обработчика входа с `await fetch(...)` и
   `catch (e) { console.error(e) }` — совпадение `swallowed_catch`, и строка попадает в бриф S2; (б) `catch`, который вызывает тост/сообщение
   человеку — совпадения нет; (в) `fetch` с `if (!response.ok)` — совпадения `unchecked_response` нет; (г) код на языке без шаблона —
   «не измерено», не пусто; (д) 21 совпадение — 20 строк и «ещё 1»; (е) нечитаемый JSON шаблонов — отказ с именем файла и дверью, не молчаливый
   пустой список.

Критик на план: да (новый вход в реестр, формат данных). Свидетель билдера — тестовый файл узла.
