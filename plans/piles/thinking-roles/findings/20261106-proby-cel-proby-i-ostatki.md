# Мутационные пробы: проба не в цель (30 из 44), `assertion_id` манифеста на строку мимо Then, повтор пробы запирает цель

id: — | кучка: `thinking-roles` | от: живая проверка проб на копии `tr-probe`, 06.11.2026 (`docs/tasks/specs/reports/t-2031-probe-live-proof-report.md`); ревью `docs/tasks/specs/reviews/t-2000-critic-probe-diff.md` (S1, S2, L2, Q5); отчёт `docs/tasks/specs/reports/t-2007-probe-fix-round-report.md`; очередь лида, пункты 3 и 9 | приоритет: П1 | кандидат наверх: нет

Решение владельца нужно: нет — S1 взят по рекомендации критика (Lead, 06.11.2026). Владельцу сказать (не вопрос): у тестов на Python нет прицельной пробы `--at`, для них слово человека о пробеле остаётся единственной дверью.

## Что наблюдалось

- Маркер доказан вживую (14 проб, форма M-TS1, файл после пробы побайтно тот же). Окно TC_001, TC_002 при этом `approved` не получило: `assertion_id` в манифесте стоит на строку мимо Then (46 при Then на 47 — пустая строка; 104 при 105), поэтому `--at` не может дать `is_assertion_id: true`, и проверка «проба не на той строке не доказывает» превращает каждую такую пробу в пробел.
- Критик: 30 из 44 настоящих проб не в цель — проба по умолчанию портит ПЕРВУЮ проверку теста, а не проверку обязательства.
- `--at 47` дал `no_failure` (тост исчезает сам), после чего `--at 46` отказан `already_probed`: проверка «уже пробовали эти байты» не смотрит на цель, и первый неудачный прицел оставляет только слово человека. Запись `no_failure` на :47 заменила запись `intended_failure` на :43 как запись экземпляра.
- Старое слово человека «go on…» из прошлого прогона печатается как «recorded, not read by this window» — применено как вейвер скоупа (AR-24).
- Путь `--judge` вживую не достигнут (ни одной записи `cause: judgment`); форма M-TS2 проверена только вне стенда.

## Что именно менять

### TR2-1. Проба целится в проверку обязательства с первой попытки

- Найти производителя `assertion_id` (кто пишет номер строки в строку манифеста: `scripts/manifest_put.py` / `manifest_from_tests`, вход — автоматор) и причину сдвига на одну строку: разбор — первый шаг узла, итог в этот файл.
- Поведение: (1) `assertion_id` указывает на строку, где начинается выражение проверки Then; запись в манифест отказывает номеру строки, на которой нет проверки (пустая строка, строка без вызова из набора `assertion_probes` языка), и называет ближайшую проверку ниже — проверка данных, не суждение. (2) `scripts/probe_by_code.py` без `--at` целится в `assertion_id` экземпляра, когда он есть (сегодня — первая проверка теста, около 3273); первая проверка остаётся только когда `assertion_id` нет. (3) Хартия критика кода и карточка команд пробы: «проба доказывает только ту проверку, которую испортила; Then, чья проверка при переворачивании проходит (элемент исчезает сам), возвращается `unverified` с причиной» — опыт уже в хартии, добавить первую половину в пределах шрапнели.
- Тесты: строка манифеста с номером пустой строки → отказ с названной строкой; проба без `--at` при `assertion_id` → `target.is_assertion_id: true`; тест без `assertion_id` → первая проверка, как сейчас; фикстура из живого файла `add_to_cart.spec.ts` (строки 43–47).

**Разбор (11.11.2026).** Производитель `assertion_id` — рука автоматора: ни один скрипт поле не пишет, автоматор переписывает его в строку манифеста из формы, которую печатает `manifest_from_tests.py` (она печатает `assertion_ref` — `файл:первая-последняя` строка выражения проверки). Сдвиг на одну строку — ручное копирование начала диапазона на соседнюю пустую строку (46 при Then на 47). Пункты: 1 — сделано (отказ записи на строке без проверки, `20394c2bf` на ветке `tr/tr2-1`); 2 — снят спекой t-2064 (проба без `--at` теперь обходит каждую проверку); 3 — перенесён в узел P7 той же спеки.

### TR2-2. Повтор пробы с другой целью, слово человека и мелкие остатки ревью проб

- `already_probed` сравнивает байты И цель: проба другой строки тех же байт разрешена; запись экземпляра хранит пробы по цели, новая не затирает доказанную старую. Где: `scripts/probe_by_code.py` (проверка повтора, запись `work/probes/`), `scripts/window_record.py` (`_probe_from_receipt`).
- Слово человека о пробеле проб, записанное до текущей ревизии окна, не читается этим окном и не печатается как вейвер: читатель `waiver.split_overridden` сравнивает ревизию (AR-24).
- `proved_by` в `window_record.probe_gap_block` — обязательный аргумент (правка 22 вызовов тестов); `judgment.facts_sha` — добавить читателя (сверка фактов при `--judge`) или убрать поле; три локальных `cut` свести к общему, `judge_detector` (88 строк) разделить; третий текст двери контроллера (`gate_preflight`, строки `probe gap` в `references/conductor-actions.json`) привести к тексту первых двух.
- Тесты: на каждый пункт по одному, плюс отрицательный контроль для `already_probed` (та же цель, те же байты → отказ как сейчас).
