## Что именно менять

### TR1-4. Дорожка с нечитаемой учёткой не уходит на старую дорогу и не останавливает прогон

- Где: `scripts/story_run.py` — `Driver.walk_actors` (3365–3393), вызывающее место (3340–3362: печать «walked on the recorder, as before», пометка `walk_old_road`); `scripts/manual_capture.py` — `auto_actor` (851–889: для `env` с одним ключом бросает `ValueError`); читатель медиан `walk_timing`.
- Поведение: (1) учётка `env:<ключ>` из одной части ищет пару в записях стенда (`credentials_by_role`, тот же читатель, что у `--as`): нашлась единственная роль с этим ключом логина — берётся она; (2) пары нет — дорожка НЕ идёт по старой дороге: каждый её кейс получает исход «не пройден» с причиной в словах стори («для учётки кейса фабрика не знает пароль: названа одним ключом <ключ>»), находка записана, прогон идёт дальше к следующей дорожке без вопроса человеку; причина попадает в отчёт под своим именем (AR-27). (3) Старая дорога остаётся только для случая «сессия ходока не открылась по причине окружения» и её кейсы видны читателю времени: `walk_timing` читает `walk_old_road` и не включает их в медианы. (4) Кейс, который ни разу не был пройден, назван в записи «не пройден: <причина>», а не «запись отказана» (замечание N11 ревью t-2018).
- Тесты: кейс с `env:USER_EMAIL` при роли стенда с парой ключей → сессия открыта; тот же без пары → два кейса «не пройден», причина названа, следующей дорожке сессия открыта, вопроса `halt` нет; `walk_timing` на прогоне со старой дорогой не считает её пункты.

### TR1-5. Отказ входа — быстрый и с дверью, которая открывается

- Где: `scripts/manual_capture.py` — `sign_in` (2694–2735), `await_landing` (2436–2469), обычная сессия `ui` (2941–2957), `_account_steps_gate` (3174–3196, читает последнюю попытку: 3120–3122), `remedy_no_revision` / `remedy_no_probe_door` (1286, 1314); `scripts/manual_evidence.py` — отказ `write_unprepared` в `write_block`; `scripts/tests/fixtures/judgment-census.json` (строки `build_record`, `rejudge_record`, `main`).
- Поведение: (1) перед запуском браузера код читает, есть ли у стенда доказательство входа для этого актора; нет доказательства и в шагах нет `fill-account` — отказ сразу, без ожидания страницы, с дверью «начни шаги с `fill-account`». (2) Три ожидания входа делят ОДИН срок (сегодня у каждого свой). (3) Замок входа смотрит на все попытки кейса с тем же актором, а не на последнюю. (4) Отказ `write_unprepared` называет дверь, отличную от отказавшей команды. (5) У двух подсказок причина принадлежит фабрике (`owner: factory`). (6) Строки переписи названы ролью, которой они служат.
- Тесты: вызов без `fill-account` на стенде без доказательства → отказ быстрее 2 с на подставном backend; три ожидания на медленной странице укладываются в один срок; замок: попытка a1 отказана аккаунтом, a2 прошла, a3 не заперта; текст отказа `write_unprepared` не содержит отказавшей команды.

Свидетель: `experiments/mybooks/thinking-roles/runs/walk-r2.log` строки 86–120; `experiments/mybooks/thinking-roles/walker-call-overhead.md`; сверка с кодом — отчёт скаута 06.11.2026.
