# Черновик непривязанного наблюдения не называет своё наблюдение: у соединения нет поля в контракте роли

id: — | кучка: `thinking-roles` | от: ревью критика TR1-11 `docs/tasks/specs/reviews/t-2306-tr1-11-critic.md` (B2, пункт 2); раунд правки t-2299 | приоритет: П2 | кандидат наверх: нет

Тип: пробел носителя. Решение владельца нужно: нет. Очередь: после слияния TR1-11.

Класс: соединению нужно поле, которого контракт роли не даёт (AR-22: у читаемого поля нет писателя; AR-10: требование не доходит до роли до работы).

## Что наблюдалось

- Место по наблюдению `obs-<диспатч>-<индекс>` без закреплённого кейса находится (`place_answers.places`), но ни один черновик к нему не присоединяется: `place_of_draft` сопоставляет `case` черновика только с `case` цели.
- Первая версия TR1-11 присоединяла черновик, если его `case` равен id наблюдения. Критик показал, что это догадка: по контракту черновика `case` — id кейса (`references/artifact-contract-run.md`, пример `"case": "TC-004"`), аналитик не получает указания писать туда id места, а значение `obs-...` в `case` выбрасывает черновик с дашборда и из трассировки (`C.case_ids('obs-S6-qa-runner-4-0')` даёт `[]`). Догадка откачена, соединение осталось прежним: такой черновик получает собственное место `draft-<файл>`, ничего не теряется молча.

## Что именно менять

### Узел. Необязательное поле черновика с id наблюдения

- Контракт черновика (`references/artifact-contract-run.md`, раздел полей черновика) получает одно необязательное поле `observation` — id наблюдения (`obs-...`), к которому относится черновик; заполняется, когда у наблюдения нет закреплённого кейса. Пишет роль (аналитик), читает один читатель — `scripts/place_answers.py::place_of_draft`; проверка формы поля — по `place_id_pattern` из `references/place-answers.json`.
- Срез контракта для аналитика (то, что роль видит до работы) называет поле и когда его писать; текст хартии правит узел TR2-13, этот узел даёт ему фразу. Срез `references/slices/qa-failure-analyst/artifact-contract-run.md` СГЕНЕРИРОВАН (`scripts/contract_slices.py`, строка 25) и руками не правится: после правки `references/artifact-contract-run.md` срез пересобирается командой `python -B scripts/contract_slices.py --write` (из каталога пакета) и коммитится вместе с контрактом.
- `place_of_draft`: правило между кейсом и `violates` — если `observation` непусто и равно id одной из целей — место этой цели. Поле `case` как id цели не читается никогда.
- `validate_artifacts.py` НЕ меняется: он проверяет только оформленные баги в markdown (`check_bug_filing_header`, `check_bug_form`), форму JSON-черновика он не проверяет, и новый валидатор черновика не пишется. Пустая строка и не-строка в `observation` читаются как отсутствие поля в самом `place_of_draft` (тест (г)).
- Тесты в `scripts/tests/test_place_answers.py`: (а) черновик с `observation: obs-S6-qa-runner-4-0` на `fixture_story()` присоединяется к месту наблюдения, `places` показывает у места источник `draft`; (б) тот же черновик с чужим `observation` остаётся на своём месте `draft-<файл>`; (в) черновик с `case: obs-...` и без `observation` остаётся на `draft-<файл>` (откат догадки закреплён); (г) пустое поле читается как отсутствие.

Принципы и правила: P27, AR-10, AR-22, FR-38.
