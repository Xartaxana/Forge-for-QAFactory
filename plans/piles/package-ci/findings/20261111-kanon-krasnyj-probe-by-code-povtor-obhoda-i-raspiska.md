## Что не так / что сделать

Что не так: в `scripts/tests/test_probe_by_code.py` после починки t-035 остаются шесть красных проверок (756/762), у них три причины в `scripts/probe_by_code.py`:

1. «pinned invert: its notes» — в записи вторая заметка `work/sensitivity-receipts/<имя>.json already holds this proof`. Обход `_walk_plan` вызывает локальную `publish()` несколько раз за один обход (около :6457, :6530, :6549); каждая публикация идёт через `_aggregate_record` → `attach_receipt` (:6913) → `write_receipt` (:4076), и второй вызов дописывает заметку «already holds». Расписка одного доказательства пишется несколько раз за прогон.
2. «pinned invert: the written record's key set» — агрегат несёт два ключа, которых нет в `INVERT_RECORD_KEYS` теста (:2303): `judgment_owed` и `walk_ended`.
3. «pinned answer: exit 0, the walk answers with the aggregate again», «pinned answer: the key set is the aggregate's», «a corrupt record: … the probe runs again», «an incomplete record does not answer a repeat» — повторный запуск отвечает `already_probed` и не запускает пробу там, где тест ждёт новый прогон (`intended_failure`, 2 запуска). Комментарий в тесте около :2334 сам спрашивает, остаётся ли `already_probed` для повтора обхода.

Что сделать (направление выбрано, Lead 11.11.2026):

1. Заметка «already holds this proof» появляется только при ПОВТОРНОМ запуске пробы (так ждёт проверка около :1378), а не при второй публикации внутри одного обхода: `attach_receipt` на пути обхода пишет расписку один раз за обход — при последней публикации, либо `publish()` не добавляет заметку, когда файл расписки создан этим же процессом. Тест: существующие «pinned invert: its notes» и проверка повтора :1374-1379 зелёные.
2. `judgment_owed` и `walk_ended` добавить в `INVERT_RECORD_KEYS`, если оба ключа читает хотя бы один читатель (AR-22: у каждого поля есть читатель) — назвать читателя в отчёте; ключ без читателя убрать из записи.
3. Развилка для дизайнера узла, с рекомендацией: испорченная или неполная запись НЕ отвечает на повтор — проба идёт заново (как ждут тесты; FR-59: гейт не решает по неизвестному); целая запись отвечает `already_probed`.
