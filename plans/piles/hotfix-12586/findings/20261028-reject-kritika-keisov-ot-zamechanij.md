# Критик кейсов ставит `reject` от одних замечаний при нуле `fail`: гейт A не записывается без слова человека

id: — | кучка: `hotfix-12586` | от: прогон TP1-12586 на 0.10.3 (`factory-backlog.md` FB-6; `work/preflight-a.txt`; раунд 3 `work/test-cases/integrations/critic-findings.md`: 0 `fail`, 3 замечания измерений 3, 6, 8, заявлено `reject`; карта t-1468 P3); слово владельца 28.10.2026 | приоритет: П2 | кандидат наверх: нет

## Слово владельца

28.10.2026, дословно: «Если замечания не критические, то они передаются дальше, автоматизатор их учитывает при автоматизации кейсов.»

## Что наблюдалось

`agents/qa-case-critic.md:72-77`: `reject — any fail or ≥3 concern`; `critic_rollcall.scoped_verdict` (`:244-321`) сохраняет заявленный `reject` над одобряющими ячейками (FR-35). После 2 раундов `reject` из одних замечаний без `fail` блокирует запись гейта A без слова человека — код решает за находку, которой нет (FR-4, AR-28).

## Решение

Вариант (A) спеки t-1469 F-6: `reject` критика кейсов — только при `fail`; замечания измерений без `fail` дают `approve_with_concerns` на любом раунде, гейт A слова человека не требует. Замечания НЕ теряются: идут дальше в бриф автоматора S5 (тот же носитель, что читает автоматор по кейсу), автоматор учитывает их; гейт A печатает их строкой «concerns carried to automation». Инвариант: кейс с `fail` никогда не одобряется.

## Узел

`hotfix-12586/4` HF4-11 (спека t-1469 §5.6 с поправкой §11): `agents/qa-case-critic.md` (шаг 4), `scripts/critic_rollcall.py` (`scoped_verdict`, при нужде), перенос замечаний в бриф окна S5. Ключ стыка: раунд 3 стенда → `approve_with_concerns` → замечания видны в брифе окна S5 по своему кейсу. Живое доказательство FR-33 — строка пачки.
