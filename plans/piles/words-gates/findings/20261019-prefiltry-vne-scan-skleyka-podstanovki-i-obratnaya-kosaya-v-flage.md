# Четыре дыры `main` вне токенизатора: гард читает подстроку, а не слово оболочки (склейка подстановки, `--p\re`, `find -exec`, метка хоста)

id: — | кучка: `words-gates` | от: Lead пачки (ревью t-979, t-983 к спеке t-976), 19.10.2026 | приоритет: П1 | кандидат наверх: нет

Что не так / что сделать: четыре дыры одного класса — гард решает по подстроке команды или по метке хоста, а не по слову, которое
читает исполняющая оболочка. Все четыре открыты на `main` (проба критика на дереве `main`, не на правке CX1-19), и ни одну нельзя
закрыть правкой `_scan`: читатели (`hooklib._first_form`, `stage_guard._delivery_in_text`/`_shell_segments`/`_slices`,
`host_adapter._read_refusal`, `guard_pre_tool.runs_check`) вне владения узла CX1-19. Закрывает их узел **CX1-20** («один обходчик
команды для R1–R4»).

- (1) **Склейка слова подстановкой.** Префильтры берут подстроку команды с вырезанными кавычками и экранами
  (`hooklib.py:525` `_STRIPPED_CHARS`, `stage_guard.py:930` `squeezed` в `_delivery_in_text`, `stage_guard.py:1509` `RUNNER_HINTS`
  в `check_command`) и ищут в ней слово формы целиком, а подстановка внутри слова их разрывает. Проба: R1 `py$(true)test -q` →
  `direct_test_form` = `None`, bash запускает `pytest`; R4 `python C:/p/run_sui$(true)te.py --task X` → проход (строка не содержит
  `run_suite.py`, `check_command` до `rule_typed_runner` не доходит), bash запускает раннер. Бэктик-близнец: `` `true` pytest -q `` →
  `None`. Лечится не префильтром, а чтением слова обходчиком (CX1-20): слово с неразвёрнутой подстановкой — возможная программа.
- (2) **Обратная косая внутри флага `--pre` у ripgrep (R5).** `host_adapter._READ_PROGRAM_FLAGS` (`host_adapter.py:418`) сверяет
  СЫРОЕ слово `--pre`/`--pre-glob` (`host_adapter.py:456`), а bash уберёт обратную косую: `rg --p\re python x f.json` и
  `rg --pre\=python x f.json` → `_read_refusal` = `''` (проход), хотя ripgrep получает `--pre python` / `--pre=python` и запускает
  `python` над каждым файлом. Контроль той же формы: `rg --pre python x f.json` → отказ. Лечится сравнением слова ПОСЛЕ снятия
  экранов оболочки (то же слово, что читает оболочка), не списком написаний.
- (3) **Читатель, который сам запускает программу: `find … -exec`.** Исключение «голова — читатель» (`rg`, `cat`, `find`…) держится
  на том, что читатель только читает; `find . -name x -exec python C:/p/run_suite.py --task X {} +` → R4 проход на `main`
  (голова `find`, срез освобождён). Сиблинг правила `--pre` из пункта (2): нужна одна таблица «читатель запускает программу»
  (`-exec`, `-execdir`, `-ok`, `xargs`, `--pre`) и срез с такой формой не освобождается головой-читателем.
- (4) **Метка хоста: PowerShell-команды Codex приходят как `Bash`.** `host_adapter.normalize` (`host_adapter.py:189-193`) ставит
  `tool_name: "Bash"` любой команде `exec_command`/`shell_command`, поэтому читатели без запрета — R1 (`runs_check` →
  `direct_test_form`) и R3 (`_is_commit_shape`) — читают текст в диалекте bash, а исполняет его PowerShell. Проба критика (t-983,
  NB-1), `main` читает правильно именно потому, что `_scan` режет на `;`, `|`, `&` и переводе строки ПОСЛЕ обратной косой: R1
  `cd C:\proj\` LF `pytest -q` → `pytest` (блок), R1 `dir C:\p\;pytest -q` и `dir C:\p\|pytest -q` → `pytest`, R3 `git status
  C:\p\` LF `git commit -m x tests/test_a.py` → коммит виден. Правило «обратная косая перед `; | &` и концом строки остаётся
  разрезом» стоит в CX1-19 именно из-за этого; полное лечение — читатели без запрета читают ОБА диалекта (как R2 и R4), либо
  метка хоста сообщает диалект. **Строки B-1 (критик t-1000, слово Lead §L-4):** то же верно для обратной косой перед
  `(`, `)`, `"`, `'`, бэктиком и пробелом — склейка bash-правилом прячет от R1/R3 команду, которую запускает PowerShell
  (измерено на pwsh 7.6.7 и 5.1). Склейка оставлена в CX1-20 (читатель обоих диалектов), в CX1-19 остались только `\$` и `\\`;
  пины CX1-19 держат отказ R1/R3 на `main` и на ветке: R1 `Get-Content C:\p\"a b.txt"; pytest -q; echo "done"` (пока склейка
  `\"` сдвигала чётность кавычек bash, `;` оказывался «внутри» кавычек; то же с `\'`), R1 `dir C:\p\(pytest -q)` (подвыражение
  PowerShell), R1 ``.venv\Scripts\`pytest -q`` (PowerShell: `` `p `` = `p`, относительный путь запускается), R1 `dir C:\p\ #it's`
  LF `pytest -q; echo 'x'` (`#…` — комментарий PowerShell, склейка `\ ` превращала его в слова, а `'` прятал следующую строку),
  и их коммит-близнецы R3 (`git status C:\p\"a b"; git commit -m x qa-factory/a.py; echo "d"`, `dir C:\p\(git commit …)`).
  Тест: `scripts/tests/test_hooklib_scan.py`, ряды «B-1: …» и `part_readers_keep_the_launch_in_view`. Когда CX1-20 вернёт
  склейку, эти ряды остаются пинами: команда PowerShell под меткой `Bash` обязана оставаться отказом.
