Что не так / что сделать: **Версия сборки на стенде: не блокер, а вопрос; реестр способов на стенд.** Владелец 02.10: «автоматизация на uitest не должна блокироваться — неизвестно, как в проектах ставятся обновления на стенд, фабрика не ограничивается одним путём. Попробовала как может — не смогла определить версию — спросила: вот так не смогла, скажите как определить, или будете каждый раз подтверждать сами?» Сегодня: `runtime_probe.py:283` знает один путь (`/usr/share/nginx/html/build-sha.txt`, заточено под один проект), рецепт требует править Dockerfile, `run_suite.probe_runtime :628-632` и `execution_request :74` требуют `matched` → автоматизация `env_blocked` (код решает за человека, P1/P13). Сделать: (1) **реестр** — один файл на все стенды, в переносимой части (`qa-factory/records/stand-identity.json`): стенд × сборка (сервис/UI/API — что есть у проекта, по данным профилей) → способ (`oci_label` с именем метки / `build_sha_file` с путём / `command` / `sources` / `person_confirms`: «буду смотреть сам»), кем и когда записан, слова человека; (2) **лестница** пробы: способ из реестра → OCI-метка `org.opencontainers.image.revision` (`docker image inspect`) → файл sha по пути из конфига → исходники в контейнере → не вышло — **вопрос человеку** с тремя ответами: «вот как определить (команда/метка/файл) — записываю для стенда», «я проверил, на этой задаче стоит нужная сборка — верю, на других задачах спрошу снова», «на этом стенде всегда подтверждаю сам — записываю, больше не пытаюсь определять»; фабрика называет файл: «принято, записала решение для стенда preview в `…/stand-identity.json`»; (3) автоматизация и ручной блок идут по слову человека с идентичностью `person-confirmed:<дата>` в отчёте, не `env_blocked`; обе половины по одному правилу; `mismatched` (способ сработал, sha другой) — тоже сообщение человеку, не молчаливая остановка (владелец 02.10): «на стенде сборка X, в MR — Y: передеплойте и скажите, когда (проверю снова) / тестировать то, что стоит — запишу для этой задачи / стоп»; (4) критик t-295 F1/F3: гейт A готовит пробу и для профилей ручной проверки / контейнеров без исходников; `remedy` пробы не теряется; (5) для нашего стенда метод записан: compose `testproject1-dev-fresh/docker-compose.yaml` ставит метку `org.opencontainers.image.revision=${UI_GIT_SHA}` на образ `testproject1-ui-static` (сделано 02.10 11:10, образ пересобран), реестр записывает `oci_label` для uitest.
