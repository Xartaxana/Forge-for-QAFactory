Что не так / что сделать: 26.10 владелец увидела, что UI стенда не грузится (`http://localhost:5173/api/v1/user` падает), и
решила, что UI «опять смотрит не на тот бекенд» (так уже чинили несколько раз, RUNBOOK §1, правка `VITE_DEV_PROXY_TARGET`).
На деле прокси UI был исправен: nginx на 5173 отдавал 502, потому что бэкенд на 8080 не отвечал вовсе. Бэкенд стартовал
раньше базы (контейнер `testproject1` в 10:16 UTC, postgres — в 10:31), запуск приложения упал (`sqlalchemy … raw_connection` →
`Application startup failed. Exiting.`), а процесс-перезагрузчик uvicorn остался жив — `docker ps` показывал «Up 5 hours»,
порт 8080 не слушал никто. Лечение — перезапуск бэкенда (`docker restart testproject1-dev-010-testproject1-1`, ответил через 50 с; три
пробы RUNBOOK §1 — 200 / 200 / 401).

Класс фабрики (не правило проекта): проверка стенда `stand_health.probe` (`scripts/stand_health.py:489`) опрашивает каждый
адрес из конфига отдельно и не связывает их. Поэтому (а) корень фронтенда засчитывается живым, даже когда его прокси к API
мёртв (RUNBOOK §1: «один curl на 5173 не годится — Vite/nginx отдаёт html-оболочку даже со сломанным прокси»); (б) мёртвый
бэкенд и сломанный прокси фронтенда дают человеку одинаковый симптом, а фраза проверки не говорит, какая часть мертва и
что из этого следует. Человек и роль чинят не то (здесь — прокси UI, в третий-четвёртый раз).

Что сделать (решает спека дизайнера): (1) проба фронтенда идёт не только в корень, но и через его путь к API (какой путь —
данные проекта, `environment`-блок конфига, FR-13/AR-1/AR-3; у Test Project 1 это `/api/v1/config` → 200, `/api/v1/user` → 401);
(2) когда фронтенд отвечает, а его API нет, фраза называет причину по порядку зависимостей: бэкенд сам не отвечает →
«мёртв бэкенд, фронтенд ни при чём»; бэкенд отвечает, а через фронтенд нет → «сломан прокси фронтенда»; (3) лекарство
фабрика не знает (docker, compose, k8s — разнообразие проектов, P2): фраза называет мёртвую часть и, если проект записал
рецепт перезапуска в конфиге, показывает его; иначе — вопрос человеку по `human-questions.md` (FR-6, P9). Один узел с
B-163 (`findings/B-163-stend-konteyner-ui-delit-set-s.md`): там обратный случай того же класса — бэкенд жив, прокси
UI мёртв после перезапуска бэкенда; обе ветки — одна проверка.
