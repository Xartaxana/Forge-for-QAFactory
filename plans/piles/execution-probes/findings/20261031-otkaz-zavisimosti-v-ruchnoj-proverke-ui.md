# Ручная проверка `ui` не умеет «отказ зависимости»: падение запроса страницы (500, таймаут) нельзя проверить

Слово владельца 31.10.2026 (бриф, W3): «подумай, что надо сделать, чтобы фабрика сама нашла все эти 3 бага» — владелец, 31.10.2026.

## Что наблюдалось

Баги Б-2 и Б-4 (свод `experiments/mybooks/cart-1-run-problems.md`, раздел 1; проверены Lead на стенде, `MyBooks` `a25b080`):
- Б-2: `GET /api/books/{id}` отвечает 500 — вся страница корзины «Something went wrong. Please try again», корзины нет; ответы не
  проверяются на `ok` (`CartPage.tsx:30-38`). Lead воспроизвёл подменой маршрута в браузере.
- Б-4: `POST /api/cart/merge` → 500 при входе — вход проходит молча, гостевая корзина пропадает (`LoginPage.tsx:36-39`).

Оба дефекта — «зависимость отказала, а страница не сказала человеку» — проверяются одним действием: подменить ответ запроса по шаблону
URL и посмотреть страницу. У ручной проверки `ui` такого шага нет: грамматика (`references/manual-capture-steps.json`, `steps`) знает
`goto`, `click`, `fill`, `fill-account`, `drag`, `wait`, `read`, `capture`; обработчик — `scripts/manual_capture.py`, `_run_step`. Агент, даже
решивший проверить отказ, не может его создать, а тест на Playwright требует отдельной работы автоматора, о которой кейс не говорит.

## Класс

Вся проверка идёт по «счастливому» пути зависимостей: отказ сервиса, от которого зависит страница, фабрика создавать не умеет, поэтому
класс дефектов «сбой зависимости на пути пользователя не виден человеку» (находка `grounding` Н-3 выводит под него требование; этот
узел даёт руки) не проверяется на любом проекте с веб-интерфейсом (P2; AR-1, AR-7).

## Что именно менять

Направление выбрано (бриф, Н-5): шаг, подменяющий ответ запроса по шаблону URL.

1. **`references/manual-capture-steps.json` + `scripts/manual_capture.py` (`_run_step`, браузерный бэкенд рядом с `goto`/`click`).** Новое
   слово шага `fail_request <url_glob> <status|timeout>` (имя — из брифа Lead; соседний шаг `fill-account` пишется через дефис, так что
   имя `fail_request`/`fail-request` сверяет дизайнер со спекой — на поведение не влияет): на странице сессии регистрируется
   `page.route(url_glob, handler)`; `status` — целое 100–599 (500, 404): обработчик отвечает этим статусом и пустым телом
   `{}` (`route.fulfill`); `timeout` — обработчик не отвечает (`route.abort("timedout")`) либо держит запрос дольше лимита шага. Подмена
   действует до конца сессии или до слова `restore_request <url_glob>` (второе слово — снять подмену; без него следующая проверка той же
   сессии получила бы чужой отказ). Шаблон URL — только на хостах стенда из `environments[]` (тот же отбор, что у `goto`: чужой хост —
   отказ с дверью, FR-1; подмена не должна ходить наружу).
2. **Запись.** Каждый перехваченный запрос — строка в `steps.jsonl` и в текстовом файле `fail-request-<glob>`: метод, URL, подмена; число
   перехватов за сессию. Подмена, не перехватившая ни одного запроса к концу шага `capture post_action`, — строка предупреждения в записи
   (шаблон не совпал: проверка иначе молча прошла бы на страницах без отказа, FR-41).
3. **`agents/qa-runner.md`** — одна строка про шаг и про то, что оракул отказа — «страница жива, человек узнал об ошибке, данные не потеряны
   молча» (читает роль, не код: P1, P17).

Тесты (по одному на пункт):
- `scripts/tests/test_manual_capture*.py` (имя уточнить по коду): фикстура-страница с `fetch('/api/x')`; `fail_request '**/api/x' 500` →
  страница получает 500, запись содержит перехват; `timeout` — запрос не завершается, шаг не виснет дольше лимита;
- `status` 99 и 600, слово без второго аргумента — отказ с формой; чужой хост в шаблоне — отказ;
- подмена без перехвата → предупреждение в записи; `restore_request` снимает подмену (следующий запрос идёт).
