# UI-тесты пробуются под профилем `api`: у двух профилей один корень тестов, селектор молча берёт первый, а закрытие окна не читает слово человека

id: — | кучка: `execution-probes` | от: владелец, 22.10.2026 (S5 TP1-12586 на `testproject1-dev-010`, 0.10.0) | приоритет: П1 | кандидат наверх: нет

перенос: hotfix-12586/batch-1 (узел HF1-3; слово владельца 23.10.2026 — срочная отдельная пачка; узел EP1-10 здесь закрывается её хэшем)

Что не так: три UI-теста TC-007 (`tests/ui/...`) пробы чувствительности запустили под профилем `api`; у него нет сопоставления id
`<test>[chromium]`, отчёт называет тесты `<test>[chromium]`, все три пробы — `not_executed` («0 report rows are named …»), окно критика
`S5-qa-code-critic-4` пишет «probe is missing for a new_or_changed instance» и не закрывается. Слово человека принять пробы без квитанций
записано, но проверка закрытия окна (`window_record`) его не читает — S5 встал. Дирижёр записал это в бэклог проекта как FB-9.

Причина (измерено по `qa-factory/config.json` проекта): у профилей `api` и `ui` один и тот же `roots.test: testproject1_test_harness/tests`
(онбординг записал общий корень; UI-тесты лежат в `testproject1_test_harness/tests/ui`). Селектор `execution_request._profile_for`
(строки ~1209-1240; его же зовёт `probe_by_code._profile_of`) ищет самый длинный подходящий корень и при РАВНОЙ длине оставляет первый
профиль списка — `api`. Ничья не названа и не отказана. Рядом: в `argv` обоих профилей стоит `-v`, хотя `pytest.ini` проекта уже несёт
`addopts = -v` (FB-7 — удвоенная многословность; `node_ids` её компенсирует, но онбординг не должен её вносить).

Почему это дефект: FR-59 / AR-28 (неизвестное — какой профиль — решено молча «первым», а не названо), AR-1 / AR-3 (факт проекта «UI-тесты в
`tests/ui`, профиль `ui`» должен жить в конфиге, онбординг записал его неверно), FR-4 / P13 и GW1-14 (слово человека на гейте закрытия
окна не действует — у состояния нет двери).

Что сделать: (1) онбординг различает корни профилей (`ui` → `testproject1_test_harness/tests/ui` или маркер/селектор профиля) и не дублирует в
`argv` флаги, которые уже в `addopts`; (2) `_profile_for` при равных корнях нескольких профилей не берёт первый: селектор профиля по
маркерам/пути внутри корня или отказ «эти файлы подходят под api и ui — уточни профиль» (тот же текст для `probe_by_code`, FR-17);
(3) `window_record`: недостающая проба с записанным словом человека — пробел в отчёт, а не непроходимая строка (связь с GW1-14);
(4) тест: два профиля с общим корнем → отказ или выбор по селектору, не первый; UI-файл под `tests/ui` → профиль `ui`; (5) свип: другие
места, выбирающие профиль по пути (`gate_preflight` «один тест на профиль», `execution_scheduler`).

Свидетель: сообщения дирижёра 22.10 (~20:02: «the factory runs the check on a UI test under its `api` profile … None of those lines offers a
way to pass the gap on your word»); `qa-factory/factory-backlog.md` FB-7, FB-9; `qa-factory/config.json` `profiles[api|ui].roots.test`;
`scripts/execution_request.py:1209-1240`; `scripts/probe_by_code.py:1153-1162`.

Принципы и правила: P13, FR-4, FR-17, FR-59, AR-1, AR-3, AR-28.

Решение владельца нужно: нет.
