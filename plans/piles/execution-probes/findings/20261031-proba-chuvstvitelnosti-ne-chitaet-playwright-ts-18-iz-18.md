## Класс

Проба чувствительности привязана к устройству python-харнесса: для другого языка/раннера она отказывает целиком вместо того, чтобы
сделать хоть что-то (FR-59 — шлюз не решает по неизвестному: называет, чего не смог установить, и спрашивает того, кто знает, или берёт
объявленное безопасное умолчание; FR-47 — код зовётся ролью и сообщает о непредвиденном; P2; AR-1, AR-2, AR-28). Человеку отдан пробел, который
на 100 % предсказуем по языку, а не по тесту.

## Что именно менять

Направление выбрано: довести существующий путь пробы для TypeScript до рабочего (данные + сопоставление), а на остаток дать ОДИН вопрос на
историю вместо трёх на окна.

1. **Сопоставление заголовка теста с объявлением: `scripts/probe_by_code.py` (`_normalised_id`, `_tail_matches`, `_longer_title`,
   `declaration_candidates`) читает правила из `references/detectors.json`, запись языка (`typescript`) — поля данных, не код (AR-1):** (а) `title_tags`: слова-теги
   вида `@name` в начале заголовка не участвуют в сравнении (`@api @regression CART-1_TC_004 …` ≡ `CART-1_TC_004 …`); (б) `title_template`: шаблонная
   строка объявления (`` `…${expr}…` ``) превращается в образец, где каждое `${…}` = любая непустая подстрока; заголовок отчёта совпадает с образцом →
   найденное объявление одно на все экземпляры цикла; (в) объявление внутри цикла (`for`, `forEach`, `.map`) помечается `generated: true`: мутация оракула
   ставится ОДИН раз в теле, а вердикт выносится по всем экземплярам-строкам отчёта сразу (в `judge_detector` уже есть параметр `among` —
   судится «среди экземпляров»; убит только если упали все экземпляры, выжил — если упал не каждый, как у параметра плагина pytest, находка
   `hotfix-12586/findings/20261028-proba-ne-nahodit-test-s-parametrom-plagina.md`). Тест: фикстура `spec.ts` с `for (const p of cases) { test(\`@api CART-1_TC_004 x [${p.id}]\`, …) }`
   и junit с развёрнутыми именами → объявление найдено, мутация одна, вердикт по обоим экземплярам.
2. **Профиль `web` получает `selectors.verified` кодом, а не рукой роли:** место, где ставится отметка у профиля pytest (`scripts/onboarding_probe.py`
   — проба отчёта; точное место уточняет спека), пишет её и для профиля не-pytest, когда проба отчёта онбординга дала `proven` (она это состояние уже знает,
   `onboarding_probe.STATES`). Тест: фикстура профиля Playwright с доказанным отчётом → после записи конфига `run_shape_checks` не отказывает на (а).
3. **Формы `selector_args`/`report_test_id` строит код — это узел EP1-37** (склейка 5.2+5.3+5.6): без него этот узел закрывает только сопоставление;
   порядок: EP1-37 → EP1-36.
4. **Остаток, который не взять кодом, — один закрытый вопрос на историю, не на окно.** Если после п. 1–3 проба по-прежнему невозможна для языка
   (`Refusal` пробы по причине инструмента — нет записи языка, не найдено объявление), код вместо `unverified (tooling)` кладёт строку
   `probe_gap` с причиной `tooling: <язык/раннер>` и ставит ОДИН вопрос дирижёру через шов (AR-17): «Пробу «тест умеет падать» для <язык> фабрика не
   умеет. Принять все такие тесты без пробы — в этом прогоне / проверить вручную красной правкой / остановить. Цена: …» (форма `human-questions.md`, P9).
   Ответ — слово класса: действует на все окна истории, пока не изменился набор причин (то же правило, что «одно решение класса — на все экземпляры»:
   P5, D-0043; узел 3.3 кучки `gates-and-words` строит саму привязку слова к классу — этот пункт ею пользуется). Пока ответа нет — строка
   отчёта «не пробован: причина инструмента» (FR-41: неизвестное — не факт). Тест: два окна подряд с одной причиной — вопрос один.
5. **В отчёте** причина «tooling» не показывается как пробел продукта (FR-19; находка 6.5 в `report-delivery`).
