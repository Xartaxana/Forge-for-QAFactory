# Desktop и mobile: набор тестов фабрика запустит, но проверить стенд и проверить что-то руками агентом не может

id: — | кучка: `execution-probes` | от: Lead (Opus, деградированное окно), 31.10.2026, по слову владельца | приоритет: П1 | кандидат наверх: да

Вопрос владельца 31.10.2026: «Фабрика сейчас не может запускать тесты на десктоп и мобайл приложениях? Это баг первого
приоритета». Ниже ответ по коду. Живьём ничего не прогонялось.

**Что, судя по коду, есть.** Набор тестов запускается командой профиля проекта любого вида:
`profiles[].commands {kind, argv, cwd, scope}` (`references/templates/config.json:27`). Онбординг не навязывает проекту
набор web/API/mobile (`skills/qa-onboarding/SKILL.md:52-54`). Значит, набор на Appium, WinAppDriver, XCUITest или
Espresso, у которого есть команда запуска, S6 в принципе вызовет. **Но это не доказано:** фабрика ни разу не работала на
desktop- или mobile-проекте (FR-33). Что сломается по дороге — S5 при встраивании тестов, сбор результатов, гейты
доставки, — неизвестно.

**Чего нет совсем:**

1. **Готовность стенда — только web/API.** У `environment.access.kind` есть только варианты
   `harness_command | local_login | oidc_password | bearer_env | none`. Есть `frontend {url_key, api_path}`, а
   `login_probe` — это HTTP-проба (`references/templates/config.json:47`). Нет понятий «устройство или эмулятор»,
   «установленная сборка приложения», «версия ОС». Doctor и S0 не смогут сказать, готов ли стенд для такого проекта.
2. **Руки агента — только HTTP и браузер.** `manual_capture.py` умеет `http` и `ui`, а `ui` — это Playwright с headless
   chromium (`scripts/manual_capture.py:996-1017`). Для desktop и mobile агент не может:
   - проверить кейс сам (P19, ступень 3);
   - показать человеку «было / стало» (P20);
   - исследовать приложение — будущий `qa-explore`, кучка `exploratory`.
3. **Часть кода видит только Python и pytest.** `repo_map.py` читает имена только из Python-файлов. Маркер
   `manifest_from_tests.py` — это `@pytest.mark.qa`. Это соседний класс («один язык»), он касается и web-проектов на
   TypeScript. Рядом лежат EP1-25 и находка `20261029-forma-markera-qa-uznayotsya-iz-otkazov.md`.

Свидетель: grep `appium|mobile|desktop|winappdriver|pywinauto|xcuitest|espresso|detox|emulator|simulator` (без учёта
регистра) по `ai-packages/qa-factory` без `tests/`, `CHANGELOG.md`, `design/`, `evals/`. О приложениях под тестом он нашёл
только `UPGRADE.md:101` («no blanket browser/mobile install») и `skills/qa-onboarding/SKILL.md:53`. Остальные попадания —
про хост Codex Desktop (`INSTALL.md:26,43,60`, `skills/qa-story/SKILL.md:33`). Эти же попадания служат положительным
контролем: поиск работает.

Что сделать (направление выбрано Lead, узел EP1-41; спеку пишет дизайнер):

1. **Сначала опыт, потом механизм** (`CLAUDE.md`, гигиена команд, п. 6а). Взять два небольших открытых проекта со
   своими тестами: desktop (Electron или WinForms с WinAppDriver или Appium Windows) и mobile (Android на эмуляторе с
   Appium). Провести онбординг и одну стори на каждом и записать, что сломалось на каждой стадии. Только по этому списку
   определяются следующие узлы. Стенд под эмулятор и Windows-драйвер нужен владельцу: подготовить его — слово владельца.
2. **Честность до починки.** Онбординг и doctor на проекте, где нет web- или API-поверхности, говорят вслух: «проверки
   агента руками для этой поверхности не поддержаны, такие кейсы уйдут человеку (P19, ступень 4)». Сейчас фабрика молчит
   и обещает то, чего сделать не может (P22: «пообещала и не сделала»).
3. **Каналы — строками данных** (AR-1). Вид поверхности (web, api, cli, desktop, mobile) плюс команда-драйвер для
   готовности и для `manual_capture` записываются в данных, а не веткой кода на каждую платформу. Первый драйвер, по
   итогам опыта из п. 1, — вероятно Appium: он закрывает и Android/iOS, и Windows. Это оценка, не замер.

## Что взять из `Xartaxana/Darker-than-a-dark-test-factory` (совет владельца 31.10.2026; разведка t-1631, второй проход Lead)

Это фабрика, целиком построенная на Android-приложении. Стек: Appium 2 + UiAutomator2 + pytest + Allure + mitmproxy, Windows и
PowerShell. Брать механизмы, не текст: правила там написаны по-русски и под один проект — пакет `com.example.ao3_wrapper`,
пути `D:\AO3_tests\…`, имя AVD.

- **Руки агента — не MCP и не интерактивная Appium-сессия, а канонические команды adb.** Роль с Bash вызывает разрешённые
  формы: `adb shell uiautomator dump` (дерево экрана в XML), `adb exec-out screencap`, `adb logcat`, `am start -W`, а также
  обёртки стенда (`.claude/settings.json:58-100`, проверено Lead: строки 60, 62-63). Ложится на наш `manual_capture.py`
  каналом `adb` с теми же доказательствами и хэшами. MCP в их `.claude/` нет: grep `mcp` пуст, тот же каталог по `mcp|adb` даёт 28.
- **Готовность стенда — список именованных проверок с тремя исходами и причиной на каждой ветке** (`scripts/doctor.py:466-641`).
  «Ошибка инструмента» у них не равна «нет объекта»: `Get-Device` печатает `DEVICE: <serial>` или ровно `NO DEVICE`, чтобы пустой
  вывод голого `adb` никогда не читался как «устройства нет» (`scripts/tasks.ps1:1346-1358`, проверено Lead). Это наш FR-41 и п. 6
  гигиены команд.
- **Здоровье Appium в два слоя** (`scripts/tasks.ps1:926-985`, проверено Lead). Поверхностный — `GET /status`, `ready=true`.
  Глубокий — создать и удалить настоящую минимальную сессию: он ловит класс «сервер ready, а сессия падает». Глубокому слою нужно
  свободное устройство, поэтому к нему прилагаются аренда устройства и однозначная адресация: никогда не брать «первое в списке»
  (`scripts/doctor.py:89-138`).
- **Цепочка идентичности сборки.** Версия и sha256 APK записаны в `state/app-under-test.yaml` и сверяются с файлом и с тем, что
  реально установлено на устройстве (`pm path` + `sha256sum`, `dumpsys versionCode`; `scripts/doctor.py:305-463`). Для нас это
  проверка, что тестируется та сборка, о которой говорит стори.
- **Автоматические доказательства падения:** скриншот, page source XML, хвост logcat и текущий контекст
  (`framework/core/reporting.py:15-50`). Утилита дерева доступности — интерактивные узлы и перекрытие границ
  (`framework/core/a11y_tree.py`).
- **Возмущения для мобильных чартеров** (`exploratory-charters/PERTURBATIONS.md:81-95`): kill, home и поворот внутри операции,
  фон без смерти процесса, смена темы и шрифта, сеть replay/live/офлайн, серия быстрых повторов. Примитивы — в
  `framework/steps/app_steps.py:243-370` и `framework/core/adb.py:192-198`. Их честная пометка: поворот на AVD API 34 —
  блокер инструмента. Это вход пачки 2 кучки `exploratory`.

Десктопа там нет: grep `winappdriver|pywinauto|appium-windows|windows-driver|platformName.{0,10}windows` пуст, широкий поиск
`desktop` находит 3 нетехнических упоминания. Для desktop-проекта образец по-прежнему нужен отдельно.

Принципы и правила: P2, P19, P20, P22, FR-33, FR-36, FR-41, AR-1, AR-3.

Решение владельца нужно: да. Нужен стенд для опыта п. 1 (эмулятор Android, Windows-драйвер) и выбор двух проектов-образцов.
