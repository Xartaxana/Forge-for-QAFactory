## Что наблюдалось

- Красный или зелёный тест читается из отчёта прогона (`pytest`, `junit-xml`, `trx`) и от языка не зависит — здесь ошибки нет.
- Мутационная проба («тест умеет падать») портит проверку в тесте и должна отличить «упал, потому что испорченная проверка сработала» от «упал по посторонней причине». Сегодня это делается сравнением текста сообщения об ошибке с образцами — строки `references/detectors.json` (`assertion_probes`: языки `csharp`, `java`, `typescript`, пары `fires_as` на стиль проверки; Python — свой путь).
- На MyBooks у Playwright нашёлся вариант сообщения, которого не было в образцах (строка локатора без префикса после авторского сообщения). Проба записала `incomplete / tooling`, окно S5 отказало, человек принимал пробел словом (B-16), три теста остались «не доказаны». Починка t-1953 (узел N6) добавила вариант одной строкой данных — это лечит экземпляр, не класс.
- Класс: образцы сообщений всегда отстают от библиотек (новая версия, новая библиотека проверок, свой хелпер проекта). Каждый новый проект с незнакомым текстом приносит «не доказано» и вопрос человеку. Код при этом судит по закрытому списку формулировок то, что является суждением (P27, AR-29, FR-12).

## Что именно менять (направление выбрано; узел исполним как написан)

Порядок доказательства «упал от порчи» — три ступени, первая сработавшая решает:

1. **Свой маркер в сообщении испорченной проверки.** Когда проба переворачивает проверку, она добавляет к ней читаемое сообщение-маркер фабрики (одна строка с id экземпляра пробы), если форма проверки принимает сообщение. Способ «как прикрепить сообщение» — строка данных на язык и стиль проверки в `references/detectors.json` (AR-1, FR-13); где форма сообщения не принимает (строки данных нет) — ступень пропускается. Отказ, в тексте которого есть маркер этого экземпляра, — «сработала испорченная проверка», независимо от формулировок библиотеки.
   - Файлы: `scripts/probe_by_code.py` (`plan_detector_mutation` — вставка маркера; `_judge_detector_rows` — чтение маркера раньше `fires_as`), `references/detectors.json` (новое поле строки пары, с пустым исходом «нет формы сообщения»).
   - Тесты: на каждый язык из `assertion_probes` — маркер вставлен синтаксически верно (реальные образцы строк из фикстур), отказ с маркером даёт `intended_failure` при незнакомом тексте библиотеки; отказ без маркера на той же строке на эту ступень не опирается; маркер другого экземпляра не засчитывается.
2. **Место отказа.** Кадр стека отказа указывает на испорченную строку (кадры уже читаются из `trx` и `junit-xml`: `probe_by_code.py` около строки 2603). Совпадение файла и строки с местом мутации — «сработала испорченная проверка».
   - Тест: отказ с незнакомым текстом и кадром на строке мутации → `intended_failure`; кадр на другой строке → не засчитан.
3. **Суждение критика кода, не вопрос человеку.** Если ни маркер, ни место не решили, код НЕ пишет `incomplete / tooling` как повод для отказа окна и вопроса человеку. Он собирает факты пробы (что испорчено, файл и строка, сырой текст отказа, кадры, статус до и после) в запись и отдаёт её критику кода в его окне S5; критик решает «это отказ испорченной проверки / нет / не могу судить» и цитирует запись (свидетель). Код проверяет только, что вердикт ссылается на существующую запись (AR-29). Человеку вопрос уходит только при «не могу судить» — через дирижёра, с фактами.
   - Файлы: `scripts/probe_by_code.py` (исход `needs_judgment` вместо `incomplete/tooling` для этого случая), форма и контракт окна критика (`handoffs/`, `scripts/contract.py` — поле вердикта по пробе со ссылкой на запись), хартия `agents/qa-code-critic.md` (опыт: как читать запись пробы; в пределах шрапнели `references/role-load.json` — она только уменьшается, рост называется), `scripts/window_record.py` (окно не отказывает по пробе, у которой есть вердикт критика).
   - Тесты: запись `needs_judgment` + вердикт критика «intended» со ссылкой → окно закрывается без слова человека; вердикт без ссылки на запись → отказ формы; «не могу судить» → вопрос человеку с фактами; старые записи `incomplete/tooling` на диске читаются как раньше (временной край).

Не делать: новый закрытый список формулировок; чтение смысла сообщения кодом; отмену существующих строк `fires_as` (они остаются быстрым путём).
