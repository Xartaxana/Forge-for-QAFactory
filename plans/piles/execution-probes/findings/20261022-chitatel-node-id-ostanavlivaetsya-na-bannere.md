# Читатель node id останавливается на первой строке из `=`: проект печатает баннер до списка тестов — фабрика видит ноль тестов и отказывает каждому

id: — | кучка: `execution-probes` | от: владелец, 22.10.2026 (S5 TP1-12586 на `testproject1-dev-010`, 0.10.0) | приоритет: П1 | кандидат наверх: нет

перенос: hotfix-12586/batch-1 (узел HF1-1; слово владельца 23.10.2026 — срочная отдельная пачка; узел EP1-9 здесь закрывается её хэшем)

Что не так: `scripts/node_ids.py` `parse_collected` (строка ~185) читает вывод `pytest --collect-only -q` и делает `break` на первой строке,
начинающейся с `=` («stops at the first `====` section»). Тестовая настройка Test Project 1-харнесса печатает строку `====…` ДО списка id —
читатель останавливается раньше первого id и возвращает пустой список; проверка node id отказывает всем пяти тестам, хотя pytest собирает
их нормально (дирижёр проверил руками: `tests/integrations/test_integration_project_change.py::…` из `testproject1_test_harness`). Дирижёр
записал это в бэклог проекта как FB-8 и назвал настоящей причиной FB-6 и FB-7 (три строки бэклога проекта на один дефект фабрики) и
попросил у человека слово на запуск без проверки node id — для окон 1, 2 и 3.

Почему это дефект: вывод инструмента проекта — открытое разнообразие (баннеры плагинов, conftest, `-p` вывод), а читатель держит закрытое
допущение «до первой `=` — только id» (AR-1, AR-2, FR-13); AR-13: тот же вывод читает второй парсер — `gate_preflight.py`
`first_collected_node` (строка ~557) — со своими правилами, и гейт A с S5 могут разойтись в ответе; FR-59 / AR-28: «ноль id» при exit 0 и
строке `N tests collected` — неизвестное, принятое за ответ «тестов нет»; FR-19 / AR-27: ошибка фабрики снова в бэклоге проекта (как FB-3,
FB-5).

Что сделать: (1) `parse_collected` не обрывается на `=` до первого id: строка-разделитель пропускается, конец списка — секция ПОСЛЕ id
(или итоговая строка `N tests collected`); (2) один читатель вывода collect для всех: `first_collected_node` берёт первый id из
`parse_collected` (AR-13, одна функция — один ответ на гейте A и в S5); (3) сверка: 0 id при exit 0 и итоговой строке «N collected» с N > 0 —
не «нет тестов», а отказ читателя с первыми строками вывода (FR-59), который чинит фабрика, а не слово человека; (4) тест: вывод с баннером
`====` перед id → все id; вывод с итоговой секцией `==== warnings ====` после id → та же граница; вывод с N collected и нулём прочитанных →
отказ, не пустой список; (5) свип: другие читатели вывода раннера (`execution_scheduler.py`, `manifest_from_tests.py`, `red_sandbox.py`
через `node_ids`; собственные парсеры вывода pytest в `run_suite.py`, `gate_preflight.py`) — вердикт по каждому.

Свидетель: сообщение дирижёра владельцу 22.10 («the project's test setup prints a line of `====` characters before the test ids. The
factory's id reader stops at the first line that starts with `=` … I logged this as FB-8; it is the real cause behind FB-6 and FB-7»);
`testproject1-dev-010/testproject1-sdk/test-harness/qa-factory/factory-backlog.md` FB-6…FB-8; `scripts/node_ids.py:185-196`;
`scripts/gate_preflight.py:557`.
