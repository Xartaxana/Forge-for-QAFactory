  (`case_files_named`). **Причина не установлена:** это пустая папка (формулировка t-1632) или форма имени `CART-1_TC_005` против `TC_005` (форма ключа

  — зелёные). Проверка отвергла верный тест, и автор подчинил порядок кода проверки.

## Класс

(5.4) Читатель берёт кейсы из места, куда ни одна стадия не пишет, и отказ не называет, где искали (AR-22 — у каждого читаемого поля есть производитель; FR-1 — отказ
называет, чего ждал). Хэш обязательства, записанный ролью по собственной формуле, — «факт, который произвёл не тот, кто за него отвечает» (FR-16, AR-14).
(5.5) Посылка проверки («тест останавливается на первом падении») — свойство фреймворка, а зашита как факт всех тестов (AR-1: разнообразие — данными; FR-13).

## Что именно менять

1. **`scripts/s5_precheck.py`, `find_case_file`/`case_files_named` — один читатель кейсов, отказ с перечнем мест.** Не нашёл файл кейса — сообщение называет
   каждый просмотренный корень и форму искомого имени (`<case>.md`, область), а не «no case file with numbered Then clauses was found». Корни поиска берутся из
   того же читателя, что `contract.case_index` (не второй список мест, AR-13). После установки причины (см. выше): если дело в форме имени — `split_case_key`/`case_files_named`
   разворачивают `CART-1_TC_005` и `TC_005` одним правилом (форма id кейса — `config.case_id_form`, `case_forms`); если в пустой папке — S4 при закреплении версий
   (`case_versions.py --pin`) кладёт копии файлов кейсов в `work/test-cases/<area>/` (производитель появляется; тест: после закрепления `find_case_file` находит
   файл). Тест: фикстура с кейсом в одной из форм имени → найден; нет файла → отказ с перечнем корней.
2. **`obligation_hash` производит код.** Роль не пишет и не пересчитывает хэш: при `manifest_put.py` хэш обязательства строится кодом из текста Then кейса
   (читатель — тот же `find_case_file`), рукописное значение, не совпавшее с построенным, — отказ с построенным значением и дверью «не записывайте хэш, он
   ставится при отправке». Место производителя (`scripts/manifest_put.py` либо `scripts/contract.py`) уточняет спека: **не проверено**, где сегодня считается хэш и какая формула. Тест:
   строка без хэша получает его; строка с чужим — отказ.
3. **Мягкие проверки (5.5): `references/detectors.json` (данные), запись языка/фреймворка получает `soft_assert_patterns`** (для `typescript`: `expect.soft(`; для
   python: `pytest_check`, `assertpy.soft_assertions`, по реальным формам — список уточняет спека по записи данных проекта, без списка проекта, AR-1). `_own_red_order`:
   Then, чья проверка (диапазон строк, закреплённый на маркере) написана мягкой формой и стоит после красного, НЕ считается «never ran» — привязка `covered` принимается;
   в остальных случаях (жёсткая проверка, диапазон не закреплён, форма не опознана) — как сегодня (сомнение — находка: ошибка допустимого направления). Тест: две
   фикстуры теста с красным Then 2 и Then 3 после него — с `expect.soft` проверка проходит, с обычным `expect` даёт `red-own-behind-…`; незакреплённый диапазон — `red-own-order-unknown`.

Тесты (по одному на пункт): `scripts/tests/test_s5_precheck*.py` (п. 1, 3; имя уточнить по коду), `test_manifest_put*.py` (п. 2).
