# RH1-11, продолжение: отказ стража и заметка `host_capabilities` не называют условия `missing`; страж отказывает и в проверенной пробе другой сессии

Что не так: узел RH1-11 дал пробе хоста поле `missing` (id неудовлетворённых условий). Фиксированные тексты остались прежними (тот же класс FR-1):

- `stage_guard.py` ~1024: отказ пишет общий текст и не добавляет `probe["missing"]`; роль не видит, какого условия не хватает (след отказа — `dispatch-denials.jsonl`). Страж отказывает также проверенной пробе ДРУГОЙ сессии (`probe.get("session_id") != event.get("session_id")`), а `missing` это условие не называет, поэтому одного добавления `missing` мало: одна причина остаётся безымянной;
- `host_capabilities.py:87`: фиксированная заметка «evidence is incomplete»; полный dict `guard_probe` с `reason` и `missing` у неё есть.

Что сделать: когда проба не проверена — отказ добавляет id из `probe["missing"]` с фразой, что делать; когда сессия другая — отказ говорит это прямо и называет дверь (выполнить пробу в этой сессии); заметка `host_capabilities` добавляет хвост «Unmet» из `missing`. Узел-горячий файл: `stage_guard.py` идёт по очереди (пачка с зоной стража).

Края: `missing` пуст при непроверенной пробе → общий текст как сегодня плюс слово «причина не установлена» (не пропуск); несколько id — все, в порядке записи; id, которого нет в таблице текстов, печатается как есть.
