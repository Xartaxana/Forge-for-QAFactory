## Класс

Отвеченная граница спрашивается снова (FR-7), потому что слово привязано к тексту блока, а не к классу решения (P5, D-0043; AR-24). Не про TypeScript и
не про стенд — про любое повторяющееся решение: «принять без пробы», «идти без источника», «стенд той версии».

## Что именно менять (направление выбрано)

Зависит от GW1-1 (один читатель `stage_overrides`; иначе это третий читатель).

1. **Класс решения — данные, не код (FR-13, AR-1).** Новый файл `references/decision-classes.json`: закрытый список классов решения; у класса — `id`,
   список кодов отказа/вопросов, которые он закрывает, и признак «действует на всю историю» или «до сдвига HEAD». Стартовый набор — два класса из
   этого прогона: `probe_gap_accepted` (проба не читает язык теста) и `stand_version_confirmed` (версия стенда подтверждена; сдвиг HEAD —
   `voided.checkout`, он уже есть в `stand_identity`). Новый класс — строка данных, не правка кода.
2. **Запись слова с классом — `scripts/waiver.py`.** Запись `stage_overrides` получает необязательное поле `class`; `waiver.py` ставит его сам, когда
   отказ имеет код из `decision-classes.json` (человек слов о классе не пишет). Запись без класса работает как сегодня (прежнее поведение, ни одна
   старая запись не меняется; обратная совместимость).
3. **Чтение — в том же одном читателе, что делает GW1-1:** `split_overridden` принимает отказ, если у отказа есть код и есть живая запись
   (не `revoked_at`) того же класса на той же истории — на любой стадии класса, не только `stage`.
4. **Не спрашивать, а сообщить (FR-7):** там, где окно/стадия строит вопрос по тому же коду (`gate_preflight`, `story_run`: поиск по построителям
   вопросов с `s5_runtime_probe`, `vcs`, `probe gap`), сначала проверяется запись класса; есть — вопрос не задаётся, в отчёт идёт строка «Решение
   <дата>: <слова человека> применено к <кейс/окно>» (человек видит, что его слово сработало; отозвать можно, `waiver --revoke`, и класс снова
   спрашивается). Нет записи — вопрос один, и в его тексте сказано: «ответ действует на все такие случаи этой истории».
5. **Края.** Запись другой истории не действует (`task` в записи); отозванная — не действует; класс без кода отказа — слова привязаны по
   тексту, как сегодня; сдвиг HEAD для `stand_version_confirmed` — слово снимается (`voided.checkout`), вопрос задаётся один раз заново;
   два живых слова одного класса с разным решением — читается самое позднее, а не «список» (GW1-1 держит это правило).

Тесты (по одному на пункт; файлы: `test_waiver*.py` для 2–3, `test_gate_preflight*.py` для 4, имена проверить по коду):
- `split_overridden`: запись класса `probe_gap_accepted` на S5 окна 1 снимает такой же отказ окна 4 с другими id кейсов; запись без класса — нет;
- `waiver.py` ставит `class` по коду отказа; на отказ без кода — поле пусто;
- построитель вопроса: при живой записи класса вопрос не строится, строка отчёта называет слова и дату; после `--revoke` — вопрос строится;
- сдвиг HEAD снимает класс `stand_version_confirmed`.
Мутация: убрать чтение `class` в `split_overridden` — красит первый тест.
