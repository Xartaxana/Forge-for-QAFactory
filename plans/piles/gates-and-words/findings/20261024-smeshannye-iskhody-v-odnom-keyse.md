## Причины

1. **`greens` берётся по всему кейсу** (`scripts/s5_precheck.py`, `check_manifest`, ветка `partial-green`): строка `unresolved[]` с `partitions`
   и любой зелёный инстанс кейса → отказ; к какой партиции относится зелёный, не проверяется. Расщепление инстансов отказ не снимает: строка
   с партицией остаётся, и как только generic-инстанс станет `green`, отказ вернётся (сейчас он `pending_run`).
2. **У `contradicts_requirement` нет двери по инстансу/партиции**: ветка `reason == CONTRADICTS and not partitions` — любой зелёный кейса →
   `contradicts-but-green`. Дверь по `instance_ids` есть только у `blocked_by_env` (стенд).
3. **«Заблокировано упавшей проверкой» — не состояние**: в `UNRESOLVED_REASONS` (`contract.py:70`) зависимости от другой проверки нет; в 12586
   это записано `contradicts_requirement` + проза «the check is never reached»; S4 пишет зависимость только прозой («depends on TC-004»),
   S6 сворачивает pass+skip в `partial`, S8 читает такой Then как `wait`/`bug`, не «заблокировано TC-004».
4. **Остаток Then — только `handed_to_person`** (фикс 0.10.1, `166f4765`, GW1-14): отбор `!= HANDED_TO_PERSON -> continue` (`contract.py:183-184`);
   остатка «красный по багу» и «заблокирован» нет.
5. **Окно S5**: красный инстанс даёт пробел `product:<id>` (`acceptance.py:568-569`), не выводимый (`window_record.py:1129-1131`), а `s5.md:117-128`
   обещает «handed over RED»; как красный тест закрывает окно — не выяснено (проверить живым прогоном).
6. **Ledger/S9**: запись `handed` кейса с `failed:*` отбрасывается (`ledger.py:223-226`) — переданный человеку Then смешанного кейса не доходит до
   «Left with you» (вердикт и так `no`).

## Что сделать (форма, не спека)

- Единица исхода на S5 — пара (Then, партиция/инстанс), не кейс: `partial-green` и `contradicts-but-green` сверяют зелёный с ЕГО партицией
  (как `blocked_by_env` делает по `instance_ids`); красная по багу партиция законно стоит рядом с зелёной в одном кейсе (FR-34: красное — вердикт).
- Остаток Then обобщается с `handed_to_person` на четыре исхода: передано человеку / зелёное / красное по требованию / заблокировано другой
  проверкой — с полем `blocked_by: <case|instance>` (новая причина в `UNRESOLVED_REASONS`, одна точка, FR-13).
- `blocked_by` проходит насквозь: S6 не сворачивает его в `partial`, S7 не триажит, S8 пишет «заблокировано TC-004 (баг …)», S9 — вид с владельцем
  блокирующего бага; Then уходит в «Left with you» (перепроверить после починки бага) и не теряется в ledger при `failed:*` соседа.
- S4: зависимость Then от другого кейса — поле, не проза (тогда S5 ставит `blocked_by` кодом, без переписывания кейса).
- **Не терять результат независимых Then за упавшим** (слово владельца выше; ассерт = Then): когда тест проверяет несколько логически не
  связанных Then и один красный (код или среда), автоматор (S5) и разбор S7 пробуют один из ходов, по своему суждению, что логичнее (P1,
  FR-47: решает автор, код не диктует): перенести независимые Then ДО красного, не ломая логики; или закомментировать красный Then и всё,
  что от него зависит, с пометкой причины. Каждый Then получает свой исход в `then_bindings` (зелёный / красный по требованию / отдан
  человеку или другой среде / `blocked_by` красного Then), без переписывания кейса; закомментированный или заблокированный Then — строка
  «Left with you»: «перепрогнать N закомментированных Then на другой среде» или «проверить Then X, Y после починки бага B». Критик кода
  проверяет: не стоит ли независимый Then за красным без причины. Носитель — роль автоматора (и S7) + `then_bindings`; детектор — счётчик
  Then «заблокирован», которые перестановка могла разблокировать.
- **Рубрика критика противоречит слову владельца** (скаут t-1222, сверено Lead): `references/code-review-rubric.md` измерение 6 «no commented-out checks» и 8 «a deleted or commented-out assertion … Without the sanctioned path (`Known defect: BUG-n` + `red_lock`, an honest failure, or a `legitimate_correction`) → fail». Закомментированный красный Then с причиной и строкой манифеста/«Left with you» становится четвёртым санкционированным путём; без причины и строки — по-прежнему маскировка.
- **`manifest_put.py` не умеет снять строку `unresolved[]`** (FB-5 бэклога стенда 24.10, скаут t-1223): слияние по кейсу не сжимается, строки партиций переживают зелёную запись `tests[]` (`_partition_scoped`, `_merge_entry`) — без этого правка гейта не даст роли выйти из отказа: единственный писатель манифеста должен уметь снять строку, когда партиция стала зелёной или ушла в остаток Then.
- Пройти тот же класс по карте: S5 окно (`window_record`), `rollup_status`, `ledger.plan_row_state`, `traceability`, `check_delivery`.
