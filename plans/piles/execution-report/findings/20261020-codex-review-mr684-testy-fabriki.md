# Проблема 1. Text Diff не проверяет обе стороны изменения
Приоритет: P2    Тест: TC-008
Файлы:
tests/ui/workflows/test_edit_workflow.py — добавленные проверки около строк 251–265
tests/ui/pageobject/workflows/workflow_version_history_popup.py — методы get_diff_removed_text() и get_diff_added_text()
Вместо сопоставления ожидаемого старого и нового значений проверяется наличие нового маркера хотя бы в одной стороне diff и неравенство полученных строк. Методы Page Object объединяют изменённые строки пробелами, теряя их границы.
Последствие: Тест может пройти при неправильном старом значении или при отображении нового значения не на той стороне.
Рекомендация: Проверять обе стороны diff относительно ожидаемых значений сравниваемых версий; сохранять достаточную структуру строк для точной проверки.

# Проблема 3. Фиксированный HTTP 403 при открытом вопросе 401/403
Приоритет: P1 — при отсутствии решения владельца    Тест: TC-014 — non-owner access
Файлы:
tests/workflow/test_workflow_validate_api.py — test_validate_by_non_owner_is_rejected_like_update_and_keeps_record(), около строк 479–523
qa-factory/artifacts/TP1-15045/work/test-cases/workflows/TC-014.md

Спецификация явно оставляет выбор между HTTP 401 (наблюдаемый кодовый путь) и 403 (R-12) открытым до решения владельца. До разрешения предусмотрена проверка отказа и совпадения статуса/тела с PUT. В тесте жёстко ожидается 403. В рассмотренных материалах подтверждение решения Q4 не обнаружено.
Последствие: Ответ 401 может быть ошибочно признан дефектом приложения, несмотря на зафиксированную неопределённость oracle.
Рекомендация: Подтвердить решение владельца по Q4; до этого не фиксировать единственный код как безусловный oracle, сохранив проверку отказа, parity и неизменности workflow.
# Проблема 4. Cleanup не гарантирован при ошибке подготовки fixture
Приоритет: P2    Тест: Общие fixtures для UI-тестов
Файлы:
tests/ui/workflows/conftest.py — workflow_with_visual_diff_revisions, workflow_with_revision_pairs, workflow_with_two_valid_revisions
В трёх fixtures workflow создаётся, затем выполняются дополнительные get/update до yield. Удаление стоит после yield. Если setup завершится исключением после create, pytest не достигнет yield и teardown не выполнится.
Последствие: В тестовом окружении могут оставаться частично подготовленные workflow.
Рекомендация: Регистрировать finalizer сразу после успешного create либо обеспечить cleanup через try/finally, охватывающий подготовку.

# Открытые вопросы совместимости и ограничения
Три вспомогательных модуля (workflow_visual_diff_popup.py, workflow_visual_diff_test_data.py, workflow_validate_test_data.py) отсутствуют в проверенном Git-дереве. Вопрос их поставки ранее обсуждался и, по имеющейся информации, решён отдельно; он не включён в перечень новых проблем. Без этих модулей нельзя полностью проверить селекторы и тестовые данные.
В доступном исходном WorkflowService Python SDK не найден validate(), хотя новый WorkflowUtils вызывает self.client.workflows.validate(). Совместимость с фактически используемой версией SDK и raw-response контрактом требует подтверждения; до этого замечание не классифицируется как доказанный дефект Factory.
Дополнительное ожидание Loading в EditWorkflowPage.navigate_to() может пропустить поздно появившийся индикатор из-за однократного count(); реальный race condition не подтверждён.
## Предложения по улучшению
Синхронизация UI. В EditWorkflowPage.navigate_to() проверка Loading выполняется только при положительном результате однократного count(). Более устойчивый вариант — ожидать конечное состояние страницы (например, доступность заголовка или canvas) независимо от того, появился ли индикатор загрузки в момент проверки. Это улучшение надёжности, а не подтверждённый дефект.
Диагностика Text Diff. Для TC-008 полезно сохранять ожидаемые и фактические удалённые/добавленные строки раздельно в сообщении assertion. Это ускорит разбор падений и не потребует дополнительной абстракции.
Повторное использование fixtures. Три fixtures для разных наборов версий оставлены самостоятельными: их назначение различается, а объединение только ради DRY усложнило бы чтение. Дополнительный helper не предлагается.
