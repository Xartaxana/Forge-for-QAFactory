# Кап окна S5 по причине раунда: у `window_rounds[*].cause` нет читателя в отчёте, и находка DC1-21 называет 04:19 раундом автора

id: — | кучка: `execution-report` | от: критик t-761 (DC1-21, B-1, B-2, m-3, L-1), 02.11.2026 | приоритет: П3 | кандидат наверх: нет

## Что наблюдалось

DC1-21 (`release-next/1`) разделил кап раундов окна S5 по причине: `state/driver-state.json` `window_rounds["S5|<кейс>"]` теперь несёт у каждой записи `cause` ∈ `window` | `refusal` (`Driver.window_round_gate`, `scripts/story_run.py:5670`, `:5675`; документ `design/driver.md`, `references/state-exits.md:150`).

- Читатель в отчёте/ретро отсутствует: поиск `window_rounds` по `plans/` находит только строку узла, находку DC1-21 и два посторонних файла; очередь F-5 (а) жила только в `docs/tasks/handoffs/t-729-*`. Поле имеет производителя и единственного читателя внутри драйвера (AR-22: произведённое без читателя).
- Находка `plans/piles/release-next/findings/20261030-kap-okna-tratitsya-na-otkaz-samoj-fabriki-bez-kvitancii.md` (:8) и строка DC1-21 (`release-next/1`) называют раунд 04:19 «первым настоящим раундом автора». Это неверно (поправка F-6): по логам ночи (`r14857-7/8/9.log`: ноль строк `S5: found N gap(s)`) все три раунда были `refusal`; **раунд 04:19 был отказом HF8-15, не авторским**.
- DC1-22 (`repair_limit_gate`, `execution-report/batch-1-execution-evidence.md:22`) считает НЕИЗВЕСТНУЮ причину противоположно DC1-21: DC1-21 считает её на человека (R4), DC1-22 «не тратит кап и не предлагает `round`». Обе стороны могут быть верны (бесплатный раунд против платной доработки автора), но спека DC1-22 обязана сказать, почему расходится.

## Класс

Причина, по которой лимит потрачен, должна быть видна тому, кто читает отчёт (FR-4, FR-42; AR-22, AR-25, AR-27), а два лимита одного класса объясняют направление ошибки одинаково (AR-19).

## Что именно менять

Направление выбрано (Lead пачки release-next/1, 02.11.2026).

1. Читатель: `scripts/report_facts.py` (+ `scripts/retro_numbers.py`, если ретро считает раунды) читает `window_rounds` через одну новую функцию `window_round_causes(task_root)` рядом с существующим читателем `driver-state.json` (поиск читателя — первый шаг узла; нет такого — `hooklib.read_json`, AR-13); отчёт получает строку «Rounds spent on the factory's own refusals: N (not counted against the author)» только при `N > 0`. Ожидание: история без `window_rounds` → строки нет, без ошибки (AR-23); запись без `cause` → считается `window` (R4 DC1-21). Тест: `scripts/tests/test_report_facts*.py` — фикстура ночи 14857 (3 `refusal` + 1 `window`) → строка с 3; без записей → нет строки; запись с `"Refusal"`/`None` → `window`.
2. Правка находки (F-6): в находке `release-next/findings/20261030-kap-okna-tratitsya-na-otkaz-samoj-fabriki-bez-kvitancii.md` дописана строка поправки (внесена тем же ходом, что эта находка); строка DC1-21 в `release-next/1` заморожена — поправка стоит в её «Остатки».
3. Спека DC1-22 (`execution-report/1`): первым пунктом §2 — «почему неизвестная причина здесь не тратит кап, а в DC1-21 тратится» (направление ошибки обеих: бесплатный раунд фабрики против платной доработки). Тест не нужен (текст спеки); критик на план проверяет наличие пункта.
4. Мелкое из того же вердикта, если не вошло в раунд правок DC1-21: `same_set` для вида `refusal` печатает «the driver does not rework it again» (ложное «rework», тот же класс, что текст капа) — одна ветка `elif cause == "refusal"` в `window_round_gate`; ключ на сравнение множеств МЕЖДУ видами (предзадать `window`-раунд с множеством X, затем отказ фабрики с телом X → `same_set`).
