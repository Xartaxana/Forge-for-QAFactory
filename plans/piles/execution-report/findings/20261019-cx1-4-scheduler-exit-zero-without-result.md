# Планировщик: ребёнок с кодом 0 и без сводки не должен записываться как `completed` (I4, FR-18) — сделано в CX1-4, остались аналоги

id: — | кучка: `execution-report` | от: билдер CX1-4 (t-1004) по критику t-965 (Q6, M-4), 19.10.2026; переписано под принятый код в раунде правок t-1065 по критику t-1057 (F1, F3), 20.10.2026 | приоритет: П2 | кандидат наверх: нет

Что сделано (в коде узла CX1-4): `execution_scheduler._child_row` больше не записывает ребёнка с кодом 0 как `completed`
без доказательства результата. Правило (решение Lead 20.10, безопасная сторона): ребёнок с кодом 0 — `completed`, только
если ПОСЛЕДНЯЯ непустая строка его stdout — JSON-объект (`_last_json_object`). Иначе строка группы — `unknown` с
`unknown_reason` и `exit_code: 0`: молчание, пустые строки, предупреждение без сводки и traceback при коде 0 одинаково
«результата нет». Ответ ребёнка вместо запуска (`reused`, `already_run`, `run_refused`) читается как раньше; ненулевой код
остаётся `failed`. Настоящий `run_suite` правило не задевает: каждый исход его планового пути заканчивается одной строкой
JSON (`print(json.dumps(summary))`, `print_not_launched`, отказы `run_refused`/`invalid_request` с кодом 2). Сводка длиннее
хвоста в 256 КиБ обрезается, не разбирается и даёт `unknown` — тоже безопасная сторона. Тесты: `test_execution_scheduler.py`
(молчание, пустые строки, шум → `unknown`; шум и затем сводка → `completed`; traceback при коде 0 → `unknown`; ненулевой код →
`failed`).

Что остаётся аналогом (для CX2-15): (а) правило проверяет ФОРМУ последней строки, не её содержание: JSON-объект, не являющийся
сводкой (например `{}`), читается как сводка — настоящая проверка полей сводки принадлежит читателю сводки, не планировщику;
(б) другие места, где код 0 принимают за результат без доказательства, этим узлом не искались (карта `docs/SIBLING_MAP.md` по этому классу не
обходилась); обход — задача того, кто возьмёт строку CX2-15; (в) для команды установки инвариант I4
реализован отдельно (`red_sandbox`: ноль без созданной папки — `SetupFailed`).

Свидетель: `scripts/execution_scheduler.py` `_child_row`, `_last_json_object`; `scripts/tests/test_execution_scheduler.py`
(пины M-4); критик `docs/tasks/specs/reviews/t-1057-t-1003-cx1-4.md` F1.

Принципы и правила: P20, FR-18, FR-41.
