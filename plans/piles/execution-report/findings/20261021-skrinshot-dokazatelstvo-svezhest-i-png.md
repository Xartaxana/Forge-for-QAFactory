# Скриншот-доказательство: mtime не раньше старта прогона, валидный PNG, папка прогона, байт-дубликат другого прогона — строка отчёта, не отказ

Что не так / что сделать: скриншот как доказательство исполнения у нас не проверяется на свежесть и валидность: по grep 21.10
в `scripts/` проверок `screenshot` + mtime/png/sha нет (есть только строка `guard_pre_tool.py:442`). Старый или чужой файл
может быть принят за свидетельство текущего прогона. У Testing Factory доказательство-скриншот проверяется так: mtime файла не
раньше старта прогона, файл — валидный PNG, лежит в папке этого прогона, а байт-дубликат скриншота ДРУГОГО прогона не
отказ, а строка отчёта (хэш совпал с чужим). Что сделать у нас: эти четыре проверки для скриншотов-доказательств; нарушение
свежести/валидности/места — доказательство не засчитывается (FR-18: исполнение — не покрытие; FR-59: неизвестное не
становится проходом), дубликат по хэшу — строка отчёта, не отказ (FR-26: измерение не вывод, пока сырое не прочитано; у них
это сознательно строка, не блок). Для спеки дизайнера (решает Lead): где у нас скриншот входит в доказательство (P19 ступень 3
«агент проверяет вручную и показывает было/стало»; S6/S7), какой читатель одной проверки (AR-13), валидность PNG без новой
зависимости пакета.
