## Что наблюдалось

`docs/tasks/specs/reviews/t-1390-fb8-n1-diff-review.md`, D-3 (строки 107-109) и очередь Q-2 (строка 155): трёхсостоятельная защита «`is_code_file`, иначе `CODE_EXTENSION_FLOOR`» существует в четырёх местах — `arch_check.py:152-154`, `gate_preflight.py:575`, `runtime_probe.py:372-374` (новое), и собственный пол `project_inventory`. Рядом, D-2 (строки 104-106): `runtime_probe._names` повторяет предикат `test_files._strings` («список непустых строк, иначе None») — исполнить через `test_files._strings(value) is not None` или сделать `_strings` публичным.

Следствие: расхождение копий (одна учтёт новое расширение, другая нет) молча меняет, какие файлы считаются кодом в пробе, предподготовке гейтов и архитектурной проверке.

## Предложение

Один помощник в `test_files` («код ли файл: `is_code_file`, иначе пол»), четыре места зовут его; тест-храповик: второе вхождение шаблона в `scripts/` краснит. Ошибочное направление: файл неизвестного расширения не должен становиться «не код» молча там, где пол считает его кодом. Воспроизводящий тест первым: расширение, которое пол принимает, а `is_code_file` нет. Построить также свип на сиблингов-читателей (`non_runtime_files`).

Свидетель: отчёт критика выше; указанные строки кода (проверить по коду — номера названы на 27.10).
