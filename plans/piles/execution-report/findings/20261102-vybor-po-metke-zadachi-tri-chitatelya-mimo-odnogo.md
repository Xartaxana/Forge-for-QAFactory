## Что наблюдалось

После CD1-27 цена строки задачи на дашборде считается из одного читателя `factory_dashboard._tagged_tasks`. Поиск «расход или время задачи выбирается по метке, либо `None` читается как 0» (положительный контроль: тот же шаблон находит собственное чтение `_tagged_tasks`, `factory_dashboard.py:2145`) находит снаружи diff три места, не одно:

- (а) `metrics_projection.py:634` и `:649` — `complete_cost` и границы выгоды по метке (находки на них не было: поиск `metrics_projection.py:6(34|49)|complete_cost` по `plans/piles/` пуст, контроль на `metrics_projection` попадает в находки `execution-report`);
- (б) `retro_numbers.orchestrator_totals:285-287` — читает `by_task[task].machine_s` по метке как `int(... or 0)`: `None` суммируется как 0 секунд (дыра «частичное принято за целое» во времени ретро);
- (в) `factory_dashboard.task_cost_totals:313-322` — сумма расхода по метке; единственный вызывающий — `tests/test_dashboard_events.py:51`, в проде мёртв (спека §0.2 его называла).

Остальные попадания не класс: `retro_numbers.py:394` (наличие использования), `:994` (сессия, названная журналом, целиком). Оси в `docs/SIBLING_MAP.md` для «времени и расхода по метке» нет.

Смежное из того же вердикта (очередь, меняет золотой образец дашборда — нужно слово Lead): m-1 — строка со «—» при сессиях, чьё время не прочитано (путь активности без `active_s`), не названа в итоге; n-1 — `total_time_cell` печатает «—»/«unknown» поверх известных нулевых строк; n-2 — сумма `machine_s` по несвязанной наследной сессии (`dashboard_cost_groups.py:325`) пропускает `None`.

## Класс

Одна цена задачи — одно истинное число (P18; FR-24, FR-25, FR-41): расход и время по метке читаются одним читателем, а неизвестное время не суммируется как ноль (AR-13, AR-28).
