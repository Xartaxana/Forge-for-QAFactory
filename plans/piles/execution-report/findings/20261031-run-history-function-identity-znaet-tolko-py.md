# `run_history._function_identity` знает только `.py`: сырая строка отчёта Playwright никогда не «называет» TS-тест, красный остаётся неподтверждённым (t-565 E-10)

id: — | кучка: `execution-report` | от: критик t-565, E-10 (`docs/tasks/specs/reviews/t-565-ep1-37-gw1-1-critic.md`), 31.10.2026 | приоритет: П2 | кандидат наверх: нет

## Что наблюдалось

Замер критика над `run_history._function_identity` (`run_history.py:146–178`): `tests/a.spec.ts::g › T` даёт функцию `a.spec.g › T`, сырая строка отчёта `a.spec.ts::g › T` — `ts.g › T`, поэтому сырой отчёт ни разу не «называет» TS-тест, и красный
остаётся неподтверждённым (`function_key`, :181, ключ парной проверки «тест изменился между красным и зелёным», B-194). `T (a)` и `T (b)` оба дают ключ `a.spec.T` из-за разбиения по `(`. Рядом — `import_test_receipt.py:108`: точное множество против сырых строк, импортированная
квитанция TS отказана (безопасно). `probe_by_code.py:2373` — зона EP1-36. Источник: функция знает формы pytest/junit/C# (`.py`, точки, заглавные классы) и не знает язык с данными `detectors.json`; EP1-37 завёл для этого единственного читателя `scripts/test_source.py`.

## Что именно менять

1. `run_history.py`, `_function_identity`: ветка `head` с расширением файла, не `.py` (`.ts`, `.js`, `.tsx`, `.cs` и любое из записи языка в `references/detectors.json`), идёт через `test_source` (идентичность ОДНОГО теста: сырой заголовок отчёта и голый заголовок объявления — те же правила, что у `test_source.matches`); форму разбора берёт из данных языка (AR-1), не из набора расширений в коде.
   Разделитель параметров `(`/`[` режется только когда запись языка не объявляет скобки частью заголовка.
2. Неизвестный язык: прежний результат и пометка «unread» в возврате, не молчаливая подмена (FR-41).
3. `import_test_receipt.py:108`: сверка строк квитанции идёт тем же ключом `function_key` (не точным множеством сырых строк), чтобы импорт TS не отказывался.
4. Тесты (`scripts/tests/test_run_history_identity.py`, `test_import_test_receipt.py`): `tests/a.spec.ts::g › T` и `a.spec.ts::g › T` дают ОДИН ключ; `T (a)` и `T (b)` — два; `.py` без изменений (все прежние строки зелёные); язык без записи — прежнее поведение с пометкой. Мутация: вернуть `.py`-только — красит первый.
