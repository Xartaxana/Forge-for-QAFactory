## Что наблюдалось

- `ai-packages/qa-factory/references/delivery-verdict-kinds.json`: виды `branch_lost`, `branches_not_recorded`, `source_unreconciled` — все `after_checks`, владелец `product`. Производители: `scripts/branch_accounting.py:_branch_records`, `_unit_records`, `_walk_records`.
- Цитаты: `_debt("branch_lost", ..., "no case carries it and nobody left it out: nobody checked it")`; `_debt("source_unreconciled", "test-candidates", [], f"the existing tests were not read ({why})", ...`; `_debt("source_unreconciled", "ticket-text", [], why, "read the ticket yourself: the factory could not account for its text")`.
- Это случаи, когда фабрика потеряла работу, которую была должна. Спека (`r0107-s6-v2-g2-11-tq1-17-20.md` §3.1) выбрала владельца `product` сознательно, по аналогии с `unconfirmed_expectation`: для строки, которую читает человек, это защитимо, и исход `after_checks` согласуется с P21.
- Но фабричной стороны нет: `git grep` по этим видам вне тестов и производителя находит только `report_facts.py:2346` (контроль: тот же grep эту строку находит). Ретро (`retro_numbers`), `metric_signals` и дашборд их не считают. Фабрика, теряющая ветви в каждом прогоне, сохраняет чистую фабричную запись, а работу получает человек.

## Класс

Отказ фабрики записан только на стороне человека (FR-19: причина называет владельца; здесь есть и фабричная причина, которую никто не считает) и не измеряется (FR-55, AR-27: находка доходит до отчёта под своим владельцем).

## Что именно менять

Направление выбрано (Lead пачки, 01.11.2026). Пути — от `ai-packages/qa-factory/`.

1. Пункт человека не меняется: вид, владелец `product`, исход `after_checks` и вердикт доставки остаются как есть. Тест: реестр с одним долгом `branch_lost` — вердикт доставки тот же, что до правки (`scripts/tests/test_delivery_verdict.py` или файл, где уже проверен этот вид; имя — проверить по коду).
2. Новая строка данных (например `references/factory-loss-signals.json` или раздел в существующем реестре метрик; место выбирает спека, но сопоставление живёт в данных, не списком в коде — AR-1): вид → фабричная причина. Минимум три записи: `branch_lost` → «ветвь потеряна, никто не проверял»; `branches_not_recorded` → «ветви не записаны в реестр»; `source_unreconciled` → «источник не сведён». Читает один читатель.
3. `scripts/metric_signals.py`: сигнал фабричного владения по каждому такому долгу реестра (число долгов вида → число сигналов; один долг `branch_lost` → один сигнал), причина — из строки данных. `scripts/retro_numbers.py`: строка ретро «фабрика потеряла N ветвей/источников» с разбивкой по видам. Деньги в строках не пишутся (P18).
4. Тесты: `scripts/tests/test_metric_signals.py` — реестр с одним долгом `branch_lost` даёт ровно один фабричный сигнал, реестр без таких долгов — ноль; `scripts/tests/test_retro_numbers.py` — строка ретро с этим числом; вид, которого нет в строке данных, — сигнал «неизвестная причина» (FR-59, не молчание).
5. Край: пустой реестр или отсутствующий ключ — ноль сигналов, без ошибки; `source_unreconciled` с одним и тем же источником дважды в реестре считается один раз (ключ — вид + источник).
