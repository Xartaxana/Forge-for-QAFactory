# `Path.glob/rglob` на Windows находит файл без учёта регистра, на Linux — нет: класс принадлежности рядом с классом порядка

## Что

C4-7 закрыл класс ПОРЯДКА обхода (`sorted(<Path>)` зависит от платформы). На той же поверхности живёт класс ПРИНАДЛЕЖНОСТИ: КАКИЕ
файлы обход находит. `Path.glob` / `rglob` в Python 3.12 (`case_sensitive=None`) на Windows сопоставляют имя без учёта регистра, на
Linux — строго. Поэтому поиск кейса по id находит `tc-001.md` для `TC-001` на Windows и ничего на Linux — у фабрики разный результат
на стенде разработчика и в CI:

- `s5_precheck.find_case_file` (:461, `rglob(f"{case}.md")`);
- `handoff_check._case_front_matter` (:288);
- `judge_results._find_case_file` (:110);
- `path in seen` в `dashboard_refresh.py:38` — равенство `Path` на Windows тоже без регистра.

Не подтверждено прогоном: нужна проба из двух файлов на обеих платформах (Windows + docker `python:3.12`), затем решение класса:
обход всегда строгий (`case_sensitive=True` там, где id кейса — часть имени; FR-16 — идентификатор разрешается тем инструментом,
который его производит), либо явная нормализация с отказом на двусмысленность (два файла, различающихся регистром, — отказ по имени,
FR-1). Перепись сайтов — по тому же grep, что у C4-7 (`glob(`, `rglob(`, `in seen`, `==` над `Path`), с вердиктом на сайт.

Свидетель: отчёт критика `docs/tasks/specs/reviews/t-896-t-892-c4-7.md` (F-3); прогон не делался (лимит).
