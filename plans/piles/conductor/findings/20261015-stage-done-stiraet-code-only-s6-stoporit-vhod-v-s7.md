## Что

Проекция `stage_transition` (`controller.py:664-680`) после `stage_done` переписывает запись стадии как
`{status: completed, reason: <digest>}` и СТИРАЕТ `code_only`/`receipt_id`, которые `code_only` записал при расписке
(`C:835-837`). Читатель `s6_closed_by_code` (`s7_pretriage.py:301-309`; тот же разбор в `check_delivery:1045`) после этого
ложен для каждого кодового закрытия S6 (`manual_close`, SR:7896-7910) — стори, у которой в S6 нечего было исполнять, на
входе в S7 (`SR:8146-8149`) не распознаёт кодовое закрытие и встаёт. Воспроизведено критиком на `main` (до C1-5b2) на реальной
проекции; у C1-5b2 тот же след: `code_only: true` у S7 живёт только в момент расписки — пин узла проверяет расписку, а не конец.

## Чинить

Одно из двух, решение Lead при диспатче: (а) проекция `stage_transition` сохраняет `code_only`/`receipt_id` стадии (контроллер —
очередь `controller.py`: C3-12 → C3-14); (б) читатели (`s6_closed_by_code`, `check_delivery:1045`, вход S7) читают кодовое
закрытие из события расписки (`receipt_id` в журнале контроллера), не из записи стадии. Тест: S6 закрыт кодом → `stage_done` →
`s6_closed_by_code` истинен, вход S7 идёт; тот же пин для S7 после C1-5b2.
