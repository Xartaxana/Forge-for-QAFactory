# Измерения и уроки, которые пережили планы

Здесь собраны измеренные факты и уроки, вынесенные из планов и отчётов, которые удалены из этого дерева. Сами документы остались в архивной ветке `experiment/qa-factory-driver` репозитория `dev1/yml-text-factory`, в папке `factory-plans/`. У каждого факта указан документ-источник под тем именем, под которым он лежит в архиве (пути даны относительно `factory-plans/`), чтобы факт можно было найти и перепроверить. Числа перенесены без изменений; одинаковые факты из нескольких документов записаны один раз с двумя источниками. Пары «старый SHA -> новый SHA» для коммитов, упомянутых ниже, см. в `docs/provenance.md`.

Обозначения: «стори» — тикет Jira; «прогон N» — нумерация прогонов TP1-13797 из документов драйвера; P1…P22 в исходных документах — принципы и пункты плана, здесь не расшифровываются.

## 1. Деньги и контекст

### 1.1 Законы стоимости

- **Квадратичность.** Токен в контексте на запросе i из N оплачивается (N−i) раз как чтение кэша; стоимость окна ~ квадрат числа ходов. При 472 запросах токен из середины контекста стоит ≈ $72 за миллион. Стоимость диспатча ~ ходы² × прирост контекста × $0.30/Mtok; внутри сессии контекст не сократить, единственный сброс — конец диспатча. Цена = число ходов × средний контекст. Источники: `PLAN-cost-and-time.md`, `PLAN-after-run4.md`, `PLAN-cost-3x.md`.
- **Каждый ход перечитывает накопленный контекст.** Пилот 13958: оркестратор — 318 запросов × 165K = 52 млн токенов. Источник: `PILOT-TP1-13958-FIXES.md`.
- **Половина контекста — размышления роли.** Постоянная часть промпта скаута — 36 700 токенов (собственные файлы фабрики 7 133 = 19%; схема одного инструмента ~10K). Источник: `PLAN-after-run4.md`.
- **Токены выхода** — 0.4 % токенов, 11 % денег. Источник: `PLAN-cost-and-time.md`.
- **Оркестраторские деньги — это ходы между диспатчами** (509 ходов × 261K контекста), а не размер промпта диспатча (1.2–1.8K символов). Источники: `PLAN-driver.md`, `PLAN-cost-3x.md`.

### 1.2 Ставки Sonnet

- Чтение кэша $0.30/Mtok; запись кэша 5m $3.75 (×12.5); запись кэша 1h $6; кэш живёт 5 минут. Источник: `PLAN-after-run4.md`.
- Доли денег: в judge-off чтение кэша — 62 % ($67.68 из $109); в driver2 до S5 — 46 %. Источник: `PLAN-after-run4.md`.

### 6.5 Стоячие правила builder-агентов (из `AGENT-BRIEF-common.md`)

Разовые данные брифа (пути, версии 0.7.13/14, ссылка на транскрипт) не переносятся.

1. **File ownership.** Правишь только файлы своего пакета; нужное в чужом файле — не правь, опиши в «Needed from integration» (файл, точный текст/код, зачем). Только интегратор трогает: `skills/qa-story/SKILL.md`, `CHANGELOG.md`, все `plugin.json`, `README.md`, `INSTALL.md`, `references/templates/config.json`, `scripts/contract.py`, `scripts/selftest.py`, `scripts/install_smoke.py`. Новые ключи конфига читать в коде с дефолтом; в отчёте — имя, дефолт, смысл.
2. **Никаких изменений git-состояния** (параллельные агенты в одном дереве): не `stash`, `add`, `commit`, `checkout`, `reset`, `restore`, `clean`, `pull`, `push`; `diff/log/show/status` можно. Чужие незакоммиченные правки не трогать.
3. **Весь репозиторий на английском**, кириллицы в пакете нет (selftest проверяет); id историй в комментариях допустимы.
4. **Стиль.** Комментарии объясняют *почему*, обычно называя инцидент, научивший правилу; тесты на `scripts/tests/harness.py` (`check`, `check_eq`, `temp_project`, `temp_dir`, `cleanup`, `finish`) или unittest, сначала смотреть соседний тест; без новых зависимостей, только stdlib.
5. **Потолки размера** (selftest `--limits`, `selftest.py:18-20`, `audit_factory.py:172,990`): `skills/*/SKILL.md` ≤ 19000 байт (и 500 строк), `agents/*.md` ≤ 9000, `references/*.md` ≤ 12000; аудит A22: инжект в одну роль ≤ 42000 байт — добавил текст в агент/референс, убери не меньше избыточного. Файлы `phases/` без потолка, но оркестратор читает их каждый прогон — добавлять кратко.
6. **Не писать байткод в пакет:** `python -B`, тесты `python -B scripts/tests/<file>.py` из `ai-packages/qa-factory`; временные файлы — в temp ОС, не в пакет.
7. **Обязательная проверка перед отчётом:** свои тесты; каждый существующий тест, импортирующий изменённый модуль (`grep -l "<module>" scripts/tests/*.py`); `python -B scripts/selftest.py --limits --lang`; `python -B scripts/tests/test_audit_rules.py`; `test_hooks_wiring.py`, если трогал хуки. Полный `selftest.py` и `install_smoke.py` не запускать (гоняет интегратор один раз, параллельные запуски конфликтуют). Красный тест вне своих файлов от чужой недоделки — отметить и не чинить.
8. **Слово человека проходит любой блок** (стоячий принцип, CHANGELOG 0.7.4): любой новый отказ обязан называть, как записанное решение человека его проходит (команда waiver в оркестраторе, по стадии и блоку), и не выдавать человеку как «его» ремонт то, что дефект самой фабрики. Роль сама waiver не запускает — pre-tool guard это блокирует; слово записывает оркестратор.
9. **Обратная совместимость:** проекты, онбордженные на 0.7.x, работают без повторного онбординга; стори «в полёте» не отказывать из-за того, что артефакт прежней версии не имеет нового поля.
10. **Живой проект — только чтение:** образцы данных прогона читать read-only, не писать туда и не делать `cd` туда (хуки живой сессии срабатывают на любой процесс с cwd внутри проекта); исполнять код на образце — на копии в temp.
11. **Формат финального отчёта** (≤ 500 слов, его читает интегратор): по каждому пункту плана DONE/PARTIAL/NOT DONE + одна строка + файлы; добавленные/изменённые тесты и точные итоговые строки прогонов; «Needed from integration» (файл + текст + причина; текст для SKILL.md — строки < 200 байт, запаса нет; новые ключи конфига; 2–4 строки в CHANGELOG в его голосе); что решено иначе, чем в плане, и почему.

Стоячее из других брифов: интерфейсы между пакетами «фиксированы» — кодировать против них, не дожидаясь чужой стороны; каждый новый CLI-скрипт регистрируется в `audit_factory.py CLI_SCRIPTS`; pytest напрямую не запускать (хук отказывает, использовать `python tests/test_<name>.py`); каждый кодовый путь обязан работать при `judge.provider: none` (шапка `driver-packages`).

`spawn_agent` передаёт непрозрачный `message` (`gAAAA…`), тикет несёт только `task_name`; фолбэк «единственная running-стори» ломается от призрака закрытой стори (2534) — отсюда I-92 (`closed_at`). Источник: `PLAN-improvements-from-story-testing.md`.

### 7.6 Протокол парного замера и раскладка бюджета

12+ пар (API/web/mobile/mixed, XS/S/M, expected-red/collection error/flaky/resume), 3 повтора; критерии: sum(new)/sum(base) ≤ 0.50, без false-green, без потери кейсов, без переноса работы на человека/CI; учёт времени до первого теста и human minutes.
