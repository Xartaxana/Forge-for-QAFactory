## A. Refusals and doors
- FR-1 — A refusal says what is wrong, what it expected, and how to satisfy it
- FR-2 — The door a refusal names must be one the refused party can use
- FR-3 — A reason owned by the factory is reported to a person, never put to them as a choice
- FR-4 — A check stops a silent pass, never an informed one
- FR-5 — A stage may not require, to close, an artifact nothing in the factory can produce
- FR-46 — The class of a refusal says whose fault it is: the call's, or the story's
- FR-48 — The conductor is called for a problem, never to run a command, and settles the problem itself before it asks a person
- FR-50 — Whatever the work needs from outside is tried by every route before a person is asked, and then the person gets three answers
- FR-57 — A ban is never bypassed, and never a dead end

## B. Text shown to a person
- FR-6 — Every text a person reads obeys `human-questions.md`
- FR-7 — A boundary a person has answered is never re-asked with the same text
- FR-8 — The person's words are carried to whatever can act on them
- FR-9 — Everything a person decides at a gate has an executor, and the decision is kept whole
- FR-10 — One packet shown to a person does not contradict itself

## C. Contracts between code and roles
- FR-11 — If a contract requires a field from a role, the tool that role is told to use must be able to produce it
- FR-12 — A detector never reads a person's or a role's wording by a phrase list
- FR-13 — Closed variety lives in data files, never in code; open variety is judged by a role
- FR-14 — A script's output shape is as much a contract as its arguments
- FR-15 — A path a role needs is given to it, not searched for
- FR-38 — A check that will judge a role's output states its requirement to the role before the work, in the fields the role must fill
- FR-39 — What the rules say a party may do, the guard permits
- FR-42 — For every state the other side can return, this side has a move or a refusal that names who acts
- FR-49 — What a stage gathers travels in its handoff, whole
- FR-56 — A role is given only the tools its work needs

## D. Identity and evidence
- FR-16 — An identifier is resolved through the tool that produces it, at the moment it is stored
- FR-17 — A tool that exists for a problem is wired everywhere that problem occurs
- FR-18 — Evidence of execution is not evidence of coverage
- FR-40 — Every state the factory can record has a sanctioned way out
- FR-58 — Code is never an oracle
- FR-59 — A gate does not decide on an unknown: it names what it could not establish and asks whoever can know — or takes the safe default it declares, never a pass

## E. Delivery and reporting
- FR-19 — Every blocking reason names its owner, and an unrecognised reason is a defect of the classifier
- FR-20 — The reason a delivery is not ready is stated in the task's own terms, first
- FR-21 — A skip because the product lacks what a requirement demands blocks delivery
- FR-22 — A discrepancy with a requirement has a road to a bug even when no test can fail
- FR-23 — Every step has a recordable completed state for the null outcome
- FR-35 — A report never changes the meaning of a role's own verdict
- FR-36 — A capability the run's standing decision forbids is neither probed nor advertised
- FR-37 — Every path named in text a person or a role reads is the path the code writes
- FR-53 — A comparison run leaves no trace in the project

## F. Measurement and money
- FR-24 — A story's spend is the sessions its own journal names
- FR-25 — When two records of the same quantity disagree, the report names the authoritative one and prints the gap
- FR-26 — A measurement is not a finding until the raw evidence is read
- FR-27 — A cache belongs to the run it measured, and a report says out loud when it used one
- FR-28 — A measurer is code and gets a test like any other code
- FR-41 — An unknown is never reported as a fact
- FR-51 — Work moved to a deterministic tool is judged by the LLM spend it removes
- FR-55 — Friction with our own code is measured on every run, and code that makes a role's stage dearer than without it is a defect

## G. Writing factory code
- FR-29 — Code bearing escape sequences is never written through a heredoc, and no package file carries a control byte
- FR-30 — The package is English
- FR-31 — A test that fails only under load is a defect of the test
- FR-32 — Every fix goes to the root cause, with a test and a green selftest
- FR-33 — A fix is proved by the factory doing the thing, not by a person doing it for the factory
- FR-34 — A red test against a requirement is a bug, not a blocker
- FR-43 — A process someone reads while it runs writes line-buffered
- FR-44 — Where a document lives is decided by who loads it
- FR-45 — A validator writes nothing: not into the request, and not onto a copy the projection rebuilds
- FR-47 — Code is an instrument a role calls, never a substitute for the role's judgment
- FR-52 — The factory's roles run on Sonnet or Terra, never on Haiku; a fix that holds only on a stronger model is not a fix
- FR-54 — A change finds its siblings by the map
