- NO_PATH: `… Its handoff: line holds no absolute path (a relative path, a placeholder and a quoted line are not read).
  Expected: …` (the same Expected and Door as WRONG_FOLDER)
- MANY: `… Its handoff: names {n} distinct .md files inside {folder}: {first 5}[ and {n-5} more]; the worker may write

- NOTE_UNCHECKED: `HANDOFF CHECK: not checked ({what}) -- the dispatch went out; tools/handoff_gate.py still limits the
  worker's writes.`
- SKIP_NOTE: `HANDOFF CHECK: sent without a report path on purpose: "{reason}" -- the worker returns its report as its
  final message (tools/handback_extract.py saves it).`

`{folder}` is shown with forward slashes, as the data stores it. `{paths}` are shown as the dispatch wrote them, at
most 5.

### A.4 Error direction of the reused functions, and inputs that must stay on the safe side

`handoff_paths`, `_in_folder` and `_real` move from the WRITE gate into a LAUNCH gate, which is a more consequential role
(a refusal now blocks the dispatch itself). Allowed error direction: **the launch check may PASS a dispatch whose writes
the write gate will later refuse. It must never REFUSE a dispatch whose write the write gate would accept.** The write
gate stays the enforcement; the launch check only moves the same refusal earlier.

Inputs that must stay on the safe side (each is a test row):
1. The same path written twice in two spellings (case, `\` against `/`, a `..` segment): one candidate, pass. `_real`
   dedups the same way as `_gate`.
2. A degraded cut (text over `md_regions.MAX_TEXT_CHARS`, or a scan that raises): pass with NOTE. The write gate refuses
   such a dispatch, but an unknown is never a launch refusal: the declared safe default is the write gate (FR-59).
3. A `handoff_gate` import that fails: pass with NOTE.
4. A kind in a different spelling (`" Critic "`): it is checked (normalized). A kind that is not exactly a gated word
   (`foo:critic`, `critic-2`): not checked, which matches the write gate (`handoff_gate.py:140-142`).
5. A path in a subfolder (`docs/tasks/specs/reviews/x.md` for a designer): refused. The write gate refuses it too
   (`_in_folder` accepts direct children only).
6. A critic dispatch with an absolute `owns:`: checked anyway. The write gate gates a known critic regardless of owns
   (`handoff_gate.py:141`).

### C.5 Edge behaviour, both worlds, invariants

Invariant of the door: **a band only raises or reserves ids above everything already issued or reserved. It never
lowers the counter, and it never makes an issued or reserved id issuable a second time.** Each edge below protects it.

- Before any band exists (both worlds, part 1): every journal and every test with no `id_band` gives the SAME verdicts
  and the SAME `next free id` as today. The NOVELTY text changes only in its wording; the `expected t-NNN` value is the
  same number. The `t-499` filler of `dev2.jsonl:474` stays; it is history, never rewritten.
- After the first band (part 2): the field exists only on lines written from then on. Which move creates it is the first
  line a second writer appends with `id_band`.
- A band on a line whose own id is the band's `A` (the opening `delegated`): legal, because the band applies first.
- A band on an accepted, rejected or decomposable line: legal. That line's own id is judged as today.
- The main sequence reaches a closed band: it jumps to `B+1`. Adjacent bands are skipped in turn.
- An id inside a band used out of order (t-405 when the band's next is t-403): NOVELTY naming t-403.
- A band is used up: NOVELTY carries the "used up" clause. The writer opens a new band, which must be above `top`.
- Two closed bands declared by two writers: the second must start above the first's end (BELOW otherwise). Overlap is
  impossible by construction.
- A malformed band on a NEW line: a FORM violation, and it does not enter the state. On an OLD line: ignored, never judged.
- A JSON `null` band: absent, no violation (the same as `node`).
- In a merge, each parent's valid bands are in the state of the tail. Bands that the two clones declared independently
  can overlap. Kept lines are not re-validated (`:1595-1596`). The collision WARN names the overlap (step 5).
- `--all --base` (CI) and `journal_echo`: the same `decide()`, so the same verdicts. No separate code.
- Limits AT and BEYOND: a size of 1000 is ok and 1001 is TOO_BIG; a jump of 10000 is ok and 10001 is JUMP.
- What a band does NOT do: it does not stop a session from ignoring its band and taking `main`. The code cannot know
  which session wrote a line (there is no session field). That stays on discipline, with the detector in §C.8 (c).
