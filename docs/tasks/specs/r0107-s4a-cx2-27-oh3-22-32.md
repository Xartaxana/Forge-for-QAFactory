## 3. Design

### 3.1 CX2-27: matcher, what counts as evidence of a form (N1)

Definitions, in `adapter_forms.segment_matches`:

- A **literal form word**: a later token, not quoted, equal to a form word after the program (`text == word` or `clean(text) == word`), or a wild word whose RAW text holds that word blank-delimited, with `$(`, `)` and backticks stripped (token text is `$(echo pr create)`; a blank split alone gives `create)`). A named program is a literal.
- **Rule L ($var).** A `$var` start (`_wildcard` true, `is_wild` false) counts only when a literal form word stands after it. `_wildcard` itself stays as it is (the finding's edge: narrow, never disable).
- **Rule H (pure substitution, fork F-1, recommended form).** A match with no literal form word starting at a wild word does not count when the segment's HEAD releases it: a mention command (`vcs.mention_commands`), a `$var`, or (from N2) a script run. Any other head keeps today's reading (`git $(a) $(b) commit` stays True, pin B-1 kept; `$(a) $(b)` stays True).
- New table row `vcs.list_heads`: `for`, `foreach`, read ONLY by `released` for Rule H. They do NOT join `vcs.mention_commands`: quoted words of a loop head are read as commands, since `for c in "gh pr create"; do $c; done` runs it (`mention_command` would make the quoted arguments TEXT in `_delivery_in_text.hops`, `stage_guard.py:1191`; the same table also feeds `_shell_segments` and `_git_words`, `stage_guard.py:1242`, `:1272`). A `do`/`then` segment is cut at `;` already and stays read.

Interface: `segment_matches(form, tokens, name=None, clean=None, is_wild=None, *, released=False)`; the caller computes `released` (`_delivery_in_text.hops`). `written_form`, `program_written` are unchanged; their no-wild call keeps its answer. Cost: one right-to-left scan per form for "last literal position", so the O(tokens x words) of `STEPS` stands; `$a $(f) $(g) pr` (a literal past the matched slots) is an accepted over-refusal.

**Error direction of the matcher: toward refusal.** Allowed error: an extra refusal, with a door. Not allowed: a pass on `$gh pr create`, or on any form with a written literal.

#### 3.3.1 Text receivers and quoted arguments (F-3)

Text receiver = a mention command (`vcs.mention_commands`), or a new table row `vcs.text_receivers` (recommended: `cat`, `tee`, `wc`, `sort`, `head`, `tail`), or a **script run**:

`script_run(tokens)`: the program is a launcher of `run_forms` whose subcommands are `["-m"]` (`python`, `python3`, `pythonw`, `py`, with the version tail via `hooklib._launcher_subs`) or a row of new `vcs.script_runners` (`run-py`); then, skipping only `vcs.script_plain_flags` (`-B -u -I -E -s -S -O -OO -q`), the next word is not an option, not `-`, not wild and not a bare `$var`, and its last path component ends in `.py` (`$P/x.py` and a quoted `"$P/x.py"` count; `$S`, `/dev/stdin`, `/dev/fd/0`, `/proc/self/fd/0`, `CON` do not); and no word of the segment is a shell of `run_forms.shells`.

**Why a script run is a safe "text":** a script can deliver with no words on the command line at all, and the guard never reads script files; an argument adds no hole that is not already there. Accepted, named, not defended: `python wrapper.py ssh host "gh pr create"`.

`_delivery_in_text.hops`: a script run's quoted arguments are text, as a mention command's. The fits check stays first, so bare words are still read (`python x.py gh pr create` refused, as `echo gh pr create` is: docstring, unchanged). From N2 `released` also holds for a script-run head.

**Glued wild words (fact 4):** a wild word with literal text stands for a form word only if that literal text can be part of it: `clean(text)` is empty, or, with a program slot's path and executable suffix off (`hooklib._name`; a bare `.exe` reads as empty), a subsequence of the word, compared lowercased. An option-shaped word that fails this falls through to the option branch (`gh --repo=$(r) pr create` stays True). `FOO=$(f)` is no start. Keep True: `cre$(true)ate`, `g$(x) pr create`, `/usr/bin/$(x) pr create`, `C:\t\$(x).exe pr create`, `$(x).exe pr create`.

**Empty table / damaged table (`FormsTableError`, floor):** no text receivers, no script runners, no flags: nothing comes out, the guard reads raw as today. Invariant: a damaged table never widens "text".

### 3.7 OH3-32: the ban reads quotes (N3)

**Reused function in a gate: `SHELL_OPAQUE_BAN` stays the first check of two guards, now with a quote fact from `_Reader`. Allowed error: a backslash stays banned. Never: a member the shell reads as code is exempted.**

- No hit is exempt when the text holds `<<` or a here-string opener anywhere: the walker does not know bodies, so a quote fact past one is unreliable.
- `shell_opaque_found` walks `finditer`, not `search`. A hit of backslash + one of `| ; &` is skipped when its backslash lies in a quoted run in BOTH the bash and the PowerShell reading; the next hit is judged. Every other member (backslash before `( ) ' "` or a line end, `<#`, `--%`, typographic, lone CR, backslash-blank-`#`, `)#`, VT/FF) is never exempt (`\(`, `\)`: fork F-5).
- **The quote fact (one grammar, AR-15):** `_Reader` records the offset of each backslash read inside a `'...'` that closed, or inside a `"..."` frame (both characters of an escaped pair), with no tick open (`self.tick is None`); `_rewind_unclosed_quote` drops those at or after the dropped frame's start; a backslash in a `$( )` region inside a double quote is NOT in the dq frame and so is not recorded unless it has its own quotes. It reaches the reader as a new field with a default on `Unit`, top unit only; `_read_units` freezes it as a tuple (the cache's frozen rule). `hooklib.quoted_backslash(text, at)` reads both dialects. `_read_backslash` is untouched.
- **Door (finding item 2):** a backslash member hit whose backslash lies in a quoted run in either reading gets a new door, the string:

  ```
  the text is already in quotes, and this backslash stays a problem there: in a regex write a class such as [(] for \(, write a Windows path with forward slashes (C:/p/(1)/x), use single quotes for a double quote, and end a path without a trailing backslash
  ```

  A hit outside quotes keeps `_DOOR_BACKSLASH`, byte for byte. The pin at `test_stage_guard.py:477` uses a quoted `\(` and the phrase "forward slashes (C:/p/(1)/x)"; the new door keeps that phrase, so it stays green unchanged.
- **`WalkerError` in the read:** propagates; `stage_guard.check` denies with `WALKER_DOOR` (AR-25, AR-28); `host_adapter._read_refusal` meets the same read a few lines later already: the builder confirms in the report how it is caught there, and if it is not, says so (no edit, analog).
- `host_adapter` gains the same freedom with no edit: a plain `rg` with a quoted backslash-pipe now goes on to `_READ_BAN` and the one-segment read. Error direction there stays refusal.
- N3 reads the executable text only through what `check_command` already hands it (N2); this is why N3 follows N2.
