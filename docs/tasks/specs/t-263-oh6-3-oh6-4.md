## A.2 The change, per file and function

**`event_store.py`**
1. Two module constants next to `REPLACE_ATTEMPTS`:
   - `TEMP_NAME_HEX = 8`: the hex characters of the token in `.<token>.tmp`.
   - `TEMP_NAME_ATTEMPTS = 8`: how many fresh names one publish tries.
   Each gets a one-line comment. A collision is about 2^-32 per concurrent pair on one target. `"x"` turns a collision into a
   retry, never into mixed bytes.
2. A seam `_temp_token()` returns `uuid.uuid4().hex[:TEMP_NAME_HEX]`. It exists so tests can force a collision without
   patching the global `uuid` module (which `event_id` and `recovery-*.bin` also use).
3. `_publish(path, write, **open_options)` keeps its signature and its docstring role. The new body, in order:
   1. `path.parent.mkdir(...)` (unchanged).
   2. For `attempt` in `1..TEMP_NAME_ATTEMPTS`:
      - `tmp = path.with_name(path.name + "." + _temp_token() + ".tmp")`.
      - `stream = tmp.open("x", encoding="utf-8", **open_options)`.
      - On `FileExistsError`: if `attempt == TEMP_NAME_ATTEMPTS`, re-raise. Otherwise take the next name. **Do NOT unlink
        `tmp`: it is another writer's file.**
   3. Only after the open succeeded: `try: with stream: write(stream); flush; fsync` → `replace_file(tmp, path)`,
      `finally: tmp.unlink(missing_ok=True)`.

   POSITIONAL invariant: the `try/finally` that unlinks begins AFTER the successful `"x"` open. A name this writer did not
   create is never written, truncated or unlinked by it. Today's code put the open inside the `try`. With `"x"` that would
   unlink the other writer's temp on a collision.
4. `atomic_json`/`atomic_text` are unchanged. The `atomic_text` docstring says "unique temp name". Keep it.

## B.0 The A24 key: which form, and why (fork F-1, recommendation D)

How A24 keys a refusal (`refusal_registry.py:827-887`, read): the key is the SOURCE TEXT of the first argument of
`deny(...)`/`block(...)`/`raise ValueError|StateConflict(...)`, unquoted and cut to 90 characters. An entry covers a site by
file, function and key PREFIX. Only `SCANNED` files are read (today `stage_guard.py`, `inject_context.py`,
`guard_pre_tool.py`).

The three refusals are raised in `native_context.stage` (`:149-165`). One gotcha: `StateConflict` subclasses `ValueError`,
so all three reach the same `except ValueError` branch in `inject_context.dispatch` (`:708-710`). That branch does
`print('INJECT: ' + str(exc)); sys.exit(2)` and writes no row.

Why `block(message)` breaks the key. Its key is the bare text `message`. For three refusals behind one wrapper it is ONE key,
so A24 cannot tell them apart. The docstring warns "a refusal added under a message that already has an entry is not caught".
The same wrapping is the t-227 Q4 hazard for `NATIVE_PACKET_UNWRITTEN`.

## B.2 The change, per file and function

**`native_context.py`**: one new function after `pending_path`. Nothing else in this file changes.
```
def launch_pending(root, session, task_name=None) -> bool
```
True when the packet file of exactly this key (`_slot(root, session, task_name)`) exists and its `status` is `pending`, OR
when it exists but cannot be read or parsed, or is not an object (safe side). False when `session` is empty, or when the file
is absent or has another status. It never raises (any exception → True). It reads only, takes no lock and writes nothing. Its
docstring states the error direction (§B.4).

**`inject_context.py`**
1. `note_denial(event, ticket, stage, role, reason, *, name_dispatch=True)`. When `name_dispatch` is False, the story row
   carries `"dispatch_id": None` and `"stage": None`, whatever the arguments. Such a row belongs to no dispatch (by
   `_denial_times`: no id, and no stage to match). Every existing caller is unchanged (default True). The ticketless path is
   unchanged.
2. A new function next to `refuse_native_packet`:
   ```
   def refuse_native_stage(event, ticket, role, root, exc) -> None
   ```
   - Prints `'INJECT: ' + str(exc)` to stderr, byte for byte what `dispatch` prints today.
   - Decides `named = not isinstance(exc, StateConflict) and not native_context.launch_pending(root,
     event.get('session_id'), raw.get('task_name'))`, where `raw` is `(event.get('_qa_host') or {}).get('input') or {}`, the
     same source `stage` keys on.
   - Calls `note_denial(event, ticket, None, role, 'INJECT: ' + str(exc), name_dispatch=named)`, then `sys.exit(2)`.
   - Import `StateConflict` from `event_store` inside the function, the same lazy style as the file.
3. `dispatch`: the `except ValueError as exc:` branch at `:708-710` becomes
   `refuse_native_stage(event, ticket, role, project_root(event), exc)`.

   POSITIONAL invariant: `except OSError` stays FIRST, and the classes are disjoint (`OSError` is not a `ValueError`). So a
   write failure still goes only to `refuse_native_packet` and its waiver pass. A `ValueError`/`StateConflict` never reaches
   that pass, and no person's word passes it. The branch still exits 2 on every path.

**`refusal_registry.py`**
1. `SCANNED = ("stage_guard.py", "inject_context.py", "guard_pre_tool.py", "native_context.py")`.
2. The module docstring SCOPE sentence: "the three hook scripts" becomes "the hook scripts" and names `native_context.py`

3. Three rows in a new block `# --- native_context.py — the native packet staged by the Agent hook`, right after

## B.4 Edges (each with the invariant it protects)

| edge | behaviour | invariant |
|---|---|---|
| CONFLICT "a row for every refusal" vs "recover never closes a pending launch" | every refusal writes a row; the row is NAMED only when nothing of the same key is pending and the exception is not a `StateConflict`; otherwise it is INERT (no id, no stage) | a launch pending under the refused key is never closed as `never_started` on this hook's row (FR-41: closing needs positive evidence) |
| a size or identity refusal, nothing pending | named row → `recover` may close the dispatch unless `dispatch_liveness` vetoes (alive, or a later receipt) | the TP1-15045 purpose: a receipt left `running` by a refused launch gets closed |
| opaque prompt (Codex desktop: `dispatch_id_of` → None) | the row is unnamed with stage None → it belongs to no dispatch (the existing convention of every `inject_context` row) | unchanged class; not widened here |
| no ticket / a ticket that names no story folder | `note_denial`'s existing project-list route | a hook never makes a story folder (CX1-18); the project list is read by no `recover` |
| `note_denial` cannot write | best-effort (existing), still exit 2 | a refusal that cannot be recorded is still a refusal |
| stderr | byte-identical to today: `INJECT: <message>\n`, no `TRAPPED` tail | the outcome does not change (the brief) |
| `launch_pending` raising, or a broken, non-object or undecodable file | True → inert | error direction: toward NOT closing; the cost is a dispatch left to the ordinary liveness verdict |
| `launch_pending` with session empty (identity refusal) | False → named | no key, so no pending launch of this key can exist |
| `launch_pending` for a delivered packet | False | a delivered launch is not pending |
| order of the raises in `stage` (size → identities → pending) | untouched | which refusal an input meets is unchanged |

Error direction of the reused `native_context` packet read, in its new and more consequential role ("pending?" now decides
whether `recover` may close a dispatch): it may err toward "pending" (an inert row; a dispatch then waits for the liveness
verdict). It must never err toward "not pending" for a packet of the same key that is pending or unreadable. Adversarial
inputs that must stay on the safe side:
- a pending packet of the same key (B-3/B-5);
- an unreadable packet (B-6);
- a packet holding a JSON list, which `launch_pending` must treat as unreadable → True;
- an exception inside the read;
- an unnamed launch while the session holds other named packets: `launch_pending` reads the exact plain slot, never
  "the session's only packet", so another launch's packet does not make this one pending. Neither direction is wrong there:
  the exact key is the identity `stage` refuses on.
