# t-015 — spec B-013: the project's own case id form

Designer draft t-015 (Opus), accepted by Lead 29.09 with the decisions at the bottom. PKG =
`ai-packages/qa-factory`. Three dispatches: D1 first; then D2 and D3 (disjoint owns, may run in parallel).

## Design (c): data + form-free detection
1. The id form is DATA the project owns: config key `case_id_form` — a template (`{ticket}` = any ticket key,
   `{nnn}` = the number, everything else literal); string or list. Onboarding writes it.
2. The default form `TC-{nnn}` is ALWAYS recognised as well (0.7.x records, fixtures, mixed stores).
3. The S4 identity check becomes FORM-FREE: it reads every front-matter `id:` in the story's case tree, so a
   case whose id code could not read is refused at S4 instead of passing silently (exit_gate.py:619 globbed
   `TC-*.md` and passed 13877's project-form files without looking at them).

2. Template compile rules: `{ticket}` -> `[A-Z][A-Z0-9]+-\d+` (same shape as stage_guard.py:146 TICKET_RE; cite
   the twin in a comment, do not edit stage_guard); `{nnn}` -> `\d+`, exactly once; `{ticket}` at most once; any
   other `{…}` invalid. Literal parts escaped and may NOT contain `/ : # , [ ] \ * ? " < > |`, whitespace or
   `--` (reserved: area/compound separator, instance separators `::`/`--`/`#`, scope lists, parametrize,
   filesystem). A configured form gets guards `(?<![A-Za-z0-9])…(?![A-Za-z0-9])`. The DEFAULT form compiles to
   exactly today's `TC-\d+` with no guards (backward identity). Case-sensitive for text and cells,
   case-insensitive for file names. Build the regex through an editor tool (FR-29).
3. contract.py: `CASE_ID_RE` / `CASE_ID_ONLY_RE` replaced by wrappers resolving cfg via
   `_project_config(artifacts)[0]`; config read at most once per (resolved path, mtime_ns, size); resolution never
   raises (any error -> `{}` = default). `case_ids(value, artifacts=None)` and `case_id(path)` keep names and
   signatures (case_id: first form match in the file name, else the stem). `split_case_key`, `case_key`,
   `case_matches`, `case_area`, `_case_keys` use `is_id`. `case_files()` (:796) uses `rglob("*.md")` filtered by

   `case_id_example(ticket, artifacts=None)`, `CASE_STORE_DIRS = _STORE_DIRS`. Keep a module attribute

## Edge behavior (all dispatches)
Key absent/""/null/[]/no config: default only, never raises. Before the key exists: project-form stories stay
unreadable (today). After it is written: next call reads it; stored ids never rewritten; TC stories stay
readable. Invalid key: ignored, default only; readiness missing/user; the designer brief prints the problem.
Mixed forms: both recognised, distinct cases; S4 accepts any recognised form. Ids containing the ticket key are
recognised whole; `{ticket}` is any ticket. Reserved characters refused in templates. Name differs from id:
refused at the S4 exit gate. Out-of-project callers: default only.
