## Findings

**B1 (blocks; FG7-76; failure_class spec). The exchange the spec chose is a mutation that `is_the_swap` can never classify as the swap. The probe moves from "anchor not found" to "NOT the swap" (exit 1). It never reaches "detected".**
- `is_the_swap` (driver_golden.py:976-994) needs the control to hold the driver-runs write at `seq` and the `[progress]` stdout record at `seq+1`. It also needs `mutant[seq+1]` to equal that write.
- After the exchange, the code between the two lines (driver_dispatch.py:2332-2333) still runs in both streams. That includes `self.save_state()`, which is `_write_json(... "driver-state.json" ...)` when not dry (driver_core.py:612-617).
- The recorder records every open with write intent except the sink and nul (driver_trace.py:656-731). `driver-state.json` is a `keep_text` file in driver-golden-rules.json:72, so it is not filtered out.
- So the control stream is W, S, G and the mutant stream is G, S, W.
- Scratch proof (`fg776_probe.py` rows 7-8, a pure call with no live file touched):
  - `is_the_swap([W,S,G],[G,S,W],0)` returns `(False, "the control's pair is write then write, not the driver-runs write then the progress line")`.
  - The positive control `[W,G]` against `[G,W]` returns `(True, '')`.
- An extra risk, estimated and not verified by a run: `_write_json` publishes a `.tmp` file and then calls `os.replace` (event_store.py:189-204). That may add its own `rename` record (driver_trace.py:733-738), so `seq+1` would not even hold for an adjacent pair.
- Fix: `is_the_swap` is in this node's owns. Teach it the exchange shape:
  - the control has the driver-runs write at `seq`;
  - k is the first `[progress]` record after it;
  - the mutant has progress at `seq` and the same write at k;
  - the records between are equal;
  - the lengths are equal.
- The alternative is for the Lead to re-decide the mutation. Moving either line next to the other does not help: the S record still sits between them.
- The builder could not see this: no golden exists, so no run reached the classifier. The spec's exchange decision did not name `is_the_swap` as the seam it changes.

**F1 (fix before merge; FG7-34; Q4 / Q12(d), axis 34). The same door's own WARNs (`report["warnings"]`) are still printed only on the commit path.**
- `_resolve_order_known` fills `report["warnings"]` (journal_validator.py:401ff, its docstring lines 6-10):

- The builder's report names this analog and leaves it with no node.
- Fix: one producer `order_known_warnings(report)` that returns `report.get("warnings", [])` plus the count line, called by all three paths (the commit path then drops its own `report.get("warnings")` append), plus one row per path. Or the Lead writes the «Остатки» line with a node.
