## FG7-69 -- verdict: NEEDS WORK (0 blockers, 2 fix-in-round, 1 question, 2 notes)

1. **fix-in-round: a failed diff always prints "workflow check skipped: no message"; the E4 row tests a shape the real
   door never returns.** ci_read.py `workflow_note` calls `gitcmd.git(root, "diff", ...)` without `stderr=True`, so it
   gets `(rc, stdout)` (gitcmd.py:38-49). Git writes "fatal: bad revision" to stderr. `gitcmd.first_line(b"")` returns
   "no message", never "", so `or "git diff failed"` is dead code (Q7). Probe witness (real repo):
   `'no-such-branch-xyz' -> workflow check skipped: no message`. The E4 row fakes `(128, b"fatal: bad revision ...")` on
   stdout, so it passes against an answer `gitcmd.git` cannot produce (Q5b). Fix: `stderr=True`, report
   `first_line(err or out, 120)`, and give the fake the 3-tuple shape.
2. **question for the Lead (fix-in-round if accepted): the ref is resolved locally, but GitHub runs the remote ref.**
   `origin/main...<ref>` reads the local branch `<ref>`. Probe witness (scratch repo, branch pushed and then deleted locally,
   like a cloud `claude/*` branch): `br2 -> workflow check skipped: no message`, while `origin/br2 -> note: nightly.yml
   changed ...`. When a local branch differs from `origin/<ref>`, the note judges the wrong commits. The dispatch prescribed
   the literal command, so I am not calling it a defect. Option: try `origin/<ref>` first, then fall back to `<ref>`.
