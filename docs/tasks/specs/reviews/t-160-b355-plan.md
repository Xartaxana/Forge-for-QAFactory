## A. Findings

**1. BLOCKER — §2 item 2 + item 3 (F-7 (a) with F-2 (b)): "recorded" is a pair-detector without carrier scoping; a word about
one territory silences the hint (and, under F-3 (b), the commit guard and the write window) in another.**
Evidence (read): `test_locations` entries are matched relative to `app_root` (`_config_match(ctx, _rel(t, ctx.app_n))`,
test_locations.py:442); `run.levels` / `roots.test` / `tests_root` relative to the PROJECT root (`ctx.root_p / given`, :402-404).
The template says `tests_root` is "Root of the test repository, relative to the project root ... set when tests live in a repo
separate from the application code" and `code_repos` is the dedicated-test-repo shape with `app_root` their common parent
(references/templates/config.json:9-10, :17-18). Empirics (the stand's real config,
`mybooks-stand/arm-factory/test-automation-framework/qa-factory/config.json`): `app_root "../MyBooks"`, `profiles[playwright-tests].roots.test
"tests"` (the FACTORY's own test repo), `test_locations ["src/**/*.test.ts", "**/test_*.md"]`. So `roots.test` names where the
automator's tests live in the test repo; it says nothing about tests inside the application checkout.
Failure scenario: a project onboarded before item 13, with `test_locations: []` (1c skipped when `--suggest` has no candidate,
p2-interview.md:130) and a profile `roots.test: "tests"` -> `recorded` = (True, ["roots.test"]) -> step 4 skipped for EVERY path ->
an application diff file `src/__tests__/cart.test.ts` (today: markers test + classic folder `__tests__` -> `file_kind` "test") becomes
"production" at the S2 exit gate (one more `derived` row asked), and under F-3 (b) `git commit src/__tests__/cart.test.ts` in the app
checkout is no longer a commit shape (stage_guard.py:2260 -> no rule_pathspec/rule_manifest at :2869-2871). Condition "a word is
recorded" is satisfied by one object (test repo) and applied to another (app code) — rule-15 class. With `app_root "."` the
territories coincide and the same happens to colocated tests.
Fix (one sentence): make the predicate territorial — `recorded(cfg, root, path)` answers for the territory the path lies in
(inside `app_root`: only live `test_locations` entries are the word; inside the project root outside `app_root`: `run.levels` /
`roots.test` / `tests_root`), and say per consumer which territory it asks; this keeps F-7's carrier list but stops the cross-match
(the Lead decides whether this re-opens F-7; I hold that F-7 (a) as written is wrong for the separate-repo shape the template
itself describes).

**2. MUST — §2 item 5 + §3 "nothing recorded -> today, byte for byte": binding a diff to a checkout outside both `app_root` and the
project root kills the generic list in the nothing-recorded world too.**
Evidence: step 4 runs only for `bases = [b for b in (ctx.app_n, ctx.root_n) if _inside(t, b)]`, else `False "outside the project and
the application"` (test_locations.py:463-466); `production` needs `v.test` first (test_files.py:255-257). Today exit_gate /
runtime_probe / user_path_failures pass checkout-relative paths with NO base, so the path is joined to the project root and the
markers apply (exit_gate.py:1531-1539). After item 5 a bound path with `base = ../app` where `app_root` does not cover it (e.g.
`app_root "."` plus `code_repos[].path "../app"`, or `implementation_repos[].local_path` elsewhere) -> every test file of that diff is
production in BOTH worlds. In the recorded world, `test_locations` can never name such a checkout at all (absolute and `..` entries
open nothing, template :7). handoff_check already has this behaviour today (`_production_files` passes the bound base,
handoff_check.py:285-289), so item 5 spreads it to the S2 gate.
Fix: add the edge to §3 and item 4 — when the bound checkout lies outside both bases, step 4 evaluates the markers relative to the
checkout (nothing recorded) and a recorded word that cannot reach it is `unbound` (unknown -> declared default + the doctor names
"app_root does not cover code_repos[...]"); one row per world.
