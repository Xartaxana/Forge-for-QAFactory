## Findings

**F1 (fix before merge) — the deny list hand-copies part of a table the same file already has, and misses the rest.**
`host_adapter.py:460-463` `WRITER_HEADS` lists python/bash/pwsh/env/xargs/nohup/eval/iex/... by hand. The same
`launch-causes.json` already holds the factory's launchers: `run_forms.launchers` (:56-71: time, nice, timeout, coverage,
yarn, pnpm, bunx ...), `wrappers` (:6-17: poetry, pipenv, pdm, hatch, uv, bundle, npx, uvx, xvfb-run) and `run_forms.shells`
(:73-86). Its one reader is `hooklib.run_forms()` (`["launchers"]`, `["shells"]`, hooklib.py:1241-1276), which stage_guard
already uses (stage_guard.py:1936, :2004). The copy leaves out time, nice, timeout, coverage, yarn, pnpm, bunx, poetry,
pipenv, pdm, hatch, uv, bundle, npx, uvx and xvfb-run. Probe (rows patched in, worktree code):
- runner guard, `runner_mention += timeout, uv, fd`: `timeout 600 python run_suite.py --request r.json` was launch=True and
  becomes **False**. The same happens to `uv run python run_suite.py` and `fd x -x python run_suite.py`. A table row turns
  the runner guard off.
- read guard, `role_read += <row>`: `timeout 5 python x.py`, `rm -rf work`, `cp a b`, `Copy-Item a b`, `make all`,
  `npx evil`, `git -c core.pager=python log` and `fd . -x python x.py` all PASS `_read_refusal` for a role without Bash.
  The aliases of cmdlets the list does name (`icm`, `saps`, `start`, `sc`, `ac`, `ri`) also pass.

The card requires that "a table row adding a writer to the read heads" stays refused. The spec says "a head named in the
table that is also a launcher (python, bash, pwsh, node)": those four are examples of a class, and the factory's own data
names the rest of that class. The name `WRITER_HEADS` does not match what the list holds (mostly launchers, plus four
writers). The about text (launch-causes.json:101: "so is a program that runs other programs or code") promises more than the
code does.

Fix: build the deny set from the in-code list (kept, so a broken table cannot open it) ∪ the keys of
`hooklib.run_forms()["launchers"]` and `["shells"]` (that reader already joins `wrappers` and has its own fallback floor)
∪ a writer/deleter list: rm, del, erase, rd, rmdir, cp, mv, copy-item, move-item, new-item, rename-item, tee-object, mkdir,
touch, dd, plus the aliases of the cmdlets already listed (icm, saps, start, sc, ac, ri, ii). Rename it, for example to
`_NEVER_READ_HEADS`. Make the comment and the about text say "a launcher or shell of `run_forms`, or a listed writer". The
about text should also state the coupling: "a head that can run a program through a flag or a script (`fd -x`, `git -c`)
needs its `reader_runs` row in the same edit". Add the test rows `timeout`, `uv`, `rm` and `Copy-Item` to the "writers are
never read heads" rows, in both lists.

**F2 (fix before merge) — a second road to read launch-causes.json for the guard, and it skips rows silently.**
The guard's tables in this file (`run_forms`, `wrappers`, `reader_runs`) are read through `hooklib.run_forms()`. That reader
names every skipped item in `run_forms_problems()`, and the shipped data is held at zero problems by
`tests/test_run_forms.py:89` (k1). `head_rows` (host_adapter.py:466-485) reads the same file through `load_ref_json` and
drops a bad row with no record. Suppose a shipped row is `cat.exe`, `rm` or `Get-Item ` (trailing blank). The row is lost.
Nobody is told (FR-4: an informed pass, not a silent one). K6 "the real table keeps today's heads" still passes, because the
floor equals the table. A row that would never take effect therefore reaches a release. This is the one-road (P31/AR-13)
residual of this diff.

Fix, preferred (the Lead widens owns to `scripts/hooklib.py`): load `reader_heads` in `hooklib._load_run_forms` next to
`_load_reader_runs`, name each skipped row in `problems`, and let `head_rows` take the parsed section from `run_forms()`.
stage_guard then needs no `host_adapter` import (that import adds about 13-15 ms per stage_guard import, see the trail).
Minimum fix inside the current owns: one shipped-data row in test_role_policy_reads, "no row of the real `reader_heads`
table is skipped" (both names), mirroring test_run_forms k1. In both cases the SIBLING_MAP row "The walker and the shell
table" (docs/SIBLING_MAP.md:284) lists `reader_heads` among the launch-causes.json tables and names its reader. That line is
outside the builder's owns: a Lead edit or a widened owns.

**F4 (fix before merge, minor) — `_is_reader` claims, and its test checks, an input no caller passes. It also does not say why
it differs from the one name normalizer.**
The docstring at stage_guard.py:2596-2597 says "A name holding a path is none". The test row `/usr/bin/rg`
(test_stage_of_dispatch.py:329) checks exactly that. Both call sites (:2613, :2625) pass `_reader_head(...)`, which takes
`Path(..).name.lower()` first (:2589-2591). Probe: `/usr/bin/rg run_suite.py` and `./cat run_suite.py` give
`_launches_runner` = False (exempt mention). The Lead's answer ("path stripping is outside the card") holds for behaviour. The
guard detects mentions: a script that hides the runner's name passes it anyway. The text and the row still claim a
protection that does not exist. Separately, `hooklib._name` (hooklib.py:1299, used in stage_guard as `_program_name`, :1901)
is the package's one "basename, lower, one executable suffix off" normalizer, and it also strips `.cmd/.bat/.com/.ps1`. Not
reusing it is the safer choice, because those suffixes are scripts a role can write. That reason must be written down.
Fix: docstring along the lines of "the caller (`_reader_head`) has already taken the path off; only `.exe` comes off, unlike
`hooklib._name`, because a `.cmd/.bat/.ps1` reader may be a script a role wrote". Remove `/usr/bin/rg` from the non-reader
row, or replace it with a junction row that pins today's door behaviour (`/usr/bin/rg run_suite.py` → mention), so a later
change shows up.
