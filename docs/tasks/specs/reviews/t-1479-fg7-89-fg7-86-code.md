## Findings

### FG7-89

**F1 (fix) -- E14 is broken for the verdict trigger: a quoted or heredoc mention of the verdict command fires the WARN.**
`tools/hygiene_gate.py.next:1988` calls `_worker_verdict_call(command)` on the RAW command, and that function scans
`dod_track.python_program_spans` over the whole text, with no mask. Card E14 says: "a heredoc commit body naming
`journal_write.py accept`: no trigger -- recognition runs on hygiene_gate's masked statements". A probe of
`_coordinator_read_trigger` from the `.next` copy, with a payload that has a transcript and no agent_id, shows the gap.
The commit recogniser handles these cases correctly:
- `echo "python -B tools/journal_write.py accept t-1"` -> `'verdict'` (expected None)
- `cat <<EOF` + body `python tools/journal_write.py accept t-1` -> `'verdict'` (expected None)
- `git log --grep "python tools/journal_write.py accept"` -> `'verdict'` (expected None)
- `git commit -F - <<EOF` + the same body -> `'verdict'` (expected `'commit'`)
- for comparison, `echo "git commit"` -> None (correct)

Error direction: this is only WARN noise (E14's second half), so it does not block. But the report does not name the
deviation, and the hygiene table (COORD_ROWS) has no verdict-heredoc row: `heredoc-body` uses `git commit`.
Fix: in `_coordinator_read_trigger`, feed the verdict recogniser the heredoc-stripped text (`_scan_heredocs(command)[0]`),
or the statement slices `_commit_road` already computes. Add one row (`cat <<'EOF'\n...journal_write.py accept\nEOF` ->
no line). Leave the worker deny alone: see R2.

**F2 (fix) -- `_commit_road` is a second statement walk, tokenizer and git-global-option parser in the same file (Q6,
SIBLING_MAP axis 11; Q7).** The new `tools/hygiene_gate.py.next:1937-1976` (`_STMT_WORD_RE`, `_base`,
`_GIT_OPTS_WITH_VALUE`, the assignment skip, the global-option loop) redoes work the gate already does on every command
in `_collect_signals`:
- `_Walker.run` (live `hygiene_gate.py:1230-1250`) already splits the masked statements, tokenizes each one with
  `_tokenize` (:428), skips assignments, and names the program with `_cmd_name` (:460, the same as `_base`).
- For `cmd == "git"` it hands `args` to `_rollback_form` (:733-750), which already skips `-C`/`-c`/`_GIT_FLAG_GLOBALS`/
  `--git-dir`/`--work-tree` to reach the verb.

Axis 11 lists hygiene_gate's recognisers as "new recognizers of this axis". It does not list a second private
tokenizer inside the gate. The builder noticed this analog but did not widen the fix.

Q7: `_commit_road` has 4 nesting levels (for -> elif -> while -> if, the `-X`/`-W` skip at ~1966-1972).
Fix: have the walker record a `commit_road` signal next to `rollback_forms` (`cmd == "git"` + verb in
`COMMIT_GIT_VERBS`; a python program whose first positional is `wave.py merge`), and have `_coordinator_read_trigger`
read `sig`. The card already puts the layer "after `_collect_signals`" (E16). If the Lead prefers, the Lead can open a
convergence node with an id instead (the Q4 exit). The decision is the Lead's.

`tools/forge_metrics.py:1292` does `bucket = "outside" if ids else "no_task"`, but `header_ids` can return
`{"feature": "F19"}` alone (`dispatch_manifest.py:872-904`). Probe:

(feature,node,task) 5, () 3. Fix: `bucket = "outside" if ("task" in ids or "node" in ids) else "no_task"`, plus a
`feature: F19`-only refusal added to the `refused_then_passed` row (no_task 2).

**F6 (fix) -- the positive print `; other failed Agent calls F` has no row (Q5 (c)).** `forge_metrics.py:1499` is a new
render branch at the CLI door. NC_CASES asserts `totals.failed == 1` (data). The one render row
`refused_cell_and_cannot_judge` (`test_forge_metrics.py:1495`) asserts only that the text is ABSENT. Fix: add one failed
Agent call to that row's `mains` and assert `"; other failed Agent calls 1"`. The existing absent-check can go to a row
without failures.

**R5 (remark) -- a row whose agents are all unscanned shows `refused cannot judge` even when refusals for that task were
