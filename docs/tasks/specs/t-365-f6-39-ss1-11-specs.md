### 1.2 Part A2 — archive-ref expiry, detached re-read, honest prune summary (points 1, 4, 6)

Changes:

A2-1 (point 1, F-A1 (a), Lead 13.11.2026: N = 30 days and reachable from `origin/main`). New constants: `ARCHIVE_KEEP_DAYS = 30` and `ARCHIVE_SAFE_REF = DEFAULT_REF` (`origin/main`).

New `expire_archive_refs(git, root, now, rep, *, apply)`, called from `sweep` after the prune/branch block (`:765-782`) and before the orphan-scratch lines. It runs only when the pass was not `stopped` and was not refused. Steps:
- (a) `git for-each-ref --format=%(refname)%09%(objectname)%09%(committerdate:unix) refs/worktree-sweep/`.
  - rc != 0 → one line `KEEP archive refs: cannot list (<first line>)` and return.
- (b) Resolve `ARCHIVE_SAFE_REF` with `rev-parse --verify --quiet <ref>^{commit}`.
  - It does not resolve → one line `KEEP archive refs: <ref> does not resolve -- none expired` and return.
- (c) For each row:
  - Keep silently when the date field is empty or not an integer (a non-commit object), or when `now - date <= ARCHIVE_KEEP_DAYS*86400` (strict `>` to expire).
  - Otherwise run `merge-base --is-ancestor <sha> <safe ref>`:
    - rc 1 → keep silently.
    - any rc other than 0/1 → count it in `unknown`.
    - rc 0 → candidate.
- (d) With `apply`: for each candidate, `git update-ref -d <ref> <sha>` (the old-value guard: a ref that moved since the listing is not deleted).
  - rc != 0 → one line `KEEP archive ref <ref>: delete refused (<first line>)`, not counted as failed.
- (e) One summary line before the final summary:
  - apply: `archive refs: <E> expired (in <safe ref>, committed more than <N> days ago), <K> kept[, <U> unknown]`.
  - dry run: `archive refs: <E> can expire …`, and nothing is deleted.

The module docstring gets one paragraph (review A-5): the rule; "N counts from the archived commit's committer date, not from the merge, so a commit made long ago and merged today expires on the first run after the merge; reachability from origin/main is the only guard; a later rewrite (force-push) of main that drops an expired commit is the accepted residual (the commit then lives only in the reflog of `refs/remotes/origin/main` until gc)"; and "an archive ref of a commit not in origin/main is never expired (a patch-equal or unmerged archive stays: cost is space, never a commit)".
