## What was built

`module_facade.install(name, parts)`. Standard library only, ASCII, English.
- `sys.modules[name]` gets `__class__` swapped to a per-install `ModuleType` subclass; module object, `__name__`, `__file__`,
  `__doc__`, `__spec__` untouched. Works for `name == "__main__"`.
- READS: class `__getattr__` does a plain loop over the part dicts (`dict.get` with a sentinel, no allocation), LIVE. A
  pre-existing module-level `__getattr__` is POPPED from the facade dict at install (the interpreter would call it before the
  parts otherwise) and called AFTER the parts. Unknown name: `AttributeError("module '<name>' has no attribute '<x>'")`.
- RECORDED SETS (edge 3): per part, `set(part dict) | co_names` of the module code and every nested code object (recursive over
  `co_consts`), minus module-machinery names. The code comes from `part.__spec__.loader.get_code(...)` (cached bytecode when it
  exists, so install is cheap); a part with no source loader -> ValueError naming it.
- WRITES: under a lock, into the facade dict if it binds the name (or if no part holds it: the name is then created in the
  facade dict), and into every part whose recorded set holds it. DEL: from the same places where present; AttributeError only
  if bound nowhere.
- ROUND TRIP (edge 4): the first write of a name stores a shadow (what getattr read, the facade's own binding, each holder
  part's binding or "none"). A later write of the object that getattr had read (mock's `setattr(original)`), either directly
  (local path) or after mock's `delattr` (non-local path), restores every place to ITS original and drops the binding from a
  place that had none (a builtin only read). The shadow is used only if every place still holds what was written last
  (otherwise someone else rebound it and the shadow is stale: a plain write). Nested patches and two patches in a row work.
  A deleted created name (read was "none") leaves no trace.
- `dir()`: facade names + every part's bound names (machinery names of parts excluded), sorted, unique.
- install refusals (ValueError naming the thing): module not imported, part not an imported module, facade itself as part (object
  or name), part given twice, second install on one facade.

## Deviations / decisions worth the coordinator's eye

1. Edge 3 says `delattr` removes from the same places where present. Kept literally. The ROUND TRIP rides on the shadow
   instead: after a literal del the following write of the read-original restores per place. A plain
   `facade.n = v; del facade.n` therefore removes the binding for good (literal), BUT a later plain `facade.n = <the object
   getattr had read originally>` while the shadow lives restores per-place originals instead of writing everywhere (only
   differs for a name held by two parts with DIFFERENT objects, or a part that merely reads it).
2. Module-machinery names (`__spec__ __file__ __doc__ __all__ __path__ __builtins__ __cached__ __loader__ __name__ __package__
   __getattr__ __dir__ __annotations__`) are never forwarded from parts and never fanned out to parts (my addition: a part's
   `__all__` must not make `from facade import *` change meaning). Spec silent; flagged for acceptance.
3. Exception class for install refusals (edge 11 says ValueError; "install twice is an error naming it" gave no class): I used
   ValueError for both. Empty `parts` is allowed (no spec text; harmless).
4. `__getattr__` pre-existing is removed from the facade dict at install (so `facade.__getattr__` no longer resolves as a
   plain attribute); behaviour of `stage_guard.UNRESOLVED_REASONS` is preserved through the chain (row "chained pre-existing
   __getattr__").
5. `co_names` is taken from the loader's code (not by walking function objects) so module-level lambdas in data structures
   are covered; this reads/compiles each part once more at install (bytecode cache makes it an unmarshal).

## Cases where a patch reaches FEWER call sites through the facade than on a single module today
- the facade's own code reading a BUILTIN as a free name (`open(` inside `main`): `facade.open = fake` does not reach it
  (the facade binds no `open`; spec edge 3 writes the facade dict only for names it binds). Fixable by recording the facade's
  own `co_names` too -- not done, spec.
- a name a part reads/binds only through a string (`globals()["x"]`, `getattr(sys.modules[__name__], "x")`, `vars()`/`eval`):
  not in `co_names`, never fanned out.
- a part imported after install (lazy `import part` inside a function), or a name a part binds later only through `globals()[...]=`.
- a part that rebinds a name through `global` after a patch (`global x; x = ...`): the facade's own from-imported copy of it (edge 6)
  and any other part's `from part import x` copy stay at the old object (as a from-import copy does today).
- a class-attribute patch on a split class (`setattr(Controller, m, ...)`) -- not a module write, not handled here (spec E4/R-A7).
- `from facade import x` copies (edge 7, today's behaviour, by design).
