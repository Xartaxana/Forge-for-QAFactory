## Root cause in one sentence

The RN1-8 fix of 0.10.9 made `fires_on` read the failure body line by line, but the detector row it reads (`references/detectors.json` `assertion_probes.typescript`, pairs T1/T2, line 247-248) still demands the prefix `Error: ` in front of `expect(locator|page|response)...`; a real Playwright report whose assertion carries the author's message (`expect(x, 'msg')`) prints `Error: <msg>` and then an unprefixed `expect(locator).not.toBeDisabled() failed`, so every UI (locator/page) test is `incomplete / cause: data_row`, while API tests (`expect(received)`, where the prefix is optional) pass. The fix was proved on the API shape only (fixture and samples invented from `cart.spec.ts`), and its live proof row never ran.
