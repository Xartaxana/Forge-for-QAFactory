## Decisions I took inside the spec (flagged)

- Cross-file rule realised per file. `_scan_wide` scans one file at a time, so "every call in every scanned file bound to detector_verdict" is implemented where the call stands: each file's scan records the literal of its own bound calls (`transport: check_id`), or a `check_arg` walk error whose `why` starts "the check of refusal() must be a literal". `_passthrough` on the constructor def itself returns `[]` (no records, no error: zero call sites is not an error, §3.2 item 4). Same observable result as §3.2 items 2-5; a same-name function elsewhere, a comment, a string, `getattr(...)` and a module not bound to detector_verdict give no id (rows `refusal-unbound/*`).
- `spoken(Record)` with an empty `check`: the check line is omitted (the spec says `check: <id>` and is silent on an empty id). A Record with no check, no expected, no door prints its text unchanged.
- `refuse` order for a Record: problem line, `expected`, `door`, today's card lines, "if you cannot", check LAST (parent §2.4 order; §3.1 T2-7 says "plus", not where).
- A sentence-less row is detected as "neither `requirement` nor `requirement_from` is a non-empty value" (not through the private `_states_requirement`); then `expected` = "" and the row's door is used.
- `hooklib.block` imports `detector_verdict.spoken` lazily and falls back to the message as it was on `ImportError` (hooklib has no import of detector_verdict today; a copy without it must still block).
