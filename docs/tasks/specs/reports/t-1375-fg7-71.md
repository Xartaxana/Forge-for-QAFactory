## Decided differently from / beyond the plan (please confirm)

1. If `obj["session"]` is present but fails `journal_hooks.SESSION_RE`, the env session is used instead ("first valid of
   the two"). The edges line does not name a malformed obj session.
2. Prune happens when `next` runs, not when `write_event` appends. Once an id is in the journal, `_check_reserver` is never
   consulted for it, so the effect matches "dropped once its id appears". The physical drop waits for the next `next`.
   Pruning is against the calling worktree's journal only. The file sits in `<common>/forge-journal/` beside the counter, so
   it is shared by all worktrees of the clone; an id used in another worktree's journal stays until the cap drops it.
3. A failed save of `reservations.json` in `next` is a WARN note on stderr and the ids are still issued: they read as "no
   record" (accepted as today). `next` is never refused for this.
4. Ids reserved with no session are recorded as `[id, null]` and count toward the 500 cap.
5. File form: `{"reservations": [[id, session-or-null], ...]}`, oldest first.
