## Interpretations and deviations (the Lead decides; each is one line to change)
1. Key: the spec text says `repr(sorted(kwargs))`, which sorts only the NAMES and drops the values, so two calls differing in a kwarg
   value would share a key. Built as `repr(sorted(kwargs.items()))` (sorted by name). Spec defect, not a design choice. Row "kwargs values make distinct keys".
2. `run(..., label=)`: the body of `run_scenarios` has no use for a label, and the spec does not say `run` calls `harness.finish`. The label is used only
   in the no-match refusal text; `run` does NOT call `finish` (adopters do, as today). Question: should `run` end with `finish(label)`?
3. "Dead world: the next entry builds fresh": built as discard the dead world (root and pristine deleted) and BUILD IT AGAIN as the key's shared
   world (the one note line, naming the root path and the first differing path, is printed when it dies). The alternative (one unshared entry, key stays dead) is not built.
4. `QA_SCENARIO_ORDER`: only the value `reverse` reverses; any other value (a typo) is file order, silently. Question: should an unknown value be refused?
5. Argv: every `sys.argv[1:]` item is a name (flags are not filtered); EACH name must select something, else exit 2.
6. `reads` world also guarded when the scenario raised (the guard runs in `finally`); `fresh` worlds also get `build.world_enter` called; `world_caches` is called
   only on a SHARED in-process `mutates` entry.
7. Validation (mode, `why`) raises when `world(...)` is CALLED, not at `with` entry; "build has no root" raises at entry (the build is lazy).
8. The scenario name in the guard line comes from the thread-local the runner sets, else from the caller's function name (`sys._getframe(1)`).
9. The `in_process` flag is a keyword of `world`, so a build kwarg of that name cannot be passed (same for `mode`, `why`).
10. The note line, the guard line and the downgrade lines are `print`/`harness.check`; downgrade lines print at the end of `run`.
11. The symlink row (edge 9) could not create a symlink on this Windows machine (no privilege): the row printed a note and checked nothing HERE. It will
    check on Linux CI. The module code for symlinks (`link:<target>`, `copytree(symlinks=True)`) was not exercised in this run.
12. Side-by-side order under `reverse` is checked through `select` (pure), not through the pool: pool start order is not a contract.
