## Deviations from the spec / Lead decisions to confirm

1. `left_gap_line` cuts `what` at 200 characters (`FIRST_REASON_LIMIT`); the dispatch says "through `left_gap_line`" AND "the word WHOLE, no cut". The two conflict.
   Resolution (mine, to confirm): `what` is built with a sentinel where the word goes, `left_gap_line` assembles the line, and the whole word replaces the sentinel afterwards.
   `by`, `ts` and the table words are bounded (30/30/50) so the sentinel always survives the cut.
2. Signature: the spec says `_word_passed_gap(art, facts)`; `facts` holds neither the trace rows nor the raw ledger (`coverage`, `rows`) nor `pipeline`, so it is
   `_word_passed_gap(art, entries, ledger, manifest, pipeline, unknown)`.
3. Sources: the spec lists "a ledger record with the suffix". Reading the suffix text would be reading wording (FR-12); the report asks the typed question instead
   (ledger `not_executed` row -> instance -> `index.instance("not_run", iid)`, the same reading as `check_delivery._no_run_word_suffix`). The "obligation with `word_passed`" is read from
   `ledger["coverage"]["obligations"]` (the projection `ledger.py` stores), not by calling `coverage_projection`.
4. "ONE line per (case/instance, Then) when annotated by trace and ledger": a ledger record can only annotate an INSTANCE (not a Then), so the pair cannot meet on one key; a Then line comes only from
   the trace row. (If the Lead meant a not-run instance whose Then also has a trace row: they are two different facts, two lines.)
5. A pass for `then_unbound` / `not_run` / `row_fields_unestablished` that NO reader annotated (an old line without `subjects`, E4; a row field other than `obligation_refs`) prints no line
   (spec: "one line per pass a reader annotated, or of fact other/s5_plan_unread"). The word of such a pass is therefore not shown anywhere in the report. Lead to judge whether that is the wanted direction.
6. `facts["word_passed"]` is present on every build (`""` when nothing is recorded), so the key pin in `one_source_per_count` changed (+ `word_passed`); the rendered report is byte-identical (pinned).
7. `test_report_facts.py` and the changed lines were run in full ONCE although the file is slow (it is the DoD's file and `scenario_walk` does not print it); the dispatch's "slow files are not run locally" is
   otherwise kept.
8. The Edit tool turns a single-backslash `\uXXXX` in my text into the real character; non-ASCII was therefore avoided with `chr(0x2014)`, `chr(0xE000)`, `chr(0x2026)` (checked: 0 non-ASCII added lines).
