## What changed per function (tools/journal_validator.py)
- `ORDER_KNOWN_RE`, `order_known_tokens(notes)`: `order-known:(\S*)`, same parse as `closes:`/`replaces_worker:`; notes not a string -> [] (base-field check owns it, no second refusal).
- `validate_new_lines(..., order_report=None)`: pre-pass collects ts and tokens of THIS file only (head + new; `seed_lines` = another file, never read for tokens); the 3 sites (id novelty, repeated delegated with no legal reason, ts not monotone) record a mark; the end calls `_resolve_order_known`.
- `_resolve_order_known`: declared = a token with equal ts on a strictly LATER line; dropped from violations. Undeclared: original text kept + door text. Token on a NEW line naming no earlier line -> refusal "names no line"; naming only lines with no order defect -> WARN; empty -> WARN and ignored. Tokens on HEAD lines are not judged.
- `decide(..., order_report=None)` passes it through; `decide_with_warnings` adds the WARNs and the summary line `order-known: N declared (...)` (only when N>0).
- Module docstring: rule 19. Not declarable (unchanged refusals): reopen of a closed task, fabricated replaces_worker, accepted/rejected orphans.

## journal_echo
It calls `journal_validator.decide(disk_text, head_text, now, seed_text=...)` (journal_echo.py ~line 2372), which runs `validate_new_lines`, so a declared defect is accepted at the write moment for free; no edit needed. It does not see the WARNs or the summary count (decide only), as with the feature/node WARNs. Caveat: a defect written BEFORE its token line is written shows as a violation at the write moment of the defective line (the token does not exist yet) and clears when the token line lands.
