How it works (edges 1-12 of the dispatch, in the order given):
- Segment = definition + decorators + the comment block directly above it, sliced line by line from the source text; its sha256 is
  the (d) witness. A comment block separated by a blank line is a "free chunk": it goes into the part that receives the first name below.
- Header of a part/common: the source's own import block reduced to the names the file uses (name use found with `symtable`, so a local
  variable is not a use), original order, `sys.path` lines kept as written, plus `from <common> import <names used>`. A name homed in a part
  and used by another part, or by common, is refused with ONE line per (name, user) listing the source lines ("home it in common").
- Runner: recognised shapes are (1) `run_scenarios([..], [..])` with literal lists, (2) a `main()` of direct calls (and `sys.exit(f())`),
  (3) a module-level `for` over a literal list or over a run-list NAME, (4) an `if __name__` block, several blocks per file; a run list read BY NAME
  (`SCENARIOS` + a loop or a `main()` with an argv filter) is regenerated restricted and its consumer copied as written (so the argv filter
  stays). Any other runner statement is refused with `file:line`. Every part gets the runner restricted to its scenarios, original order,
  list membership kept, `finish("<label><part suffix>")`.
- Unreached function (no run list, nothing uses it, no importer): listed as `UNREACHED:`, moved with its section, never added to a runner.
- `--shim`: found importers by real import nodes (`import x as A` -> `A.name` uses; `from x import n`), refuses `shim:false` when an importer exists and
  `shim:true` when none does; shim has `__all__`, no `test_*`, no check, prints a note, and with `--all` runs the parts in order as children.
- Proof (a)-(e) printed by dry-run and apply, computed from the bytes that are (to be) written, re-parsed and re-segmented independently of the plan;
  `--apply` writes temp names, re-reads them, proves again, then renames; any failure leaves the tree untouched.
- Re-run after a complete apply: "nothing to do" (exit 0); a target that exists and differs from what the map generates: refused.
- `--draft` prints a JSON map with every `home` empty; keys starting with `_` (`_line`, `_section`, `_runs`, `_world`, `_notes`) are comments
  and are ignored by `--map`; the summary line goes to stderr.

### Map format, one filled example (the fixture of the first test case)
```json
{"source": "test_demo.py", "common": "demo_common", "shim": false,
 "parts": ["test_demo_a", "test_demo_b"],
 "names": [{"name": "TASK", "kind": "assign", "home": "demo_common"},
           {"name": "helper", "kind": "def", "home": "demo_common"},
           {"name": "a_one", "kind": "def", "home": "test_demo_a"}, {"name": "a_two", "kind": "def", "home": "test_demo_a"},
           {"name": "b_one", "kind": "def", "home": "test_demo_b"}, {"name": "b_two", "kind": "def", "home": "test_demo_b"},
           {"name": "never_run", "kind": "def", "home": "test_demo_b"}],
 "statements": []}
```
`statements` holds `{"line": N, "home": ...}` for module-level statements that are not definitions. Runner names (`main`, `SCENARIOS`, a runner
loop variable) get NO row (a row for one is refused). `common` must be the source stem without `test_` plus `_common`; parts must start with `<source stem>_`.

## 4. Deviations, decisions the spec did not state (flagged, not silently closed)
- D1 (reading of edge 8): an ASSIGNMENT is a census name (it has its row in `names`) and is NOT also required in `statements`, even when its right side is a call; only non-definition, non-assignment statements need `statements`. A call-bearing assignment that touches the world/disk/cwd gets the WARNING. If the owner wants "a constant built by calling a function" refused until placed, that is a one-line change.
- D2 (shim run): the shim runs the parts only with `--all` (spec 2.2 and the precedent `test_story_step.py`); edge 7 reads "when run directly runs the parts". Without `--all` the shim prints a note and exits 0, so a canon that runs the shim file as a data_join row does not run every part twice. Question for the coordinator: confirm.
- D3: `common` name and part prefix are enforced (rule 2.1): `common` = source stem without leading `test_` + `_common`; parts start with `<source stem>_`.
- D4: the common module is written only if some name is homed in it; the shim's `shim:true` with no importer is refused (2.2 "iff").
- D5: a link (an entry in a runner block that names another runner function, e.g. `if __name__` -> `main()`) is repeated in every part that holds the runner; the proof counts only scenarios, not links, in the multiset union, and checks every part's sequence is a subsequence of the source's.
- D6: generated runner blocks of the module-level kind carry a marker comment `# split: runner piece N`, which the proof reads back to align blocks with the source.
- D7: `--draft` exits 2 when it finds a construct that would be refused whatever the map is (unrecognised runner, mixed newlines...) and still prints the map; summary to stderr.
- Spec vs reality: spec §2.6's note that `import a, <stem>` forms do not exist is not relied on; the tool reads real import nodes (AST), the regex form is only a cross-check warning.
