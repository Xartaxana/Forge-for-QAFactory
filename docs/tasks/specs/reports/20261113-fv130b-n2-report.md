   of the case. `_row` now copies `word_passed` only when the outcome has it; `_signature` appends the finding id only when it has one, so every other outcome is

   `unconfirmed_expectation` item from the case's own question (`_unconfirmed_to_check`) after the record's `to_check` was kept. The RECORD carries "Then 2 of TC-001:
   <text>" and the item carries the `how` ("passed by your word at S5 (<ts>): no test is bound to it") and counts; the item's `to_check` reads "confirm the expectation: ...".
   The branch is unreachable under F4 (a); making the (b) switch ONE data row needs one more edit in `build_left_items` (a question for the Lead, not made).
3. **R4 interpretation.** "A row whose cases include an instance named `not_run`": I read the instance of the row as the row's own `ref` (a non-plan row) or the manifest
   tests whose `plan_row` equals the ref (a plan row), and add the suffix only when the row's state prefix is `not_executed` (the fact must stand as the ledger shows it, E6/E8).
4. `Story.then_outcome`: the word row is made only when `not bindings` (a Then with a binding row of any status, even a covered one whose instance is unknown, is never
   annotated: E24); `index.then` gets the story's `case_config` as `cfg`.
