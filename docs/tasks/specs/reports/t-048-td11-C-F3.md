# t-048 / TD-11 node C-F3: split-keep and its K5 door

## Built (tools/test_quarantine.py, tools/test_test_quarantine.py only)
- `cmd_split_keep` + parser entry `split-keep OLD --into P1,P2 [--shim] --reason TEXT [--root]` + usage line in the module docstring.
- Every refusal is computed before any write (`Refusal`, exit 1, text `split-keep refused: <what is wrong> -- <expected / door>`): OLD not keep; `--into` empty or with an empty name; duplicate part; blank reason; part equals OLD; part a quarantine name ("a quarantined file never returns"); part already a row of keep / quarantine / pin_holds; part not on disk under scripts/tests; no `--shim` and OLD on disk; `--shim` and OLD missing.
- Writer: the existing `_write_layers` (indent=1, trailing newline). Parts are inserted in the place of OLD in the keep section (no shim: OLD removed; shim: OLD stays, parts follow it). Each part = copy of OLD's row (same key order), `why` + ` (part of OLD split, TD-11c)`; `covers`, `named_by`, `replaced_by`, `layer` copied whole. Shim row: `layer: data_join`, `why: "split shim: re-exports for importers; checks live in P1, P2"`, `covers: ["tests/<OLD stem>_common.py"]`; its other keys (`named_by`, `replaced_by`) are left as they were.
- Message file `ci-out/keep-split-msg.txt` (same `_write_msg`/`_gate_lines` as drop-keep), exact text for `split-keep test_k.py --into test_a.py,test_b.py --reason "slow file"`:
```
keep-split: test_k.py -> test_a.py, test_b.py -- slow file

architecture: AR-14 -- a keep row is split only by split-keep, the one writer, with the reason in this message
judgment: none -- the person gave the reason (--reason); the tool copied the row to each part and judged nothing
axes: not a mechanism (a data move made by tools/test_quarantine.py; the mechanism block is in the TD-15.6a commit)
piles-skip: TD-15 -- the owner's word 10.11.2026, docs/tasks/test-diet.md
```
- K5 (`check_history`): new door regex `keep-split: OLD -> P1, P2 -- reason`. Accepts a removed keep row when its OLD has such a line and every named part is a keep row in that commit. Refused with a message naming the part: a line whose part is not in keep; a line whose OLD was neither removed nor (shim) had its `layer` changed. `keep-drop:` and `quarantine-enter` branches unchanged; a bare removal is still refused with the old text; a layer change with no line stays as before (accepted, nothing new). Quarantine-edit check untouched.

## Deviations / questions
1. `--layers PATH`: the siblings have no such option; the registry path is fixed (root + LAYERS_REL) and they use `--root`. I followed the siblings and did NOT add `--layers`. If wanted, say so.
2. Temporal (edge 6): run before the part files exist -> refusal "part X is not on disk ... create the part files in this change first". Run on the tree after the node deleted the old file (no shim) or kept a shim file (--shim) works (tested).
3. A shim row keeps the OLD `named_by`; E4 says a carrier must not name a shim, so hand re-pointing is still needed (not decided here).
4. `status` was not touched; the K5 door does not check that the old file was deleted in the commit (spec did not ask).
