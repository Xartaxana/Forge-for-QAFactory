- A run aimed at a reference stand (the stand that runs the OLD version of a side) is no longer refused: it goes, and it is recorded as a sample. Its run block carries a `reference_run` mark (the stand, the side, "not the story's code") and is written to `work/reference-runs`, never to `work/run-blocks`, so the reducer, the ledger, the proof stamp and the delivery verdict never read it as the story's evidence; the report names it ("a run on the reference stand - a sample, not the story's result") and counts it apart. A reparse of a sample stays a sample. A run block with no mark (older runs) reads as the story's own stand, as before. The record that names the story's own stand ALSO as the reference of a side is still refused at validation and at `run_suite.py --request` entry (a data contradiction, with the record as the door). Read through `stand_identity.reference_run_mark` and `stand_identity.reference_runs`.
- Every test the report shows now says whether its result came from real code or from a mock. `ledger.real_or_mock` writes the words on each ledger test row (`real_or_mock`): `real code`; `on a mock: <side> — kept by the person's decision (date not recorded)` for a test with a `kept_by_decision` row (the row carries no date field, so none is guessed); `on a mock: <side> — the side was substituted` for a test proven while its side was substituted (each mocked side is listed); `real or mock: not established` for an unreadable stamp, `sides_unknown` or an unreadable `provisional` field (an unknown is never `real code`). The `## Proven` lines carry it, a green stays green, and the check that holds the report against the ledger (`check_report_left_with_you`) names a test line with no mark, and a ledger that names a mock the report never mentions. A ledger written before the field existed is not checked. The scribe's `Left with you` form names the field for each test an item lists.
