- New capture step `fill-new-account <selector> user|secret [template]`: the agent makes a new account through the app's own sign-up form on a stand whose config row records `safe_to_break`. `user` generates the pair, records it and types the name (the template defaults to the data row `generated_user_template`, `{generated_username}`; `{generated_username}@example.test` fits a form that validates an email; a template without the placeholder is refused); `secret` types the same pair's password and is refused without a `user` step before it. The step, the log and the answer carry `created:<name> [generated]`, never a value, and a generated value that matches a `secret_content_patterns` entry is replaced, or the step is refused when three pairs in a row match. The step opens the same sign-in window as `fill-account`. A sign-up the app refuses (a step fails while the page is still on the form) records the account `unconfirmed`, and `--as created:<name>` refuses it.
- `CreatedAccounts.add` now writes the two created-users files under an OS lock: two walkers adding at once keep both rows, and a created password is never lost.
