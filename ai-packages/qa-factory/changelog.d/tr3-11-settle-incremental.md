- `probe_debt.py --settle` no longer repeats work it already did on the same inputs. A rebind that was kept (refused, or a dry run that would not write the instance) is remembered with the shas it was made on, the record's modification time, the author dispatch and the `generated_from` files, and is not dry-run again until one of them changes. When every item is stamped the same as at the last settle and was left for a reason a repeat could only repeat, the settle starts no subprocess, re-addresses its debt file to the new dispatch and `story_step.py start` says `probe_debt --settle: nothing changed since <dispatch>, not run`. A changed sha on either side, a rewritten record or an unreadable debt file always runs the settle.
