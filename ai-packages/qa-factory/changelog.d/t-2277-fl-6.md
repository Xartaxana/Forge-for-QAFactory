- A story the person stopped after the first look (`first_look_stop`) now has its own report, its own question and its own arrival. The hold prints the first look's report (`interim_packet.first_look_packet`: what the stand showed, the requirements it did not reach with the evidence the walker cited, the code the look was about, the day the story stopped, the restart command) instead of the S5 packet; a story stopped by the person's words prints a line naming the first look. A relaunch with no flag compares, per repository, the head the first look recorded with the head the same source has now (`git ls-remote` in the repository's checkout: `refs/merge-requests/<number>/head` for a merge request, whether the manifest writes a bare number, `!42` or a link, then the entry's own branch when that gives nothing; a commit alone does not move): one repository moved, or the manifest names an implementation the record does not, and the code arrives; otherwise the closed question `first_look.same_code` (`wait` / `source` / `continue`, with prices) is asked, with one line for every repository whose head could not be established (never read as "moved"); after a `wait` the next question names the day of that answer. `continue` is the same `first_look_continue` operation as for `first_look.dead`. A flag on the hold (`--mr`, `--branch`, `--commit`, or `--side <s>=real` for a side not yet real) records the arrival and owes the reading of the story again against the new code (S1, S2) and then the flow from S3: no bind round and no affected-rows rework, since S5 never ran.
