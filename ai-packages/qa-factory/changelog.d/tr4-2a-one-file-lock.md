- One file lock for the package (TR4-2 part A): `event_store.take_file_lock` / `hold_file_lock` take one byte of one file with a non-blocking try polled until a monotonic deadline, the same on Windows and POSIX. A lock that stays held raises `LockBusy` (a `TimeoutError` naming the lock file, the seconds, the recorded holder or that none is recorded, and the door); a lock that cannot be tried at all raises `LockBroken` with its stage (`open`, `platform`, `lock`); `EventStore.lock` re-raises a failed open or a missing platform module as `LockBroken` and keeps a failed lock call (stage `lock`) as the same `StateConflict` as a busy lock. A holder is recorded after byte 0 only for locks under `qa-factory/state/`; a lock file in a project's tree stays the single byte `0`. `EventStore.lock` and the created-users lock of `manual_capture` run on it (their refusal texts are unchanged; the second adds the holder words); `file_lock_state` and `lock_holder` read a lock without writing it. A new ratchet test lists the files that still carry a private copy.
