- Reference stands (S-c), the walk and the stand rules: when a side of a story carries a `reference` (the launch flag or the project's record), S1 has one more dispatch after the scout - the runner walks the old version in a `survey` walk session on the reference stand and writes `work/reference-snapshot.yaml` with `reference_snapshot.py put` (a card in `role-commands.json`; `--replace` when S1 is made again over an existing snapshot - a `rework S1` does not open the reference window again, that road is queued); `stages.json` S1 names it as an optional dispatch (purpose `reference_walk`, not a stage role) and S2 reads the snapshot. A story with no reference runs S1 exactly as before. A reference stand's build is never asked: the implicit stand pick skips it, and the runtime probe of a named reference stand compares nothing (`not_applicable`, `no_changed_file`); the story's own stand is still asked.
- The reference is never the stand under test (C8): a run request aimed at it is refused at the entry of `run_suite.py --request` (`run_refused`, exit 2) and by `validate_request`, with a door naming the story's own stand. `reference_snapshot.py` now refuses a usage error with its card, like the other role commands.
