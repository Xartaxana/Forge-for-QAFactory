- A story can say that its code is not built yet, and that a side of the product is not real. The no-change questions (`s0.no_change` for a local story, `s1.no_diff` when the scout finds no change) offer a new answer, `not built yet`: the tests are written now from the requirements, what cannot be known yet gets a named placeholder, and the story stops after them and tells you what is missing. The driver records it as `pipeline.sides.product` with `reality: absent`, `deliverable: true`, `source: person`. The answer `ungrounded` no longer promises a "not met" bug at gate B (no code made one); it now reads "go on with the requirements only, on the code the stand runs now; a test that goes red is judged like any red". New launch flags `--side <name>=<reality>` and `--reference <side>=<stand>` (repeatable, kept on a restart like `--mr`): a reality outside `references/side-realities.json` is refused at the command line naming the allowed words and the corrected flag; a side name the project has not recorded is accepted, and when it is not real the driver asks once, in the closed question `sides.deliverable`, whether this story delivers it (`ours`) or another team does (`another team's`). A single-side story is never asked, and a launch whose sides are all real writes no `pipeline.sides` at all, so such a story behaves as before. The scout's charter and `phases/s1.md` carry the same answer. The sides are written into `pipeline.json` in the same write that records S0 (a refused value stops before S0 is recorded and S0 replays); when the launch names a side other than `product`, the record also carries `product: real` (`source: default`); `--side product=absent` is the same as `not built yet` and asks nothing; a curly apostrophe in `another team's` is read as the straight one. The skill's and the README's flag lists name `--side` and `--reference`.
