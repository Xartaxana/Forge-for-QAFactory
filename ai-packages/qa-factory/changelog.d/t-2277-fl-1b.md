- Walk session: `http <METHOD> <path|url> [--body-file <file>]` is a step of `walk_session.py step`, beside the screen steps. It sends one request on the walk's stand as the request's actor (a path is joined to the stand's `base_url`; a full URL must be on the walk's hosts, checked by the walk before any step runs and again at the send), and keeps the evidence the screen steps keep: one JSON document of request and answer in the item's attempt (the one body cut and the one base64 rule, headers redacted, the actor's account hidden, a secret in the answer saves nothing and leaves no excerpt), a quote check by `capture_cited`, and `surprise:` lines for a 3xx (a redirect is never followed), 4xx or 5xx answer, a redirect to a foreign host and an unreadable JSON body; the default stop rule reads the 5xx number. The single request of `manual_capture.py http` and the walk step now share ONE executor, `http_call`. A survey walk of a project with no profile that fits a UI capture has no browser: its record says `profiles: {http: <id>}`, each named actor signs in once by the HTTP request the project records (the actor's own stored account, not only `default`; an actor with no known HTTP sign-in leaves the walk open and its steps end `failed` with `http_sign_in_unknown`), and a screen word is refused whole; a project with neither a UI nor an HTTP profile refuses `open` (exit 2, cause `no_reachable_surface`). Walks with a screen and walks that make no HTTP step run as before.
- Walk `http` step, fix round: an `http` step is sent on the walk's OWN stand only (a walk with no `--env` no longer lets the first stand's Bearer token reach another stand's host); the request secret scan skips the headers code itself sets (`redact_headers`), so a JWT Bearer login through `manual_capture.py http` is accepted as before; `step --final` on a walk with no screen is refused with the walk's door; a malformed redirect `Location` is a `surprise:` line, not a crash; `http` joins `steps.type.keeps_run`; a survey walk whose only fitting profile is HTTP (a single `api` profile) has no browser.
