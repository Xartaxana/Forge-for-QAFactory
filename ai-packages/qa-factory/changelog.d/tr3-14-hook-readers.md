- The guards that run inside a session now tell parallel windows apart through the same one reader. A typed test-run request passes when it names the running dispatch of its own window (with two windows running and no dispatch named in the session, the request's own dispatch id picks the window; a session that is named and carries a sibling's id is refused as before). The owner guard no longer opens for a session that is not the owner because a sibling of the owner is running, and a session's role is read from its own dispatch rather than the first one running. The hook that records a role's return, and the environment projection refresh, wait for a sibling's commit instead of dropping the return (the return waits up to 31.2 seconds - three tries, computed, not measured - and the projection refresh up to 10 seconds); a failure after the wait is still swallowed but leaves one line in the hook's log. With one running dispatch, or no name, nothing changes.
