- A registry of what a test assumes, in the automation manifest. `provisional[]` rows (`id` `P-<n>`, `kind`, `what`, `assumed_from`, `home {file, line_hint}`, `dependents`, `settles_on`, `status`, `evidence`) are sent through `manifest_put.py --fragment` and merged by `id`; a field a fragment omits survives. `home_hash` is built by the tool from the line that carries the marker `qa-provisional: P-n` in the row's `home.file`, wherever that line is (`line_hint` is only a hint, so an edit above the line changes nothing); a hash a role sends is dropped, the baseline is kept once the row settles (the tool also stamps `evidence.home_hash_after`), and a marker that cannot be found leaves the row with no hash and is printed. `retracted_provisional: ["P-n"]` keeps the row as history with `status: retracted`; an id that names no row is refused, and a malformed `provisional` (not a list, a row that is no object, an id that is not `P-<n>` or repeats) is refused before the commit. `tests[].provisional` (`[P-n]`) merges with the other fields of the test row. `contract.manifest_provisional` is the one reader: an absent field reads `[]`, and a malformed row is skipped and named in the return value, never raised. The kinds (`placeholder_locator`, `assumed_contract`, `side_substitute`, `reference_value`) are rows of `references/provisional-kinds.json`. `manifest_from_tests.py` writes `sides: {}` on a new test row only when the story has a side that is not `real`; a story with every side real gets the same manifest as before. The `automation-manifest.json` contract and its role slices describe the fields, `design/state-exits.md` has the ways out, and `references/null-outcomes.json` declares the empty outcome. Nothing requires or checks the registry yet, so every story behaves as before.
