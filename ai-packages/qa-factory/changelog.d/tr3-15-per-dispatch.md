- S5 windows no longer share the files a critic reads (spec t-1937, TR3-15). The probe debt is one file per critic dispatch (`work/probe-debt/<dispatch>.json`, `probe_debt.debt_rel`); what carries from one settle to the next is a separate story-wide memory (`work/probe-debt-memory.json`, the last settle's doc whole; an unreadable memory means the settle runs, a memory that could not be written is reported and removed). The advice the exit gate files for an S5 automator is `work/advice-S5-<dispatch>.json` (atomic; no identity or another stage keeps `advice-<stage>.json`) and the critic's brief names the file of ITS window's latest accepted automator (`brief_pack.advice_of`). The judge's file is `work/judge-code-<dispatch>.json`. The notes are `work/s5-notes/<dispatch>.md`, one per dispatch (registry rows per role); the brief and the receipt's `read_first` list the old `work/s5-notes.md` and every per-dispatch file. `sizing.py` publishes `work/sizing.json` by replace. A story from before reads the old files as a fallback and never writes them.
- `probe_debt.py --settle` never touches a running window: an item whose case belongs to, or whose test file is in the file set of, another S5 dispatch that is `running` or `returned_unaccepted` is left with reason `running_window` and no subprocess is started for it (an unreadable controller record leaves every item outside the settling dispatch's own scope). A kept rebind remembered across settles now has its own reason, `rebind_same_bytes` (`same_bytes` stays the probe's).
