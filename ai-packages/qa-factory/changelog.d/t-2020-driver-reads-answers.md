- The driver reads a script's answer as the last line of its output that is a JSON object, through one reader. A warning a controller prints to stderr (for example the note about a project folder copied elsewhere) no longer hides the answer: before, the scope of S6 came back unread and the stage closed as "nothing to execute" although the manual half held cases. A controller call with no readable answer is now refused with the text that came back, and S6 refuses an answer without a scope instead of closing over it.
- The same reader (now `hooklib.read_answer`, shared by the driver and story_step) is used for the handoff_check form answer, so a stderr warning no longer makes the form read as unparsable; the pretty-printed probe_by_code answer is read by `hooklib.read_document`, which a warning holding a brace no longer breaks.
