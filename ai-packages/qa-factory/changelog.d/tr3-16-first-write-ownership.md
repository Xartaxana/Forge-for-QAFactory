- First-write ownership of a test file by an S5 window (`window_files.py`, `guard_pre_tool.py` `window_file_check`): the first window to Write, Edit or NotebookEdit a test file claims it in `state/window-files/` (`O_CREAT|O_EXCL`, one winner); a later write by another window is refused with the door of a new file in the same directory (where a test lives stays the role's choice). A claim holds until `window_files.release` (no takeover): an open window and a grown round keep their files, a window sharing a case with the owner is the owner. Support files are not claimed; a session with no dispatch name, a critic and a plan dispatch are not checked; with `dispatch.parallel_windows` 1 nothing is claimed and the write goes the old road. An unreadable claim is an unknown owner and refuses with the same door; an unreadable story controller is retried, then the write passes with one notice to the person (a journal signal). A second refusal in a row names the story's state (windows meeting on files) and stops nothing. The conductor frees a claim with `python window_files.py --task <task root> --release "<window>"`. Writes through Bash are not seen (the launch gate is the net).
- `agents/qa-automator.md` and `agents/qa-code-critic.md` tell the roles about file ownership before the work: the automator that a claimed file takes a new file, the critic that a test in a new file beside another window's file was forced, not chosen.
