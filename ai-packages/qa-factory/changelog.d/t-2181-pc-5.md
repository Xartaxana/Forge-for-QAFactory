- The delivery check now keeps a green that met only a substituted or unknown side apart from a real proof. A covered Then (or a walked manual case) whose run is stamped with a side that is not `real`, whose test does not declare that side `real`, whose stamp carries `sides_unknown`, or whose stamp cannot be read at all, reads `not_verified:on_substitute` or `not_verified:sides_unknown` instead of `passed_green`; a red on a substitute stays a failure, a real green beside a substituted one proves the Then, and a row with no stamp and no non-real declaration reads exactly as before. The run row of a test is found by the one join every other reader uses, so a row the runner spelled differently from the manifest is read too, and a Then whose own test has no green row reads the case's green rows instead of being skipped. A Then that an open first-look placeholder locator stands behind (named in the row's dependents, or proven only by tests that name an open row) reads `not_verified:placeholder_open` until a run settles the row; it sits right after `failed:*` and before the flaky, skipped and hand-off words. All three read as the third verdict `after_checks`, one "Left with you" item per case with its tests and how to run them again, in words of their own in the summary, and the Then table no longer prints `pass` for such a Then. A story held for code (awaiting or stopped) now reads as ONE record `awaiting_implementation` (`delivery_ready: no`, owner product, no bug candidate and no gate B reason; a red a recorded verdict already stands behind keeps its own record) with words by the hold's cause: "waiting for a fix", or "stopped after the first look: the feature does not work yet"; the dashboard card shows the same words with the age of the hold.
