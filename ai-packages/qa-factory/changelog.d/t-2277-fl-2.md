- First look: a new `first_look.py` keeps the record of the first look at the new version on the stand (`work/first-look.yaml`) and the attempt that walks it (`state/first-look-attempt.json`). The walker sends one YAML row per requirement of the register with `first_look.py put` (a status, `blocked_by` for a `missing` or `unreachable` row, where it lives on the stand, and the capture that shows it, tied to this walk's attempt of that requirement through `walk_session.capture_cited`); code writes the walk, the stand, the stand build (`confirmed` only on a `deployed` word of the person at the one implementation head), the code heads map, the register hash and `sides_met` itself and ignores the walker's values for them; a first look that was not walked is `put --null <reason>` with empty rows and one gap line. `current_keys` is the one producer of the heads text and register hash that `first_look_continue` stores, `read` is the one reader (stale on other code or another register), `share` is the reachable share without `access` and `nature` rows against the floor `first_look.reachable_floor_percent` (default 30), `due` is the pure question whether a walk is owed (no code yet, empty or unreadable register, no stand, an attempt on the same heads, one retry of a walk that could not be opened) and `continued` compares the person's `continue` with the current keys. The closed words are `references/first-look-statuses.json`; the form is `references/artifact-contract-first-look.md`. Nothing in the existing stages calls it yet. `role-commands.json`: the `walk_session.py open` card names the survey place for `qa-runner`. `role-commands.json` also carries the `first_look.py put` (rows file only; the null record is the driver's) and `first_look.py show` cards for `qa-runner`. `put` refuses a `blocked_by` on a `confirms` or `contradicts` row, refuses when the code or the register changed since the walk was opened (the driver opens a new attempt), and `put --null` never replaces a walked record that is still current. The words the code checks (`blocked_by_required_for`, `share_excludes`, `no_capture_needed`, `attempt_settled`) are data in `first-look-statuses.json`; the attempt is written through `event_store.atomic_json`; `work/first-look.yaml` and `state/first-look-attempt.json` are in the collect sets.
