- `probe_by_code.py`: Python's check vocabulary is now data. `references/detectors.json` `assertion_probes_ast.python.forms` holds one row per kind of check (`PY-assert`, `PY-assert_that`, `PY-unittest`, `PY-unittest-none`, `PY-pw-expect`): a closed AST shape (`assert`, `call`, `method`, `chain`) plus the row's own names, receivers, rename map, wrap text and message slot, validated by `assertion_detectors.ast_entry` (a broken row is a typed data gap naming the field and the row). The code no longer spells `assert_that` or any method name (`ASSERT_THAT`, `PY_FORMS` removed; `_is_assert_that` -> `_form_of`, `first_assert` -> `_first_check`, `_assert_that_replacement` -> `_call_replacement`). A Python probe now reads `self.assertEqual`-style unittest checks (inverted by the row's rename map, the marker as `msg=`) and Playwright-for-Python `expect(...).to_*` chains (`to_` and `not_to_` swapped, the marker as the head's `message=`, an `await` kept); a check of a row with no inversion (`self.assertRaises`, `self.fail`, ...) that comes first is refused naming the row and the doors, never skipped for a later one. The `--at` door and the write check read the same rows, so an id on `self.assertEqual` opens. A `with self.assertRaises(...)` / `with pytest.raises(...)` block is a check too (shape `with`, rows `PY-with-unittest`, `PY-with-pytest`, spanning the with header only), refused as not invertible by code when it comes first. When call statements that no row reads stand before the check a plan takes, `target_note` names their lines and the row set. `assertAlmostEqual` keeps its positional `places`. Existing `assert` and `assert_that` probes plan byte-identical statements.
