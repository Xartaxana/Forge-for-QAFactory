- A bug that shows in several ways is now one bug in the trace, the dashboard board and the report (node N3a of "one bug, many manifestations"; no role is asked to write the new draft keys yet, so an ordinary draft reads exactly as before). The trace's bug record reads a draft's cases through `bug_records.draft_cases` (so `case` no longer hides `cases`, and a case that only a manifestation names finds its bug through `bug_for`), takes the requirements of every manifestation, and carries the lines of the ways it shows, the cause (status, statement, how it was confirmed, claims nobody verified) and the drafts it may share a cause with. The dashboard's bug row lists every case of a merged draft. In the report, under a bug that shows in two or more ways, one line says the cause and how it was confirmed (by the line of the application code, by trying it from n starting states, or both), one line per way it shows, none cut, and a "Not verified:" line for every claim nobody verified; a cause that is only a hypothesis, or one whose evidence can no longer be re-read, is never printed as confirmed; a bug the analyst suspects shares a cause with another is told "Possibly the same cause as <row number> (not verified)". A bug with one way and no link prints the same bytes as before. A new test, `test_draft_readers.py`, fails when any script other than `bug_records.py` reads a draft's `case`/`cases` by hand again (with a planted-line control inside it).
