- Env-file names (`references/env-file-names.json`, `env_probe.env_file_kind`): which file names are env files and which are samples is now one data table instead of a regex and a name test in `project_inventory.py`; a sample marker (`example`, `sample`, `template`, `dist`) anywhere in the name counts, and the bare `env.example` is scanned and marked a sample like `.env.example`. A damaged or missing table is a named `ValueError`, never a silent built-in list.
- Onboarding discovery (`project_inventory.access_discovery`): new fields `env_file_is_sample` (the chosen file is only a sample, declared or fallen back to), `env_file_addresses` (the origin - scheme, host, port - of every http(s) address an env file holds, with its file, a `has_path` flag and a `sample` flag; no path, query or userinfo is ever shown) and `env_file_addresses_more`. A declared `./.env` or `.\.env` now matches the row `.env`. `render_access` says "only a sample" instead of naming a sample as the stand's env file, and prints the address origins.
