- `manifest_put.py` refuses a `tests[]` row whose `assertion_id` (`<file>:<line>`) names a line that holds no check, before the commit (`assertion_line_problems`): the refusal names the line, the nearest check below it as the door (`<file>:<m>`) or says that none follows. In live runs 7 of 41 ids stood one line above their check (a blank line), so a probe aimed there proved nothing. A check counts when it starts on the line or its statement spans it, by the one reader the probe uses (`probe_by_code.check_on_line`, imported only when an id is being written or changed). Only a row that writes or changes its id is looked at; a language with no reader, an unreadable or unparsable file, a path outside the project and an id of another form are one printed note, never a refusal and never a silent pass.
