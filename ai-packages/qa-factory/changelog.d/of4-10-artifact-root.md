- A broken project `qa-factory/config.json` (empty, not JSON, not an object, nested too deeply, a folder, or an unusable `artifact_root` value) now ends in a refusal that names the file and the fix at `hooklib.artifact_root()` and its callers, never in a traceback or a silent default folder. The config reader and `ConfigUnreadable` live in `hooklib` now; `config_contract` re-exports the same objects.
- `vcs_evidence.py`: an `--output` that is a file in `artifacts/`, or lies in a folder without `pipeline.json`, no longer counts as a story, so the person's "do not read this merge request" word is consulted for every story. With a broken config and no story named, the tool refuses (exit 2, stdout `status: unknown`, `error: not_checked`) instead of reading.
- `exit_gate.py`: `grounding_errors` returns one `unreadable` record when the story folders cannot be found; the stop hook's fingerprint and the S1 source-review check no longer raise on a broken config.
