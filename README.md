# QA Factory — development

The development home of **QA Factory**, a Claude Code plugin that tests a Jira story end to end
(context, requirements, plan, cases, automation, runs, triage, report) with two human gates.
Projects use it through released versions in `Xartaxana/QAFactory` (marketplace `qafactory`); this repository is
where it is built, measured and fixed.

- `ai-packages/qa-factory/` — the package itself (English); its own README, INSTALL and CHANGELOG.
- `PROJECT.md` — how work on the factory is done here: principles, layout, acceptance, release.
- `plans/PILES.md` — the list of what to do in the factory (generated from the piles); `plans/BACKLOG.md` is
  frozen and holds the old rows until they close.
- `docs/RUNBOOK.md` — the MyBooks stand, release hygiene, CI on GitHub and the canon, updating the installed plugin,
  the night run.
- Work is routed with [Supervised Delegation](https://github.com/Xartaxana/Supervised-Delegation):
  the policy is `CLAUDE.md`, model bindings `delegation.config.yaml`, decisions `DECISIONS.md`,
  live state `CURRENT_CONTEXT.md`, session restore `BOOT.md`.

## Getting started after a clone

1. Prerequisites:
   - Python 3 on `PATH` as `python` (the hooks call `python`; on a system that has only `python3`,
     provide a `python` alias or shim).
   - `pip install pyyaml`: the commit-msg mechanism gate and the SessionStart hook import `yaml`;
     without it every commit fails closed.
   - `pip install pytest openpyxl` for the tool tests (`python -m pytest tools/ -q`).
2. Turn on the repository's git hooks. This is a local git setting and does not travel with a clone.
   The gates, exactly as `.githooks/` runs them: pre-commit runs the journal validator, the escape
   check, the enforcement probe and the factory rules index check; commit-msg runs the mechanism
   gate.

   ```bash
   git config core.hooksPath .githooks
   ```

   The first Claude Code session opened in the repository root sets it too (the SessionStart hook
   prints `WIRING AUTOFIX: core.hooksPath set to .githooks`), but a commit made before that session
   goes through with no gates. If a commit is refused with "factory rules index is stale", run
   `python tools/factory_rules_index.py` and stage `docs/FACTORY_RULES_INDEX.md`.
3. Open Claude Code sessions in the repository root, not in a parent folder: the Claude Code hooks in
   `.claude/settings.json` run `python tools/...` relative to the root and are not loaded otherwise.
   Codex users: read `AGENTS.md` (generated by `python tools/agents_md.py`, it inlines CLAUDE.md and its imports) and raise `project_doc_max_bytes` as its first lines say, otherwise Codex cuts the rules off at 32 KiB.
4. Check that the hooks are alive and wired:

   ```bash
   python tools/hook_liveness_probe.py
   ```

   ```bash
   python tools/wiring_check.py
   ```

   Expected: `OVERALL: OK` and `WIRING: OK`.
5. Restore context: say "restore context from BOOT.md".

### Working on a batch (team work)

1. Copy `tools/dev.config.example.yaml` to `tools/dev.config.yaml` (git-ignored) and fill it: your
   `developer` slug, `stand_copy_root` (the folder of the project copies your runs use),
   `release_repo_root` (the folder of your `QAFactory` clone), and `github_token_env` (the NAME of the environment
   variable that holds your GitHub token, never the token). `python tools/dev_config.py` prints what was read and
   whether the token variable is SET.
2. Open `plans/PILES.md` and pick a batch with status "ожидает" whose "стенд" you can satisfy
   (a batch marked "не нужен" is proved by CI alone).
3. Take it: `python tools/piles.py take <pile> <N> --who <your-slug>`. Work on the branch
   `pile/<slug>/batch-<N>`, cut from `origin/main`.
4. A taken batch is frozen: its file is written only by you. Your Lead keeps its "Ход" section (not
   CURRENT_CONTEXT.md) and the node statuses.
5. A new finding is a file in `plans/piles/<slug>/findings/` (form: `plans/piles/_template/finding.md`),
   never a row in `plans/BACKLOG.md`.
6. Do not edit `DECISIONS.md`, another batch's file or `plans/BACKLOG.md`: a proposed decision is a finding
   marked "needs the owner's word".
7. Open a PR to `main` when CI is green and the critic accepted; the integrator merges.
